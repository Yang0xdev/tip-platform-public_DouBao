- 版本：v0.1（2026-09-22，随 PRD 基线冻结）
- 里程碑：M2（依赖 M0 地基、M1 内容域；合同/支付条款受 D2/D4/D8 决策门约束）

## 1. 目标与非目标

### 1.1 目标（可验收）

1. 客户与顾问经**双向确认**建立服务关系（客户发起/选择 + 顾问接受，一名主责）；来源、关系、佣金归因三分离；冲突未裁决前锁定方案与订单。
2. 顾问在授权范围内编制方案，经 A05 报价复核后客户才能确认；**客户确认方案 ≠ 签署 ≠ 付款**；任何内容变更使旧确认失效、新版重确认。
3. 订单三态（合同态/到账态/服务态）独立维护；**主体三要素门**不过，客户端与顾问端四个入口同时关闭，无强制通过。
4. 合同五要素齐备并完成受控登记（电子签或线下登记，【门 D2】）；付款按 D8 推荐口径：线下对公转账 + 凭证上传 + 财务核验，待核验≠到账，到账开收据。
5. iPad 面谈双模式：需求采集/初评比较（I-01）与方案共读（I-02），演示模式不泄露内部信息。
6. 退款/调整只产生申请与冻结（执行与工单闭环在 M4）。

### 1.2 非目标

| 不做 | 说明 |
| --- | --- |
| 案件、材料、官方进度、T0 送达（M3） | 订单"生效建案"在 M3 接通；M2 订单到账后停在"待建案" |
| 换顾问五步交接完整流（M3） | M2 仅实现关系冲突锁定与"不可单方转移"；离职/暂停交接随 M3 |
| 佣金计算与结算（M4） | M2 只在下单时**锁定佣金规则版本快照**，不产生可提现金额 |
| 工单/投诉/退款执行（M4） | M2 仅退款/调整申请入口与订单冻结标记 |
| 资金托管、在线支付、跨境收款通道 | 【门 D8】未拍板不开发；PaymentGateway 抽象预留 |
| 多级分佣、协作顾问关系 | 首期一名主责；协作角色 M3 后评估 |
| 合同模板的法律定稿 | 五要素结构先行，文案【门 D2/D9】法务定稿 |

## 4. 详细需求

### M2-01 咨询捕获与分配队列

- **来源**：初评"请顾问解读"（M1 已落 `consultation_capture`）、名片"预约沟通/请求服务"、分享链接落地（仅记来源）、平台外登记（后台手工录入，标来源）。
- **客户端规则**：
  - "预约沟通"生成预约请求，**不成立关系、不授权问卷**；"请求 TA 服务我"才进入关系流程（M2-02）。
  - 发起时客户可勾选授权顾问查看本次初评/问卷（默认不授权；授权动作与关系解耦，可撤回）。
  - 点击、浏览、分享来源不产生归属与佣金归因。
- **后台 A04 队列（首期人工分配）**：脱敏摘要、来源标签、重复线索检测（同手机号/同证件哈希 + 近 90 天已有关系 → 进冲突队列）；分配动作留痕。
- **状态**（GP4 §5 Consultation）：`pending_assign 待分配 → pending_accept 待顾问接受 → accepted 已接受（转关系）/ reassigned 已转分配 / closed 已关闭`；冲突：`conflict_pending 待裁决（锁定方案/订单）→ resolved 裁决归位`。
- **验收**：同一客户在冲突期间，任何顾问无法发起方案（接口 409）；"预约沟通"不产生关系记录。

### M2-02 服务关系双向确认

- **成立**：客户发起（指定顾问或平台分配后客户确认）→ 顾问端接受 → `active 主责`；顾问可"转分配"（回队列，需填原因）。一名客户一名主责；客户在顾问接受前可撤回请求。
- **顾问端 S-06**：chips（待接受/方案中/服务中/全部）；客户行脱敏标识；无"一键接受"、不可批量；不可检索全平台客户；越权查看他人客户 → 403 + 审计告警。
- **锁定规则**：
  - 冲突未裁决：方案、订单接口对冲突双方均锁定。
  - 关系未成立：顾问看不到客户联系方式与问卷全文（除非有单独解读授权）。
  - 关系结束/未成立：历史只读，不可新增动作。
- **名片动作激活（M1 置灰处）**：M2 上线后 C07 的"预约/请求服务"真实可用；统计字段（响应中位数）开始累计，样本不足仍显"样本积累中"。
- **验收（D7）**：关系必须同时存在客户发起事件与顾问接受事件；只有其一不可下单；分享链接落地不自动成立关系。

### M2-03 顾问客户详情（方案域，S-07 子集）

- 三页签本期开放：biz（关联初评/方案/订单状态与编号，官方回执类只读占位）、follow（跟进记录时间线、新增跟进，过词库校验，不可删除只能更正）、scope（可见范围清单；原件批次申请在 M3 开放，本期显"办理阶段开放"）。
- 顾问**不可见**：支付明细/账户、其他客户、服务方结算、投诉正文（M4）。
- 跟进记录对客可见策略：事实类节点对客可见，内部质检标签不对客（字段级 DTO 过滤）。

### M2-04 方案编制与版本化（顾问端）

- **前置**：顾问对该项目 `granted`（M1）、关系 `active`、项目版本 `published`、FeeSchedule `published`。
- **方案内容**：个性化建议（每条可追溯项目条件版本或人工署名）、FeeSchedule 快照（只读选择，不可改价）、责任分工、有效期（初始参数 14 天，可配置）、不承诺事项清单（模板化，A12 审核版）。
- **状态机（GP4 §7）**：
  `advisor_draft 顾问草稿 → pending_review 待报价复核 → pending_customer 待客户确认 → customer_confirmed 客户已确认（生成订单草稿）→ revised 已修订（旧版归档只读）→ invalid 失效（项目暂停/超期）`；
  复核驳回 → 回 `advisor_draft`（带逐条原因）。
- **规则**：
  - 金额/项目/申请人/责任范围任一变更 → 新版本；旧确认失效。
  - 方案文本过词库（block 强拦截，第四生产点：方案）；超模板的个性化结论必须"人工署名"（顾问实名 + 时间戳），无署名不可提交复核。
  - 未过复核/已过期版本，客户端不可见"确认"按钮（服务端同样拒绝确认）。
  - 异币种费用分列、不合计；tbc 项保留。
- **验收**：顾问改价（前端无入口；直接调接口改金额）被服务端拒绝并审计；项目暂停后在途方案转 invalid 并对客户显示说明。

### M2-05 A05 报价复核队列

- 队列项：方案编号、顾问、客户脱敏、项目版本、费表版本、金额/币种分项、diff（相对标准 FeeSchedule 的偏离，仅允许"减免/分期"类经审批偏离，不允许新增收费方）。
- 双人：复核人 ≠ 编制顾问；金额类偏离（减免超过阈值，阈值影子期配置）需第二复核人。
- 通过 → 对客可见为 `pending_customer`；驳回必填原因，回顾问。
- 留痕：复核意见、前后版本、操作人入审计。

### M2-06 客户方案确认（C08/P-08）

- 版本头：编号、版本、编制顾问、复核状态、有效期；旧版只读且无确认入口。
- 客户动作：**确认本版本**（校验复核通过 + 有效期内 → 记录确认人/时间/快照 → 生成订单草稿）；**我要修改**（填修改点 → 生成任务回顾问，旧版保留，新版重走复核）；暂不确认（停留，不逼单、无虚假倒计时，到期前 T1 提醒）。
- 确认快照内容：方案全文、费用快照、责任文本、不承诺事项、项目条件版本、词库版本，随订单永久留痕。
- iPad 共读确认（I-02）与本页确认写同一条版本确认记录。
- **验收**：对过期/未复核版本调确认接口返回 409；修改后旧确认失效必须重新确认（V2 §5.3）。

### M2-07 iPad 需求采集与初评比较（I-01）

- 横屏三栏：需求表单（同 M1 审核问卷版本，字段一致）、初评四类结果（同引擎同口径）、最多 3 个已发布项目并排（核心门槛/参考周期[非承诺]/费用分项收取方/自助范围）；未授权/暂停项目不可选入。
- **数据归属**：关系未成立时面谈记录仅存本机草稿（初始参数保留 7 天），不建客户数据、不上云；关系成立后可保存为客户档案来源之一（写跟进/初评记录）。
- 演示模式（见 M2-08 双模式规则）下不可使用真实客户需求采集。

### M2-08 iPad 方案共读（I-02）与双模式硬规则

- 左目录七节：建议结论/路径时间/费用分项收取方/责任分工/材料清单（清单展示，上传在 M3）/不承诺事项/下一步。
- 不承诺事项独立面板，逐条知悉勾选；底部双动作："客户要修改"（留痕、版本+1 重来）/"客户确认理解并继续"（写共读确认：时间/版本/不承诺知悉项）。
- 禁表述实时校验：讲解备注文本命中 block 词不可确认（第五生产点：讲解）。
- 确认理解后流转：回顾问端 S-08 发起订单，仍过主体门与 A05；**共读确认≠签署≠付款**。
- **双模式硬规则（服务端可见性 + 端上隐藏双保险）**：
  1. 进入面谈默认工作模式；切客户演示需显式开关 + 持续可见模式标识；退出需再次明确；
  2. 演示模式服务端不下发：佣金规则/金额、内部备注、其他客户信息、内部评分、境外方结算信息（收取方用中性"境外持牌方"表述）；
  3. 模式切换、停留页、演示模式下尝试打开内部内容（拒绝并记录）全部写审计；
  4. 面谈一位客户期间不得切出到其他客户档案，结束面谈清理同屏上下文；
  5. 双模式只改可见性，不改事实口径。
- **验收（AT23 子集）**：演示模式抓包确认内部字段不在响应体；未过 A05 复核的方案不可进入共读。

### M2-09 订单生成与主体三要素门（核心闸门）

- **生成**：方案客户确认后生成订单草稿，固化方案/费表/规则快照。
- **三要素（服务端校验，配置来自 A02/A05，M2 用 M1 机构台账 + 收款账户配置）**：
  1. 签约方 = 境内备案主体（机构状态有效）；
  2. 境外交付方 = 已关联的有效持牌方，或自营交付部门（M3 A02 完整版前，自营/境外方信息为后台配置项，D2 未拍板时订单不可对真实客户生效，仅影子环境可走通）；
  3. 收款账户户名 = 签约主体（账户白名单配置，户名不一致即阻断，反例 ORD-2409-018 户名为第三方商务公司）。
- **结果**：`passed 通过 / blocked 阻断（列差异项 + 阻断码）`。
- **四入口同时关闭**：客户付款指引、客户下单确认、顾问 S-08 发起、财务核验入口共享同一判定；**不存在强制通过参数/后门**；反复提交同一阻断（初始参数 24h 内 ≥3 次）触发 A10 告警与合规事件线索（M4 接单）。
- **顾问端 S-08a 阻断详情**：三要素对照表、差异项、强制路径（停止收款引导、已收款原路退回指引【门 D8 流程】、转 A05/合规、按结论重建）；无"强制通过"按钮。
- **收费主体/账户未配置不可下单**；阻断单状态：`blocked → 转复核 → 结论（重建/终止）`。
- **验收（AT21）**：三要素任一不一致，四个入口接口全部 4xx/422 且审计留痕；影子环境用 ORD-2409-018 反例回归。

### M2-10 合同五要素与签署受控登记

- **合同模板版本化（A05-tpl）**，五要素缺一不可：服务范围与边界、退款规则、境外段服务方告知、平台保障与平台外交易边界、隐私与跨境告知（跨境条款【门 D9】法务定稿，未定稿用占位文本且合同不可对客生效）。
- **告知 Consent（GP4 §12）**：费用逐项知悉、不承诺结果知悉、隐私告知——逐条时间戳，随合同登记。
- **签署方式（两通道，开关配置）**：
  - 通道 A（推荐先行）：线下/外部签署受控登记——上传签署完成件（L3 水印）、签署时间、签署方式、核验人（**≠顾问**）；
  - 通道 B（【门 D2】电子签供应商适配：e签宝/法大大）：PaymentGateway 式适配器，回调写登记记录；供应商未定不开发。
- **状态（合同态）**：`draft 订单草稿 → gate_passed 主体通过 → pending_sign 待签署 → signed_registered 已签署登记 → effective 生效`；登记缺要素 → 停在 pending_sign。
- **验收**：五要素/告知缺一不可登记；顾问账号调登记接口 403。

### M2-11 付款计划、凭证核验与收据（D8 保守口径）

- **PaymentPlan**：期次、条件（与合同/案件节点挂钩，M3 前仅合同首付）、金额/币种、状态；官方/第三方费按实际代收代付，未发生显"未发生"，不预记应收。
- **客户付款（P-09/09a）**：
  - 仅展示签约主体对公账户信息（后台配置、白名单）；"请勿向个人账户转账"防骗提示常驻；非主体账户无复制入口。
  - 上传转账凭证（JPG/PDF/20MB 初始参数，L3 加密桶）→ 状态 `pending_verify 凭证待核验`；**客户端明确显示"待核验，不代表到账"**。
  - 财务核验（双人/银行核对）：`verified 已核验到账`（开收据）/ `rejected 驳回`（原因：户名不符/金额不符/图像不清/重复凭证，可重传，原凭证留存）。
  - 重复凭证（文件哈希 + 金额 + 期次）拦截重复记账。
- **收据 Receipt**：编号、期次、金额/币种、PDF 水印；到账后生成，客户可查。
- **财务职责分离**：财务默认不见证件原件；核验人 ≠ 顾问；退款执行在 M4。
- **到账态**：`unpaid 待付款 → pending_verify → verified（开收据）/ rejected（回 unpaid 可重传）`。
- **服务态**：M2 仅 `not_started 未开始`；首付 verified + 合同 effective 后订单整体到"待建案"，M3 建案。
- **支付通道抽象**：定义 `PaymentGateway` 接口（发起/回调/查询），无实现；D8 拍板后装在线支付/跨境通道，不影响状态机。
- **验收**：凭证上传后任何终端不显示"已到账/已付款"；重复凭证被拦截；财务越权访问证件原件被拒。

### M2-12 订单变更与退款/调整申请（只冻结，不执行）

- 客户从 P-09b 提交：退款 / 分期变更 / 方案变更 / 费用争议，关联订单、说明、凭证（L3）。
- 系统行为：生成变更申请单（编号），订单进入 `change_pending 变更中` 或 `refund_pending 退款调整中`；**佣金相关结算冻结占位**（M4 生效）；变更类工单 M4 流转 A05/A06/A07/A08，"提交即生效"不存在。
- 前置告知（模板文案，法务定稿前用中性表述）：官方/第三方已发生费按实扣除、境外专业费按已完成工作量结算、以合同条款为准；**无"不成功全额退款"字样**；顾问端无承诺退款比例/时限的入口与话术（词库覆盖）。
- 平台外交易（无登记订单）：不假装受理，显式告知保障边界与其他合法途径（M4 工单完整话术）。
- **验收**：变更申请提交后订单状态冻结、不可并行付款/改方案；申请有编号可查。

### M2-13 规则快照与佣金归因占位

- 订单确认时固化：FeeSchedule 版本、佣金规则版本（M4 才配置规则，M2 存快照槽位与版本号）、来源/关系/归因三字段分离记录。
- 明确不产生：点击、咨询、预约、方案确认均**不产生可提现佣金**；M4 六态从订单生效后按规则启动。

## 7. 服务端闸门清单（自动化测试逐条覆盖）

1. 关系双事件齐全才可下单；冲突期方案/订单全锁。
2. 未授权/暂停顾问、未 published 项目/费表不可进方案。
3. 方案复核人 ≠ 编制人；未复核/过期不可确认；确认后任何内容变更使确认失效。
4. 词库在方案文本、iPad 讲解备注两个新生产点强拦截。
5. 主体三要素四入口同判定、无后门；反复阻断告警。
6. 合同五要素 + 三条告知 Consent 缺一不可登记；登记人 ≠ 顾问。
7. 待核验≠到账（状态、文案、收据三处一致）；重复凭证拦截；财务不见原件。
8. 金额不可被顾问端任何接口修改；异币种不合计（无总价字段）。
9. iPad 演示模式内部字段不出现在任何响应体；切换/越权尝试全审计。
10. 变更/退款申请提交即冻结相关链路，无"提交即生效"。
11. D 门未开（境外方未配置/合同占位文本）时，真实客户订单不可生效（环境级开关 + 影子标识双保险）。

## 8. 关键异常与边界

| 场景 | 行为 |
| --- | --- |
| 顾问超时不接受请求 | 客户可撤回/改选/转平台分配；状态透明，不假装已服务 |
| 客户确认方案后项目暂停 | 订单草稿转取消说明，已确认方案归档，引导替代项目/工单（M4） |
| 合同签署后主体备案失效 | 阻断后续付款，转 A05/合规；已收款按 D8 预案处置（预案待 D 门） |
| 客户上传凭证后又重复上传 | 哈希查重提示已有凭证，不重复建账 |
| 客户坚持向第三方账户转账 | 系统不提供该账户信息；提交后阻断并出示风险告知与工单入口 |
| iPad 面谈中掉线 | 本机草稿加密保留；关系未成立数据不上云 |
| 电子签供应商故障 | 通道关闭，可走线下登记通道，不阻塞已开通路径 |
| 两人同时操作同一方案复核 | 乐观锁；后到者基于新版本重操作 |
| 客户无账号（线下客户） | 顾问不可代注册代确认；由客户本人完成手机号验证与确认动作 |

## 9. 验收用例（AT 映射，E2E）

1. **D7 双向关系**：Given 客户请求，When 顾问未接受，Then 不可建方案；接受后双方收到 T1（M3 通知引擎前用站内记录）。
2. **冲突锁定**：Given 两顾问关联同一客户冲突未裁决，When 任一方提交方案，Then 40901。
3. **方案复核与重确认**：改价/改范围后旧确认失效，客户必须确认新版（V2 §5.3）。
4. **AT21 主体门**：三要素不一致反例（ORD-2409-018）在客户/顾问/财务四入口均失败，无强制通过；反复触发产生告警。
5. **合同五要素**：缺任一要素/告知未逐条确认，登记接口拒绝；顾问身份登记被拒。
6. **待核验≠到账**：凭证上传后三端状态均为"待核验"；只有财务 verified 后才开收据、显到账。
7. **重复凭证**：同凭证二次提交被拦截。
8. **iPad 演示隔离**：演示模式响应体无佣金/内部字段（抓包断言）；切换记录可审计。
9. **不承诺闭环**：iPad 未逐条勾选不承诺事项不可确认；方案确认快照含不承诺版本。
10. **变更冻结**：退款申请后订单冻结，M4 工单生成前无任何金额执行。
11. **D 门保护**：境外方/合同占位状态下，生产环境订单生效接口拒绝（仅影子环境放行并打标）。
