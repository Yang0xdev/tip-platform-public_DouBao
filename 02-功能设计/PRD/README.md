## 冻结规则（开发期间严格执行）

1. **开发以本基线为准**：需求、状态机、闸门、接口契约、验收用例（AT 映射）是研发与测试的唯一输入；高保真原型是视觉契约，不替代本 PRD。
2. **不得口头改需求**：任何变更走《变更控制》：提出人 → 影响面（状态机/闸门/接口/AT/相关里程碑）→ 产品+研发+合规评估 → 版本号升级（v0.x → v1.1）→ 在此索引登记 → 才允许改代码。
3. **D 门与 Q6 为外部依赖门**，不是需求缺口：门未开时按各 PRD 的保守方案实现（结构先行、开关关闭、影子可用），不得自行降低门槛或绕过开关。
4. 初始参数（时限、阈值、SLA、文件规格等）集中在后台配置，影子期按 A11 数据校准；校准值变更同样登记，不直接改死在代码里。
5. 发现 PRD 与原型/技术方案冲突时，以本 PRD 的业务规则为准并发起勘误；勘误累积到下一版统一发布，紧急安全/合规问题可即时修订并即时通知。

## 跨里程碑一致性基线

- **内容红线 14 条**（无成功率、费用分项收取方、四级来源、主体三要素、T0 只升级不改期、职责分离、佣金六态、授权五步、分享白名单、平台外边界、门户只读水印、家庭授权四维度、跨境单独同意、超模板署名审核）已逐条落到各 PRD 的"服务端闸门"与 AT 验收。
- **金额铁律**：numeric + 币种分列、异币种不合计、待确认≠0、无总价字段。
- **验收映射**：AT01/02/07/08/21/22/23/24（M1）、D7/AT21/AT23（M2）、AT11/19/20/22/25（M3）、AT09/26（M4）、Q6 下架（M5），全部转为 E2E/集成测试用例，进 CI 必过集。
- **环境门**：交易（D2/D8）、门户跨境（D9）、结算（D6）、全球通行（Q6）、电子签（D2）、T2 营销六个特性开关在 M0 开关中心预留，默认 off。
