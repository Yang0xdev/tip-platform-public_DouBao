# PRD-M3 案件交付、材料、T0 送达、家庭授权与服务方门户（研发级）

- 版本：v0.1（2026-09-22，随 PRD 基线冻结）
- 里程碑：M3（依赖 M0–M2；跨境数据路径受 D9 决策门约束）
- 依据：V2 §5.5/5.7/5.8/5.9、GP3 第2批 C10/C11/C13、第3批 S-07、第4批 A02/A06/A09（tpl/rcpt 子集）、服务方门户高保真（4 页签×ext/in）、GP4 §4/§10/§11/§12/§13/§14
- 成熟度：可进入研发排期；门户跨境与原件能力在 D9 法定路径确认前按"只读在线、不落地、不出境 L3"实现。

## 1. 目标与非目标

### 1.1 目标

1. 订单生效后建立案件，任务/材料/进度事件全部按**四级来源**（cu 客户提交 / co 公司审核 / sp 服务方报告 / off 已核验官方凭据）呈现；无凭据不发布官方节点，sp 永不变 off。
2. 材料按"案件 × 申请人 × 清单项"组织，状态四态、退回有因；越权（含直链）服务端拒绝并审计；家庭授权按"人员×案件×动作×有效期"逐项校验（AT20）。
3. T0 硬截止任务多通道必达、失败换道、未读升级，**升级绝不改写原截止时间**（AT19）；客户侧与后台同一份送达事实。
4. A02 完整供给准入（境内主体/境外持牌方/自营交付部，控制点完全相同）；服务方门户四页签、批次授权、全屏水印、受控阅读器、到期自动回收（AT25）。
5. 顾问资质/授权到期或离职：停新接旧、在办强制交接五步、客户不失联（AT22 完整版）。
6. 服务方报告经 A06 核验才成官方节点；核验人 ≠ 案件发起人。

### 1.2 非目标

| 不做 | 说明 |
| --- | --- |
| 工单/投诉/合规事件完整链路（M4） | M3 只有任务协同与 T0 升级；服务质量队列在 M4 |
| 通知模板治理后台完整版、T2 营销（M4） | M3 交付 T0/T1 模板与送达回执能力，A09-home/T2 在 M4 |
| 佣金结算（M4） | 案件推进只产生佣金触发事件，不结算 |
| 服务方在线协同编辑/双向文件外发 | 门户只读 + 上传报告两类动作，不开放案件写权限 |
| 门户移动端 App | 响应式 Web 即可 |
| 跨境原始数据批量导出 | D9 法定路径确认前不做；确认后另开变更 |
| 税务居民判定等全球通行二期 | M5/Q6 之外不做 |

## 3. 详细需求

### M3-01 建案与案件看板

- **建案**：合同态 `effective` 且首付到账态 `verified`（M2）→ 自动生成 Case，按 ProjectVersion 的材料/任务模板生成清单与基线任务；建案事件含订单、方案、费表、规则版本快照。
- **案件阶段态（GP4 §10）**：`material_prep 材料准备 → pending_submit 待递交 → submitted 已递交（公司动作）→ accepted 已受理（官方，需凭据）→ supplementing 补件中 / reviewing 审理中 → approved 批准 / refused 拒绝（事实）→ closed 结案`。
- **并行独立异常态**：`paused 暂停 / lost_contact 失联 / disputed 争议`——独立记录、独立时间线段，**绝不并入"处理中"**；拒绝是官方事实，不渲染成败评价。
- **A06-board**：看板按阶段/异常分列，责任人、在办任务、T0 剩余时间；服务方报告在"待核验"泳道，不进官方列。
- 规则：阶段推进的写权限按角色（办理员/凭据核验岗）；`submitted→accepted` 必须挂 off 凭据且核验人≠发起人；无凭据的推进接口不存在。
- **验收**：无 off 凭据时 accepted 无法落库；异常态案件在看板与客户端独立成段。

### M3-02 任务系统与 T0 时钟

- **Task**：案件、类型、责任人（岗位/人）、截止时间、来源（官方要求/合同/公司 SLA）、是否 T0、升级链配置。
- T0 类（硬截止、客户权利相关）：补件截止、官方回执响应、合同约定通知等；T1 类：普通协同/提醒。
- 时钟由服务端定时驱动（BullMQ），截止时间一旦创建**不可被升级动作改写**；只有"官方改期凭据 + 核验通过"才能产生改期事件（保留原截止与改期原因）。
- 任务完成/逾期/升级全部事件化；逾期只触发升级链。
- **验收（AT19 时钟部分）**：构造任意升级链，数据库中截止时间字段不变，只新增升级事件。

### M3-03 材料中心（C10/P-12）

- **清单生成**：按 ProjectVersion 材料模板 × 案件申请人列表生成 Material 项：`案件 × Person × 材料类型`；状态 `pending 待提交 → submitted 待审核 → approved 已通过 / supplement_needed 需补充（原因+要求+时限）`；重交产生新版本，旧版标记作废不删除。
- **上传**：JPG/JPEG/PDF、单文件 ≤20MB（初始参数，可配置）；客户端直传加密桶（预签名 URL，服务端控制路径与 MIME/大小）；上传失败明确反馈、可重试，**不假成功**（分片/断点续传为体验增强，失败状态以服务端入库为准）。
- **审核**：办理员审核（通过/退回，退回必填原因+要求+时限，自动生成/关联 Task）；证件原件不向顾问/服务方开放默认查看。
- **客户视图**：按申请人分栏；他人材料行锁定 → P-12a 拦截态（明示"服务端已拒绝、非故障"、写审计、发授权邀请入口）。
- **规则**：
  - 无监护证据不能为子女提交；成年成员不得被默认代签（AT20，与 M3-05 联动）。
  - 已审核文件不可自行替换，只能走新版本。
  - 客户本人查看自己的 L3 原件也写访问记录。
  - OCR 仅做质检/预填辅助（如启用），不产生通过状态。
- **验收**：直链访问无授权材料返回 403 且审计有记录；退回后客户端可见原因/要求/时限三要素。

### M3-04 四级来源时间线与凭据核验门（A06-cred）

- **CaseEvent 四级**（颜色+文字+圆点三通道）：
  - `cu` 客户提交（蓝）；`co` 公司审核/动作（紫）；`sp` 服务方报告（琥珀，固定后缀"未经官方核验"）；`off` 已核验官方凭据（绿，含凭据与核验人）。
- **核验门**：
  - 服务方通过门户上传的报告/凭据只生成 `sp` 事件，进 A06 待核验队列；
  - 凭据核验岗逐件核验（原件比对/官方渠道核验，过程记录），通过才发布 `off`；不通过则保持 sp 并说明；
  - **核验人 ≠ 案件发起人**（SoD 服务端校验）；
  - 公司"已递交"是 co，官方"已受理"必须 off；两类措辞在模板中固定，不可改写。
- 客户端 P-11：时间线、节点凭据水印查看、补件/异常独立段、常驻"参考周期非承诺、无百分比进度"；无获批率/成功率。
- **验收（AT11/AT25 子集）**：sp 事件在任何接口响应中不可能带 off 标记；尝试由案件发起人自核验被 409 拒绝。

### M3-05 家庭授权与监护（Consent，P-18/A10-consent）

- **统一模型（GP4 §12）**：`主体 Person × 对象（案件/数据范围）× 动作 Action × 有效期 × 授予方式`。
- **动作枚举（开发前冻结，首期四类）**：`progress:view 查看进度`、`material:view_submit 查看与提交本人材料`、`matter:confirm 确认事项`、`notice:receive 接收通知`。
- **成年成员**：邀请（短信/邮件）→ 成员本人注册登录 → 逐项勾选动作与有效期 → 有效；主申不可代勾。
- **未成年子女**：登记监护证据（出生证明/户籍/监护文书，L3，核验岗核验）→ 可代理子女材料；状态 `evidence_pending → verified → dispute_frozen（争议冻结，转人工）`；离异/收养/身故争议系统不判定，转人工合规（M4 队列接单，M3 只冻结+提示）。
- **例外通道**：成年成员确无法本人操作 → 线下授权书受控登记（原件 L3 + 核验人 + 有效期，1–2 工作日 SLA 初始参数）。
- **撤回/过期**：服务端逐项、即时生效（顾问端、门户同步关闭新访问）；进行中的当次审核可完成，不扩展新范围；不溯及依法保留记录，但向客户说明保留依据（文案【门 D9】）。
- **跨境共享 Consent**：单独同意、不与其他授权捆绑、清单最小化、按 ServiceProvider 范围、可一键回收全部批次（门户在 M3-08 联动；法定路径 D9 未确认前不启用真实跨境共享，仅保留同意记录结构）。
- **验收（AT20）**：成年成员被默认代签、无监护证据提交子女材料、撤回后继续访问三类请求全部被服务端拒绝并审计。

### M3-06 T0/T1 通知引擎与送达回执（A09-tpl/rcpt 子集）

- **模板**：T0/T1 模板版本化、变量快照、A12 合规审核（M4 补完整 A09 后台；M3 提供最小模板管理：创建/审核/发布由合规角色操作）。
- **签约时采集并验证**联系方式（手机+邮箱），T0 通道偏好可改不可全关；**锁屏/推送摘要不含案号与项目细节**。
- **DeliveryRecord 状态机**：`pending 待发送 → sent 已发送 → delivered 已送达 → read 已读；failed 失败 → channel_switched 换通道 → manual_call 人工电话 → escalated 升级（顾问→主管/合规）`。
- **T0 换道升级链（初始参数，可配置，影子期校准）**：
  - 多通道并发首发（App+短信+邮件）；
  - App 推送 2 小时未读 → 短信；当日仍未达/未读 → 人工电话；
  - 距截止 ≤4 小时未触达本人 → 直升级主管；
  - 人工电话结果如实记录（含"家属代接、本人未确认理解"→ 继续升级直到本人）。
- **铁律**：升级链不改截止时间；后台与客户 P-13a 展示同一份逐通道回执与升级时间线；全部通道失败显"平台将人工联系"+备用联系方式更新入口，不静默。
- 通知与案件任务同源：T0 Task 自动生成 Notification，不允许个人手工发 T0。
- **验收（AT19，CASE-A02 回归）**：短信未达场景自动转人工、升级记录完整、截止时间不变、锁屏文案无案号、客户侧回执与后台一致。

### M3-07 供给准入 A02（ext/in 双模式）

- **主体类型**：`domestic_entity 境内签约/备案主体`、`overseas_licensee 境外外部持牌方（ext）`、`inhouse_delivery 自营交付部（in）`。
- **状态**：`incomplete 待补资质 → in_review 准入审核 → active 有效 → expiring 临期 → suspended 暂停（新签/全量）/ terminated 终止`。
- **准入要件（ext）**：关联境内协作主体 + 有效持牌 Credential（如 CICC/RCIC、OMARA MARN 等按国别配置，编号+有效期+核验记录）+ 协议四件（委托边界、保密与个人信息处理、跨境共享最小清单、禁夸大/禁虚假材料）。要件不全不可派案、不可开门户。
- **in 模式**：自营交付部人员同样备案、岗位授权、走同一套控制点；**不豁免、不替代目的地法定持牌环节**。
- 境外企业不得在境内直接提供中介服务的告知固化在配置与对客展示（M1 详情占位在 D2 后替换为真实主体信息）。
- 资质临期/到期：门户停权、派案停止、在办交接（与 M3-11 同机制，对象为机构）。
- **验收（AT25 前置）**：无有效持牌的境外方无法被选择为交付方（M2 主体门联动）；ext 与 in 账号的门户权限矩阵逐项相同。

### M3-08 门户账号与批次授权（PortalGrant）

- **门户账号**：按 ServiceProvider 开通，绑定机构、个人实名、MFA；账号生命周期随主体状态；ext/in 同一开通流程。
- **授权维度（GP4 §13）**：`ServiceProvider × Case × 材料范围 × 动作（roster 只读查看 / report_upload 上传报告）× 有效期`；原件查看为更高级别单独审批。
- **状态**：`pending 待审批 → viewable 可查看（水印）→ download_approving 下载/原件审批中 → download_window 限期可下载/查看 → expired 已到期自动回收 / revoked 提前撤销`。
- **默认值（初始参数）**：影印件批次有效期按案件需要逐案审批（示例 7–14 天）；原件查看窗口 2 小时、审批 SLA 1 工作日；到期定时任务自动回收（断链、失效预签名）。
- 门户账号可见范围 = 所有有效批次授权的并集，**无全局案件列表**；越权请求服务端拒绝 + 审计 + 异常访问冻结规则（阈值可配，触发转 M4 合规事件）。
- **验收（AT25）**：到期后历史链接立即失效；响应只含授权范围内材料；原件无审批不可见。

### M3-09 门户四页签（ext/in 同构）

1. **分流本案/我的案件**：仅授权案件、阶段、本次授权范围与剩余有效期；顶部常驻受控告知（只读、水印、禁下载另存打印、全程审计）。
2. **批次授权与材料**：授权批次列表（有效/待批/已回收）、受控阅读器入口、上传报告（sp 级，表单+附件，提交即进 A06 待核验）。
3. **报告/凭据提交**：提交记录与核验状态（sp 待核验 / 已核验发布 / 不通过说明）；官方结果不由门户录入。
4. **机构与资质**：机构信息、持牌/备案状态、门户成员、协议与到期提醒；in 模式显示自营部门岗位与备案信息，附加"自营不豁免"告知。
- 顶部模式标识：ext「外部持牌方」/ in「自营交付部」；底部固定受控声明条。
- **验收**：ext/in 两模式走同一权限中间件，差异仅在文案与主体类型字段。

### M3-10 受控阅读器与水印

- **水印**：登录用户姓名/机构 + 时间，对角平铺，服务端逐页渲染（或加密文档 + 动态水印层），全屏覆盖含固定底栏区域。
- **防落地**：不提供原始文件 URL（预签名 ≤2 分钟、逐页/分片）、禁右键/拖拽/复制/打印（体验层）+ 服务端不提供下载端点（根本层）；阅读器有会话超时与离开即清。
- **下载/原件**：审批通过后生成**带水印 PDF**（非原件）限时下载；原件查看走 2 小时窗口 + 全程页面级审计（谁、何时、看了哪几页）。
- 客户端顾问/内部查看 L3 同样走水印视图；财务默认无任何原件入口。
- **验收**：网络面板不存在长期有效的原始文件 URL；下载产物含水印身份信息；到期窗口自动关闭。

### M3-11 顾问交接五步与停新接旧（A04-handoff，AT22 完整版）

- **触发**：资质/授权到期、顾问离职/暂停/调查、机构到期、客户申请换顾问（M4 工单驱动，M3 提供机制）。
- **五步（GP4 §5/V2 §5.7）**：①客户发起或同意（离职等平台强制情形向客户告知并给异议窗口）→ ②冻结新分配/新报价/新签 → ③资料与在办交接清单（案件、材料、任务、待办逐项核对）→ ④新顾问接受 → ⑤切换通知（客户 T0/T1 + 顾问双方）。
- 交接完成前旧顾问仍担在办责任、客户不失联；来源/关系/佣金归因三字段分离记录（归因规则 M4）。
- 系统不允许顾问自行把客户转给他人；强制交接由 A04 岗位执行并双人复核。
- **验收**：停新接旧账号无法发起任何新方案/订单（接口级），但在办案件只读可见且客户侧显示接管安排；五步缺一步不可切换。

### M3-12 顾问端交付协同（S-07 交付域）

- biz 页签：案件阶段（只读，co/off 同源）、下一步任务、模板化提醒（经 A09 送达、可查回执）；不可改官方进度、不可标到账、不可改金额。
- follow：跟进记录（词库校验、更正留痕）。
- scope：可见/不可见清单、原件批次访问申请（走 A06/A10 审批，限时水印）、申请状态。
- 工单协同项在 M4 接通；M3 顾问只收到任务协同，不显示投诉正文（接口不下发）。

### M3-13 客户端案件列表与办理中首页

- P-10：进行中案件卡（项目、成员、主责顾问、阶段指引步骤条——非百分比、待办数、T0 截止）；历史/暂停案件只读+说明；空态真实。
- 首页办理中态（M1 游客态升级）：按"时限等级+截止"排序待办，T0 置顶；每条=现状一句话+下一步+责任人+截止；顾问异常显示接管安排（AT22）；加载失败保留缓存+更新时间，不伪装"暂无待办"。

## 6. 服务端闸门清单

1. 阶段推进与事件来源的合法性（状态机白名单 + off 凭据强制）。
2. 所有材料/案件访问过 Consent/关系/批次三重校验（PEP），直链同样拦截。
3. T0 截止字段只接受"凭据核验改期"一种变更路径，升级链无写权限。
4. 通知发送、换道、升级、电话结果全部事件化且对客同源可见。
5. 门户每个请求校验"账号→有效批次→案件→材料范围→动作→有效期"六元组。
6. 原件/下载无审批不产生 URL；所有渲染与翻页写审计。
7. ext/in 同中间件、同水印、同回收、同审计（自营不豁免）。
8. 交接五步与停新接旧冻结在服务端强制执行。
9. 跨境共享：D9 开关关闭时，任何批量导出/原始文件跨境端点不存在（不只是禁用）。
10. L3 访问（含客户本人、顾问、门户、核验岗）全部入哈希链审计。

## 7. 关键异常与边界

| 场景 | 行为 |
| --- | --- |
| 服务方报告与官方结果冲突 | sp 保持琥珀；以 off 核验为准；冲突留痕并通知办理岗 |
| 门户账号异常访问（越权枚举） | 拒绝+审计+阈值冻结账号，转 M4 合规事件 |
| 批次到期时服务方正在阅读 | 宽限不超过当前页（初始参数 3 分钟）后断链；审计记录 |
| 客户失联 | lost_contact 独立态；T0 升级链走完仍失联转人工外呼/工单（M4），不改截止 |
| 补件逾期 | 任务逾期事件 + 官方后果说明（按官方告知原文，不吓唬），不自动判失败 |
| 成年成员撤回授权时材料在审 | 当次审核完成、停止新访问；结果仍回写案件 |
| 监护争议 | 争议冻结相关材料动作，转人工；系统不做法律判断 |
| 通知全部通道失效 | 显式人工跟进任务+主管升级；客户侧显示"平台将人工联系" |
| 机构资质到期有在办 | 门户停权、停新派案、在办按交接机制处置，客户不失联 |
| 文件上传中断 | 不入 submitted；客户端可重试，不产生假成功记录 |

## 8. 验收用例（AT 映射）

1. **AT19 T0**：CASE-A02 场景全链回放——三通道首发、App 未读转短信、短信未达转人工、家属代接继续升级、主管升级；截止时间全程不变；客户 P-13a 与后台回执逐笔一致；锁屏无案号。
2. **AT11/四级来源**：门户提交报告显示 sp（琥珀+后缀）；核验后才出 off（绿+核验人）；发起人自核验被拒。
3. **AT20 家庭授权**：四类动作逐项校验；默认代签成年成员、无证据代子女、撤回后访问三场景均拒绝并审计；P-12a 拦截态文案与入口正确。
4. **AT25 门户**：ext 与 in 账号分别走查四页签，权限矩阵一致；到期批次链接失效；水印含身份时间；原件无审批不可见、审批后 2h 窗口、页面级留痕；越权六元组尝试全拒。
5. **AT22 交接**：到期顾问账号停新接旧（接口级），五步未齐不可切换，切换后客户收到通知且首页显示新顾问。
6. **材料不假成功**：上传失败无 submitted 记录；退回三要素齐全；已审核文件替换走新版本。
7. **异常态独立**：暂停/失联/争议案件在看板、客户端均独立成段，不存在"处理中"合并。
8. **D9 保护**：跨境开关关闭时，批量导出/跨境原始端点不存在（接口扫描断言）。

## 10. 发布策略
