# PRD-M4 保障闭环、结算、通知治理与总后台收尾（研发级）

- 版本：v0.1（2026-09-22，随 PRD 基线冻结）
- 里程碑：M4（依赖 M0–M3；佣金规则与退款比例受 D6/D8 决策门约束）
- 依据：V2 §5.6/5.8/5.10、GP3 第2批 C11/C12、第3批 S-09、第4批 A07/A08/A09/A10/A11/A12、GP4 §15/§16、总后台高保真 A07–A12
- 成熟度：可进入研发排期；佣金规则数值、退款节点表在 D6/D8 与合同定稿前用配置占位，不写死。

## 1. 目标与非目标

### 1.1 目标

1. 工单/投诉形成"有编号、有责任人、有状态、有结果"的闭环；**投诉独立队列、调查回避**；私收款/误导承诺自动生成合规事件（AT26）。
2. 合规工作台（A12）贯通：事件发现 → 分级 → 调查 → 处置（顾问/机构/资金）→ 申诉 → 归档；处置联动授权、门户、佣金、关系交接。
3. 佣金六态不可逆跳步、双人结算、异币种不合并、冻结/调整/追回全程留痕；点击/咨询/方案确认不产生可提现佣金（红线⑦）。
4. M2 退款/调整申请在此执行：独立工单 + 双人复核 + 财务执行 + 佣金联动；不承诺"不成功全退"。
5. 通知治理完整版（A09）：模板审核、通道与回执看板、T2 营销单独同意/退订、首页内容编排。
6. A10 权限/审批/审计、A11 报表基线、A12 词库/话术/事件补齐；**控制矩阵逐格可测**，完成"一后台控两终端一门户"的内容与控制点闭环。
7. 防骗教育专区（P-16）与服务目录（P-14）上线。

### 1.2 非目标

| 不做 | 说明 |
| --- | --- |
| 多级分佣、团队管理、自动分账 | 首期单级顾问佣金 + 财务双人；多级在 V1.5 评估 |
| 平台资金托管/自动打款 | 【门 D8】不做；结算单驱动线下财务执行并登记 |
| AI 自动判投诉/自动处置 | 仅线索与分级建议，处置必须人工 |
| 全量 BI/数据仓库 | A11 只做运营质量基线看板与导出 |
| 服务方结算门户 | 境外/自营结算走线下协议与财务台账，不在门户开放 |
| 营销自动化/推送平台 | T2 仅最小人工编排 |

## 3. 详细需求

### M4-01 服务目录与工单（P-14/P-15/15a/15b）

- **P-14 目录**：左分类（了解评估/签约费用/办理材料/进度结果/变更投诉/家庭授权）右宫格；每项标注是否需登录、是否需顾问/服务方；公开类游客可见，提交类登录。
- **类型**：预约咨询 / 疑问 / 资料变更 / 投诉；可关联订单/案件（可选）；描述必填、附件 JPG/PDF。
- **提交即有编号**（不假成功：服务端落库才返回单号）；草稿本机保留。
- **P-15b 详情**：单号、类型、受理部门（机构岗位，非顾问个人）、首次响应承诺、状态时间线、补充信息、撤回（填原因，已受理记录保留）、关闭后评价、不认可申请复核。
- **变更类**：涉合同/费用/申请人的变更不"提交即生效"，显"需重新确认/登记"，流转 A05/A06 回写订单/案件（M2/M3 冻结态在此解冻或驳回）。
- **平台外交易投诉**：无登记订单也可提交（合规线索价值），但显式告知保障边界，提供合规举报与合法途径建议，不一推了之、不假装受理资金争议。

### M4-02 工单受理分派（A08）

- **状态机（GP4 §15）**：`draft 草稿 → submitted 已提交 → accepted 已受理 → processing 处理中 / info_needed 待补充（可循环）→ resolved_pending 已解决待确认 → closed 已关闭 / rated 已评价`；支线：`review_pending 复核中 → compliance_referred 转合规`、`withdrawn 已撤回`。
- **分派**：系统按类型+队列分派（不由顾问挑单）；投诉队列与普通工单物理隔离；顾问只见协同项、不见投诉正文、不能关闭。
- **SLA（初始参数，可配置，合同定稿前为内部标准）**：咨询 1 工作日受理；投诉 1 工作日受理，复杂件调查时限默认 10 工作日（合规制度定稿后校准）；超时自动升级（与 M3 升级引擎同源：队列负责人→主管→合规）。
- 顾问离职/暂停时其协同工单自动改派（复用 M3 交接机制）。
- 每个状态必须有责任角色与下一步说明，禁止"处理中"吞异常。

### M4-03 投诉独立受理与回避（AT26）

- 投诉提交页显著告知：进入客服/合规独立队列，被投诉顾问不可见正文、不可处理/关闭。
- **争议分类**：服务未交付 / 交付质量 / 官方结果（拒绝/补件）/ 平台外交易；**官方结果≠服务失败**，该类投诉的处理结论以服务范围与凭据记录为准。
- **回避**：被投诉人及其汇报链（可配置层级）不参与分派与调查；调查人变更留痕。
- **私收款/误导承诺**：提交即自动创建 ComplianceEvent（线索级，不需人工判断是否"够严重"），同时冻结被投诉顾问新增授权（M3-11 停新接旧），客户侧可见"已进入独立调查"。
- 处置结果与补救向客户反馈；不以"和解"关闭合规事件；客户不认可可申请一次复核（复核人未参与原调查）。

### M4-04 合规工作台（A12-evt）

- **事件来源**：投诉自动转、词库命中（方案/话术/素材/讲解四生产点）、主体门反复阻断、门户越权、审计异常、外部举报、财务异常。
- **分级（初始）**：L1 一般（话术瑕疵）/ L2 严重（误导承诺、越权查看）/ L3 重大（私收款、虚假材料、资金风险）；分级可人工调整并留理由。
- **状态**：`new 线索 → triaged 已分级 → investigating 调查中（回避规则）→ proposed 处置待批 → decided 已决定 → closed 已归档`；当事人申诉支线 `appeal_pending → appeal_reviewed`。
- **处置动作（可组合，均有独立审批与留痕）**：顾问警告/培训、暂停授权、终止合作、停新接旧与交接（调 M3-11）、门户账号冻结/回收批次、佣金冻结/调整/追回（调 M4-06）、退款方案（调 M4-05）、证据保全（审计 WORM 导出）。
- **L3 双人审批**（合规负责人 + 财务/法务其一，按类型）；任何处置不可由单人完成。
- 私收款核实原则：冻结新增授权；**已发生的合规佣金不连坐清零**（红线⑦），调整按规则与事实逐笔处理。
- 事件、证据、决定、申诉全部哈希链审计；当事人可见与其相关的结论摘要（不含调查人隐私字段）。

### M4-05 退款/订单调整执行

- 接续 M2 `refund_pending/change_pending`：工单受理 → 事实核对（合同、到账、服务记录、官方结果）→ 退款/调整方案（A05 业务复核 + A07 财务复核，双人；金额类强制）。
- **规则（对客前置告知同 M2）**：已代收代付官方费、已发生第三方费按实扣除；境外专业费按已完成工作量结算；以合同条款为准；**不出现"不成功全额退款"**；顾问无权承诺比例/时限（词库 + 方案/话术拦截）。
- 财务执行（线下转账登记 + 凭证，D8 路径）→ 客户确认到账/异议 → 关闭；收据冲红/更正留痕，不删除原记录。
- 佣金联动：退款触发对应佣金冻结/追回评估（M4-06），客户侧不见佣金细节，只见退款结果。
- **验收**：无双人复核的退款方案不可执行；执行后订单/收据/佣金三处记录一致。

### M4-06 佣金六态与结算（A07-comm、S-09）

- **六态（GP4 §16，不可逆跳步）**：
  `not_accrued 未计提 → accrued 已计提（订单生效/到账触发，规则快照版本）→ frozen 冻结（争议/投诉/退款/合规事件）→ settled 已结算（结算周期双人复核通过）→ paid 已支付（财务执行登记）→ clawback 追回（事后事实）`；
  调整：`adjusted` 作为事件记录，不覆盖历史。
- **触发规则（配置化，D6 定稿前只放结构与影子数据）**：按 FeeSchedule/佣金规则版本；到账核验后计提；官方/第三方费、未发生费不产生佣金；异币种分列、**不合并、不折算汇总**。
- **不产生佣金的动作**：点击、浏览、咨询、预约、名片扫码、方案确认（服务端无计提路径）。
- **结算流程**：周期生成结算单 → 财务复核（双人，异币种逐笔）→ 审批 → 线下支付登记（无自动打款）→ 顾问端 S-09 可见状态与明细（不含他人、不含客户资金账户信息）。
- **冻结矩阵**：投诉立案（涉事订单佣金冻结）、退款申请（关联部分冻结）、合规 L2+（顾问新增冻结）、离职交接（在办按规则归属，归因三分离字段裁决）。
- 私收款：冻结新增授权与新计提；合规历史佣金不自动清零，逐笔决定。
- **验收**：状态迁移测试证明不可跳步（如 not_accrued→settled 拒绝）；顾问端任何接口不可自计提；异币种无合计列。

### M4-07 通知治理完整版（A09）

- **模板**：T0/T1/T2 分类；草稿→审核（合规）→发布→版本归档；变量白名单（禁自由文本注入）；锁屏摘要单独配置（脱敏）。
- **看板**：逐通道送达率/失败原因/换道次数/人工电话结果/T0 升级热力；失败通道告警阈值（初始参数）。
- **通道管理**：供应商配置（可插拔，至少主备两家短信）、频控、签名/模板合规；客户联系方式验证流程（改号需验证，旧失败记录保留）。
- **T2 营销**：单独同意（注册不默认勾选）、一键退订、与 T0/T1 物理分群不混发；退订即时生效。
- **首页内容编排（A09-home，M1 游客态的运营后台）**：首页卡片/教育位/公告的草稿-审核-发布（复用四眼流）；定时上下架；内容词库校验；紧急公告通道（合规双人发布）。
- **验收**：T2 退订后该通道零下发（断言任务）；T0 模板未经审核不可被任务系统引用。

### M4-08 防骗教育专区（P-16）

- 内容：识别私收款/个人账户、主体三要素自查、"不成功全退"等违规承诺识别、官方渠道核验方法、平台外交易保障边界（D5 客观告知，不恐吓）。
- 内容走 A12/A09 审核发布；每篇含"立即核验/投诉"入口（跳 M4-01/03）。
- 对未登记平台订单客户：展示保障边界说明 + 合法途径，不展示其案件数据。

### M4-09 A10 权限、审批、Consent 台账与审计

- **RBAC+ABAC**：角色矩阵（沿用各 PRD 角色）+ 关系型授权（顾问↔客户、门户↔批次、岗位 SoD 互斥）；最小权限默认拒绝。
- **审批中心**：统一待办（报价复核、合同登记、原件审批、门户批次、合规处置、结算、退款、内容发布），审批人按矩阵自动过滤（本人申请不可自审）。
- **Consent 台账**：家庭授权、跨境共享、告知 Consent、营销订阅四类统一查询：人×对象×动作×有效期×授予方式×状态；到期/撤回影响面预览（将关闭哪些访问）。
- **审计**：全量关键动作哈希链（技术方案已定）；A10 提供按客户/案件/顾问/机构/时间的检索、WORM Object Lock 导出（双人审批导出，水印+申请事由）；异常访问规则（越权尝试、异常时段批量访问、门户枚举）告警入合规线索。
- 员工 MFA、敏感操作 step-up（M0 已建，此处接审计策略）。
- **验收（AT09 子集）**：抽 10 个高风险动作验证"无权限=接口拒绝+审计"；导出无审批不可用。

### M4-10 A11 运营质量基线看板

- 首期指标（口径在看板内写明，不设未经验证的目标值）：
  - 供给：核验节拍达成率、临期/过期主体数；
  - 交易：主体门阻断次数及原因分布、凭证核验时长、重复凭证拦截数；
  - 交付：T0 送达率/换道率/升级闭环率、补件按时率、sp→off 核验时长；
  - 保障：工单首响时长、投诉受理/调查时长、回避执行率、退款处理时长；
  - 内容：词库拦截分布、模板/发布四眼执行率；
  - 授权：到期授权数、越权拒绝数、批次回收及时率。
- 支持按时间/机构/顾问筛选与导出（CSV）；样本不足显"样本积累中"，不造趋势。
- 指标只用于运营基线与影子期参数校准，不对客宣传。

### M4-11 A12 合规工作台补齐

- **词库**：block/warn 分级、四生产点统一引用、命中审计与申诉复核（误命中可由合规调整，调整留痕）。
- **话术/素材**：超模板话术人工署名审核（AT23）；分享素材库版本化（M1 分享链路的完整后台：核准素材、过期下架、名片白名单联动）。
- **合同/告知文本库**：模板版本与 M2 合同登记联动。
- **凭据核验记录**：off 凭据的核验方式/核验人留痕（M3 队列的后台台账）。
- **监管备案台账**：机构/人员备案信息、到期提醒（M1 台账的合规视图补齐）。

### M4-12 独立回访

- 工单关闭、案件结案后由**非顾问**岗位（客服/质检）发起满意度与回访（站内/短信模板）；结果进 A11；差评自动生成复核线索（不自动改判）。

### M4-13 控制矩阵收尾

- 以技术方案 §10 控制矩阵为基线逐格补自动化测试（前端隐藏≠控制：每格至少一个接口级拒绝用例）；产出《控制矩阵测试对照表》作为 M4 出口物，未覆盖格不得进入 M5 放量。

## 6. 服务端闸门清单

1. 投诉正文对被投诉人在所有接口（列表/详情/搜索/导出）不可见。
2. 私收款/误导承诺关键词与投诉类型组合触发自动建事件，人工不可"删除线索"（只能合并/驳回并留痕）。
3. 处置动作前置事件状态；L3 双人；顾问本人/汇报链回避校验。
4. 佣金每个状态迁移白名单校验；结算双人；异币种逐笔无合计；非触发动作无计提入口。
5. 退款金额双人 + 合同条款快照校验；"全退"类表述在工单回复中被词库拦截。
6. T0/T1/T2 模板与人群隔离；退订名单在发送前强制过滤。
7. 审批矩阵：申请人≠审批人；SoD 互斥角色服务端拒绝。
8. 审计导出双人审批、水印、限时、下载日志；L3 导出默认不允许。
9. 内容/素材/话术发布四眼流与词库校验缺一不可（含首页编排与教育专区）。
10. 控制矩阵每格至少一条接口级拒绝测试；前端隐藏不计为控制。

## 7. 关键异常与边界

| 场景 | 行为 |
| --- | --- |
| 投诉人撤回投诉但已涉私收款线索 | 工单可撤回，合规事件不撤销，继续调查并告知客户边界 |
| 顾问对投诉认定申诉 | 申诉期间处置不停止（L2/L3 先保护客户），申诉结论可调整并留痕 |
| 结算周期内订单退款 | 已计提未结算直接冻结；已结算走追回评估流程，不静默扣下期 |
| 官方拒批后的退款争议 | 以服务范围/凭据记录处理；官方结果≠服务失败的结论模板化呈现 |
| 通道商大面积故障 | 自动切备用通道；T0 转人工电话；看板告警 |
| 审计日志被篡改检测 | 哈希链校验失败立即告警合规负责人，冻结相关导出能力 |
| 当事人为员工本人 | 跨角色回避（员工投诉走更高层级，制度配置） |
| 指标口径变更 | 版本化口径，历史数据不重算，标注口径版本 |

## 8. 验收用例（AT 映射）

1. **AT26 投诉独立**：被投诉顾问账号在列表/详情/搜索/通知均看不到投诉正文与客户身份；私收款投诉自动生成事件并冻结新授权；调查人非其汇报链。
2. **和解不销案**：客户与顾问私下和解后，合规事件仍需决定与归档，状态不可被关闭请求改写。
3. **佣金六态**：全迁移白名单测试（合法路径通过、跳步全拒）；点击/咨询/方案确认后无 accrued 记录；异币种结算单无合计列。
4. **退款双人**：单人审批执行被拒；执行后订单、收据冲红、佣金冻结三处一致；对客页面无"全退"字样。
5. **T2 隔离**：退订客户不再收到任何 T2，T0/T1 不受影响；混发任务在发布前被拦截。
6. **AT09 审计**：越权动作矩阵抽测全部 403+审计；导出无审批/超期链接均失败且留痕。
7. **SLA 升级**：咨询/投诉超时自动升级且时间线对客可见处理部门（不暴露个人隐私）。
8. **控制矩阵**：M4 出口《控制矩阵测试对照表》100% 覆盖技术方案 §10 矩阵格。
9. **回访独立**：回访由非顾问岗位触发，差评生成复核线索，顾问端不可见回访原始差评人映射（对事不对人保护）。
