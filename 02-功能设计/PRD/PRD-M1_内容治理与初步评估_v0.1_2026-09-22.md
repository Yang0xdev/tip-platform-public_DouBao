## 1. 本里程碑要解决的决定

M1 交付一条最小但完整的价值链：

> **后台能把"经核验、经复核、经合规审核"的项目内容与问卷发布出来 → 游客无需留资即可浏览并完成初步评估 → 顾问完成入驻、学习与项目授权，获得受控展业资格。**

它同时把三条红线第一次变成可执行的系统行为：**无核验不发布（编辑≠核验≠发布）、无授权不展业（五步闭环）、禁表述词库在内容生产端强拦截（AT23）**。

### 1.1 目标（可验收）

1. 一个项目从草稿到对客可见，必须经过"编辑 → 事实核验 → 收费复核 → 发布复核"，且这些动作不能由同一人闭环；未核验事实在任何终端不可见。
2. 客户端游客（不登录）可完成：首页游客态、项目发现、项目详情、本机收藏/比较、初步评估与四类结果；全程无注册墙、无成功率/评分/总价。
3. 顾问可完成入驻提交与审核、项目必读学习、授权申请与审批；未授权项目在顾问端锁报价、锁方案、锁佣金。
4. 初评问卷与结论模板由后台版本化管理；初评只输出"已知符合/明显差距/待确认/来源时间"，超模板转人工标记（人工解读流转在 M2）。
5. 全球通行数据源开关框架就位（默认关闭），授权失效可一键下架（Q6）。

### 1.2 非目标（本期明确不做）

| 不做 | 原因 / 重新考虑条件 |
| --- | --- |
| 方案、报价复核流、订单、合同、支付、收据（M2） | 依赖 D2/D4/D8；本里程碑不产生任何交易与佣金 |
| 关系双向确认、咨询分配、换顾问（M2/M3，A04） | M1 名片只读展示；"请求服务/预约/请顾问解读"按钮置灰并提示"即将开放"，不做僵尸成功反馈 |
| 人工初评解读的流转工作台 | M1 仅产生 `needs_manual` 标记与记录，影子期线下处理；M2 随 A04/S-01 上线 |
| 案件、材料、T0、门户、iPad（M3） | — |
| 工单/投诉/合规事件完整链路（M4） | M1 仅在词库命中、越权尝试处写审计事件，供 M4 接入 |
| 境外持牌方/自营交付部门户与派案（A02 完整版，M3） | M1 只建"境内机构最小台账"作为顾问入驻的归属对象 |

| 个性化推荐/行为画像 | 首期只按静态标签编排 |

## 3. 角色与权限矩阵（M1）

角色（M0 建账号与角色体系，M1 定义策略）：

| 角色 | 说明 | 关键互斥（职责分离） |
| --- | --- | --- |
| `content_editor` 内容运营 | 编辑项目版本、收费草稿、首页内容位 | 不能核验自己编辑的事实；不能发布 |
| `fact_verifier` 项目核验岗 | 登记/复核 VerificationRecord | 不能核验本人编辑的版本；不能发布 |
| `pricing_reviewer` 报价复核岗 | 复核 FeeScheduleVersion | 不能复核本人编辑的费项 |
| `publisher` 发布复核人 | 最终发布/暂停/下架 | 不能发布本人最后编辑的版本（四眼） |
| `compliance_editor/reviewer` 合规岗 | 词库、问卷模板、顾问自述/名片审核 | 词库与模板同样走编辑→复核 |
| `advisor_admin` 顾问管理岗 | 入驻审核、授权审批、机构台账 | 审批自己介绍进来的顾问需第二人（影子期可配置） |
| `advisor` 顾问 | 入驻、学习、申请授权、受控展业 | 只读项目事实；无任何后台写权限 |
| `customer`/`guest` 客户/游客 | 浏览、初评、收藏 | — |

互斥规则在 Casbin 策略 + 服务端 SoD 校验双层实现；所有"提交/审核/发布"动作记录 actor 与角色，闭环同人时服务端返回 409 并写审计。

## 4. 详细需求

### M1-01 境内机构最小台账（A02 子集）

- **触发**：顾问入驻前必须有所属境内备案机构；顾问管理岗在后台维护。
- **字段**：机构名称、统一社会信用代码、出入境中介备案状态（依当地监管口径，字段可配置）、备案编号、备案有效期、联系人/联系方式（L2）、状态（待备案/有效/临期/暂停/终止）、备注。
- **规则**：
  - 顾问入驻只能选择状态为"有效/临期"的机构；机构到期后其下顾问**停新接旧**（授权不新批、已有授权到期不续，在办交接在 M3 补，本期仅冻结新授权并在顾问端显示原因）。
  - 机构状态变更、字段变更双人留痕（编辑+复核，影子期可由 advisor_admin 单人操作但必须写审计并在 M3 前补齐复核记录）。
- **异常**：备案到期前 60/30/7 天进看板提醒（初始参数，影子期校准）；到期当日定时任务批量冻结新授权。
- **验收**：无有效机构时顾问入驻提交被服务端拒绝；机构到期后授权申请入口关闭。

### M1-02 项目库与项目版本（A01-p）

- **对象**：`Project`（稳定身份）与 `ProjectVersion`（内容版本，GP4 §1）。
- **ProjectVersion 编辑字段**：
  - 基础：项目名、目的地（受控词表）、身份性质（长期居留/永居/入籍等**准确标签**，禁模糊词）、人群标签（多选受控词表）、交付模式（外部持牌 ext / 自营交付 in，M1 仅元数据，门户在 M3）。
  - 内容：结构化申请条件（条目化，每条可挂核验记录）、办理流程阶段、材料清单模板、责任分工、参考周期区间（必带"非承诺"标记）、自助边界、保障边界文本（A12 审核版）。
  - 关联：收费方案版本（M1-04）、初评规则集（M1-08）、数据源（无）。
- **规则**：
  - 版本状态机（服务端强制，GP4 §1）：
    `draft 草稿 → pending_verification 待核验 → pending_publish 待发布复核 → published 已发布 → suspended 暂停（停新签、存量只读）→ delisted 下架（历史只读+说明）`；
    核验/复核驳回回 `draft`（带原因）；修订已发布版本 = 新建版本，旧版本归档只读。
  - 客户端只读到 `published` 且当前生效的版本；暂停/下架版本新客不可见，详情页转说明页。
  - 所有富文本/结构化文本在提交时过词库校验（M1-06），命中不可提交。
  - 参考周期、费用等数值字段必须选择口径来源（关联核验记录或显式"待确认"）。
- **异常**：两人同时编辑同一草稿 → 乐观锁（version 冲突提示合并/覆盖选择，不静默覆盖）；发布期间被编辑 → 发布快照锁定，编辑进入新版本草稿。
- **验收（成功）**：运营创建 v1 草稿 → 核验通过 → 收费复核通过 → 发布复核通过后，客户端列表/详情可见且带版本号与核验日期。
- **验收（失败）**：任一条件事实无有效核验记录时，"提交发布"被服务端拒绝并逐条列出缺失事实（反例：B 地区 v0.9 三项事实无记录不可发布）。

### M1-03 事实核验台账（A01-v）

- **对象**：`VerificationRecord`：事实描述、事实类型（政策/条件/官方费/持牌要求/周期）、来源类型（官方链接/官方文件/持牌方书面确认）、来源 URL 或附件、来源发布日期、核验人、核验日期、下次复核日期、状态（verified 已核验 / due 临期 / invalid 失效）。
- **规则**：
  - 项目版本中每条"关键事实"必须关联一条 `verified` 记录才能发布；"待确认"项允许发布但对客显式展示"待确认 + 官方核对入口"，**不得显示编造数值**。
  - 核验人 ≠ 该版本最后编辑人（SoD）。
  - 定时任务：到期前 30/7 天进临期看板（初始参数）；到期当日记录置 `due`；来源被标记失效置 `invalid` 并**自动阻断关联版本对客展示**（详情转"内容复核中"），同时通知编辑与核验岗。
  - 官方链接失效：客户端显示"链接待更新"，不假装有效。
  - 初始复核节拍：政策类 90 天、费用类随官方公布、其他 180 天（产品初始参数，A11 数据校准后调整）。
- **验收**：核验记录失效后，关联项目在客户端 15 分钟内（定时任务节拍，影子期配置）不可见新入口，后台看板可见阻断事件。

### M1-04 收费方案版本（A01-fee）

- **对象**：`FeeScheduleVersion`（GP4 §2）：费项名、收取方枚举（`platform 平台 / domestic_entity 境内机构 / overseas_licensee 境外持牌方 / official_passthrough 官方代收代付 / third_party 第三方`）、币种（ISO 4217）、金额或区间、确定性（fixed 确定 / estimated 估算 / tbc 待确认）、发生时点、退款节点（文本，M2 生效）、版本号、生效期。
- **规则**：
  - 状态：`draft → in_review → published → superseded`；复核人 ≠ 编辑人。
  - **异币种分列、不合计、不折算总价**；服务端不提供"总价"字段，客户端/顾问端也不允许自行加总（金额组件按币种分组渲染）。
  - `tbc` 项必须显式展示，金额不得为 0 或留空冒充；官方费标"可能调整/代收代付"。
  - 发布后被未来订单快照锁定（订单在 M2，本期只保证版本不可变、只可出新版）。
  - 顾问端在未授权前不可见佣金维度（佣金规则 M2/M4，本期字段不下发）。
- **验收**：含多币种费项的项目，任何终端不出现合计总价；费项修改产生新版本号，旧版本只读可追溯。

### M1-05 发布四眼流（A01-pub）

- **流程**：
  1. 编辑完成项目版本（含收费选择、规则集选择）→ 提交核验；
  2. 核验岗逐事实核验/确认 → 通过转待发布复核，驳回带逐条原因回草稿；
  3. 系统自动校验：词库（零命中）、核验完整性、收费复核完成、问卷/规则集版本有效；
  4. 发布复核人查看与当前线上版本的 **diff**（字段级增删改 + 核验状态变化）→ 通过发布 / 驳回。
- **规则**：
  - 同一版本中，编辑、核验、发布三类动作至少出现两个不同自然人，且"最后编辑人 = 发布人"禁止；收费复核为独立环节。
  - 发布动作生成不可变发布快照（内容、收费、规则、词库版本号、模板版本号一并固化），写事件与审计。
  - 发布后对相关顾问产生"规则更新 → 旧阅读确认失效"事件（M1-10）。
  - 暂停/下架需填写原因类别与对在办客户的处置说明（在办客户通知在 M3，本期只存文案）。
- **验收**：用同一账号尝试编辑+发布同一版本被拒；diff 页能看到每一处变化；发布事件在审计链可查且含前后值。

### M1-06 禁表述词库与内容校验（A12-words）

- **对象**：`WordLibraryVersion`：词条、类别（保证性/成功率/内部渠道/违规承诺/投资收益/时限承诺…）、匹配方式（精确/短语/正则，由合规配置）、处置（block 强拦截 / warn 人工复核）、适用生产点、版本、状态（草稿/复核中/已发布/停用）。
- **生产点（M1 覆盖三个）**：
  1. 后台项目版本与首页内容位提交/发布；
  2. 初评问卷模板、结论模板、初评规则的文案；
  3. 顾问入驻自述、名片自述字段（提交与审核两处都校验）。
  - （方案/讲解/iPad 两个生产点在 M2/M3 接入，词库服务一次建成、生产点逐步挂接。）
- **规则**：
  - 词库同样走编辑→复核→发布；发布后即时生效于所有生产点（配置缓存 ≤ 5 分钟刷新，发布事件主动失效缓存）。
  - `block` 命中：服务端拒绝保存/提交并返回命中词条与位置；`warn`：允许进入但必须人工复核通过。
  - 词库校验为**服务端唯一裁决**；前端实时校验仅为体验，断网/绕过前端时服务端仍拦截。
  - 词库命中事件写审计（词条、生产点、提交人、时间），供 M4 合规事件与 A11 质检。
  - 初评结果文案由模板拼装，不允许自由文本承诺；自动结果不出现任何人名背书。
- **验收（AT23 子集）**：在项目详情文本、问卷结论、顾问自述三处分别植入"包过/成功率/内部渠道"类词，均无法提交；词库升级后旧草稿再次提交时按新词库校验。

### M1-07 初评问卷与结论模板（A12-rev）

- **对象**：`AssessmentTemplateVersion`（题组、题目、题型、必填、跳转逻辑、适用项目）与 `ResultTemplateVersion`（四类结论的呈现模板与固定性质提示文案）。
- **规则**：
  - 模板状态：草稿 → 合规复核中 → 已发布 → 被替代；客户端与 iPad（M3）只加载已发布版本，顶部向用户展示版本号。
  - 题目最小集（以高保真 v3.2 题组为基线，合规评审冻结）：目的地/项目意向、家庭构成（成年随行成员的本人授权提示文案）、年龄/学历/语言/职业（自填，**不要证件**）、预算区间（可选，分币种不合计）、时间偏好。
  - 不含证件号、证件影像、账户信息；不采集与初评无关的敏感信息。
  - 模板升版后，未提交的旧草稿提示按新版补答；已出结果标注"基于 vX"。
- **验收**：未发布/已停用模板在客户端不可加载；模板更新走审核留痕。

### M1-08 初评规则集与结果生成（C06 引擎）

- **对象**：`AssessmentRuleSet`（随 ProjectVersion 管理，状态同项目版本，需核验与发布）：
  - 每个项目条件结构化表达：`{条件项, 运算符, 期望值/区间, 证据(核验记录ID), 映射题目}`；
  - 每条答复映射为：`met 已知符合 / gap 明显差距（含可补方向文案，不承诺可弥补）/ tbc 待确认`；
  - 无法被规则覆盖的答复组合 → `needs_manual`。
- **结果结构（固定四类 + 性质提示）**：
  1. 已知符合项（引用项目条件版本与核验时间）；
  2. 明显差距项（差距是什么、可能方向，不承诺）；
  3. 待确认项（需官方/持牌方核实）；
  4. 信息来源与时间（数据/条件版本、核验日期、官方链接）。
  - 常驻性质提示："信息整理与差距提示，不是资格认定、不构成法律意见、不代表获批结果，个案以官方审核为准。"
- **流程与权限**：
  - 游客：问卷在端上填写，**结果由服务端无状态接口计算**（不长期保存、不建账号；接口限流、不落 L2 明细，仅留聚合日志）；草稿存本机。
  - 登录客户：可保存问卷与结果到本人账户（L2，仅本人可见；M2 才有授权顾问可见）；可删除（法定保留除外，保留期待 D9/法务）。
  - 进度指示用"第 x/n 步"，禁止百分比暗示；必填未完成只给"已完成部分的信息整理"，不出确定性结论。
  - `needs_manual`：结果页显示"建议由顾问人工解读（即将开放）"；M1 不产生顾问任务、不绑定顾问、不产生佣金归因。
  - 匹配不到任何已发布项目：结果页如实说明"当前试点暂无匹配路径"，给教育内容入口，不硬推项目。
- **验收（成功）**：答复满足全部条件 → 四类结果正确归位且每条带来源；**（失败）**缺必填 → 无确定结论；植入违规词的项目内容不可能进入规则集（M1-06 前置）；同一问卷用相同已发布版本重复计算结果幂等。

### M1-09 顾问入驻与审核（S-00 / A03-roster）

- **顾问端流程**：手机号登录（M0）→ 选择所属境内机构（M1-01）→ 提交身份与从业证明（L3，走对象存储/KMS，仅审核岗可见）、人员备案信息（字段由 A12/A03 配置，对应 841 号令备案要求，具体字段【门 D2 合规】）→ 逐条签署入驻承诺（不私收款、不平台外承诺、不夸大/不协助虚假材料、保密，逐条时间戳）→ 完成通识培训阅读确认 → 提交。
- **状态机（GP4 §3）**：`draft 草稿 → submitted 待核验 → correcting 补正中 → approved 有效（待首个项目授权）/ rejected 不予入驻（终态，带申诉入口说明）`；顾问账号后续状态（临期/暂停/调查/离职）在 M3/M4 扩展。
- **后台（A03-roster 最小集）**：申请队列、材料查看（水印、留痕）、通过/驳回（必填原因）、补正要求；顾问自述/简介过词库后才随名片可见。
- **规则**：
  - 审核中/未通过账号：顾问端业务区锁定（项目超市、客户等入口不可用），只可见审核状态与申诉入口。
  - 资质证明不清晰/过期：退回补正并指明材料；机构无效时不可提交。
  - 所有查看与动作写审计；审核岗默认不见与入驻无关的其他 L3。
- **验收**：未通过账号无法进入项目超市（接口级拒绝，非仅 UI 隐藏）；承诺未逐条签署不可提交。

### M1-10 学习必读与项目授权五步（S-02/S-03/S-04/S-10 / A03-learn）

- **五步状态机（GP4 §3 Authorization）**：
  `unstarted 未开始 → reading 必读确认中 → pending 待审核(A03) → granted 已授权（带有效期）→ expiring 临期 / expired 过期自动暂停`；驳回 → 回 reading（带原因）可重申。
- **必读资料**：项目规则（对客可表述口径）、禁表述清单（锁词库版本）、费用说明（对客口径，不含佣金）；每份必须打开并显式确认（记录资料版本与时间）。全部确认后申请按钮才可用。
- **审批**：advisor_admin 审批；授权有效期 = min（申请时长、人员备案有效期、资质有效期），不允许永久授权。
- **规则**：
  - 未授权：项目超市可见公开介绍与"申请授权"，**报价、方案生成、佣金维度接口不下发**（S-02 锁佣锁报价）；S-03 三页签中"内部规则/佣金"本期不开放（M2/M4），M1 只有"对客可表述/禁表述"两部分。
  - 项目规则版本更新发布（M1-05）→ 关联顾问旧确认失效，授权状态转"待重确认"（展业前必须重新确认新版，重确认前该项目不可新报价/新方案）。
  - 临期提醒：到期前 60/30/7 天站内通知（初始参数）；到期定时任务自动转 `expired`，停新；在办交接 M3 补齐，本期到期顾问对在办只读可见。
  - 机构到期/顾问被暂停（M4 完整处置）：本期实现"冻结新授权与新确认"。
- **验收（AT22 子集）**：五步不可跳步（直接调审批接口无前置确认记录被拒）；到期账号在项目超市对该项目无报价入口；版本更新后未重确认前不可展业。

### M1-11 名片白名单与客户端只读名片（A03-card / C07）

- **后台**：维护白名单字段（姓名、头衔、备案编号、从业年限（需核验凭证）、所属机构、授权项目列表）；自述区单独审核（词库 + 人工），通过后带"自述内容，未经平台核验"标识。
- **客户端（M1 只读）**：
  - 名片展示白名单事实 + 自述分区 + 实名/备案状态与有效期 + 授权项目；统计字段（案件数、响应中位数）**本期无数据，显示"样本积累中"，不显示假数字**。
  - 违规记录：有核实结论才展示，无则"无已核实记录"。
  - "预约沟通/请求服务/请顾问解读"按钮 M1 置灰，点击 toast"即将开放"，**不生成关系、不授权资料、不记归属**。
  - 顾问临期/暂停/未入驻通过：名片对新客不展示动作区（本期即不展示名片于可选列表，仅在办关系 M3 后才有"我的顾问"）。
- **验收（AT24 子集）**：名片接口只返回白名单字段；非白名单字段（内部备注、佣金、其他客户）不存在于响应体。

### M1-12 客户端首页游客态（C02 游客部分）

- 内容位全部由后台配置驱动（A09-home 最小集并入 M1-02 后台：Banner、人群分区、精选项目、教育位；M1 只支持 L1 内容位的增改与发布，复用四眼流的简化版：编辑→复核）。
- 高频入口：找项目、初步评估、全球通行（框架态，点入显示维护中说明）、防骗教育（M1 仅静态内容位，教育专区完整版 M4）。
- 规则：无注册墙、无逼单倒计时、无虚假内容位；内容位未配置时降级为稳定功能宫格；下架项目自动从内容位消失（发布态过滤）。
- 办理中态（P-01b）在 M2/M3 随订单案件上线。
- **验收**：游客首屏无任何登录拦截即可进入 P-02/P-03/P-05；内容位全部可在后台改、改后客户端不需发版。

### M1-13 项目发现与详情（C03/C04）

- **列表**：筛选（目的地/人群/身份性质/参考周期区间；费用筛选只按"是否有 tbc/币种"，不做价格排序）、搜索（仅已发布项目与公开内容）、项目卡（名称+版本、身份性质、人群标签、参考周期[非承诺]、费用分项入口、核验日期）。
- **详情**：条件区（每条带来源链接与核验日期，缺项显"待确认"）、费用区（M1-04 全部分项规则）、主体与资质区（境内签约主体名称与备案状态；境外方信息在 D2 落定前显"由境内备案机构统筹持牌交付，详情见合同"占位，**不编造境外机构名**）、周期流程区（非承诺）、自助边界与保障边界、来源与版本、底部双按钮（初步评估可用；联系顾问置灰"即将开放"）。
- **规则**：
  - 只返回 `published` 版本；浏览期间被下架 → 详情转暂停/下架说明页。
  - 无成功率、无佣金排序、无总价、无"最便宜"；从全球通行框架跳入带"短期旅行 ≠ 长期身份"提示。
  - 旧版分享链接打开 → 提示版本已更新并引导当前版。
- **验收（AT01/AT02/AT07/AT08/AT21 透明口径子集）**：游客不留资可见全部核心条件与费用分项；多币种页面无总价；tbc 项逐格可见。

### M1-14 本机收藏与比较（C05）

- 游客：收藏与比较（≤3 项）存本机；登录后提示合并（用户选择，不自动覆盖）；云端收藏随账号。
- 比较维度固定（身份性质/家庭随行/参考周期/费用分项框架/居住要求/自助阶段/主体资质）；缺失值显"待确认"；不评分、不推荐、不产生归属。
- 项目暂停/下架：比较表中标状态、禁止新结论，不静默删除。
- **验收**：超 3 项无法加入；下架项有状态说明；收藏比较不产生任何顾问侧线索（顾问端无浏览者信息）。

### M1-15 初步评估（C06，端上流程）

- 分步问卷（步数进度、草稿、可退出恢复、提交前可改答）；模板版本号常驻；无证件上传；成年随行成员处展示本人授权提示（授权动作在 M3）。
- 结果页：四类结构 + 性质提示 + 保存（登录门）/重测/看项目；游客结果不长期留存。
- 撤回/删除：登录用户可删除已保存问卷（M1 硬删除 + 审计，保留期待 D9 定稿后改为合规保留策略）。
- **验收**：见 M1-08；另验收"游客不登录可走完全流程，中途触发登录被拒后结果仍只在本机"。

### M1-16 全球通行数据源开关框架（A01-ds / C14）

- 后台配置对象 `DataSourceAuthorization`：提供方、授权范围、合同期、更新节拍、署名口径、开关（off/on）、缓存策略；本期只有一个内置"未授权"记录，开关强制 off。
- 客户端：tab 与三页骨架（我的护照/签证查询/护照对比）存在，进入显示"数据服务维护中 + 官方渠道教育"，不展示任何编造天数/类别；开关 on 且有效才放开（M5 接入真实 API）。
- **验收（Q6）**：开关 off 时接口不返回任何签证数据；开关切换写审计；不存在硬编码假数据对客可见。

### M1-17 质量基线看板（A11 子集，只读）

- 指标（口径版本化、只建基线不设目标）：核验覆盖率（已核验关键事实/全部关键事实）、事实临期率、词库命中次数（按生产点/类别）、授权五步平均时长与驳回率、必读确认及时率、初评完成漏斗（开始/完成/needs_manual 占比）、内容发布周期。
- 明确禁止：获批率/成功率、以成交额单一排名、把词库命中做成对顾问的简单负向计数（M4 质检定性后再用）。
- 样本不足显"样本积累中"。

## 5. 状态机落地清单（本期）

| 聚合 | 状态与合法迁移 | 守卫要点 |
| --- | --- | --- |
| ProjectVersion | draft→pending_verification→pending_publish→published；任意前置态驳回→draft；published→suspended→delisted；修订=新版本 draft | 无 verified 事实不得进 pending_publish；published 不可变 |
| VerificationRecord | verified→due→invalid；新建/复核只改记录不改历史 | 核验人≠版本编辑人 |
| FeeScheduleVersion | draft→in_review→published→superseded | 复核人≠编辑人；published 不可变 |
| WordLibrary / AssessmentTemplate / ResultTemplate / RuleSet | draft→in_review→published→superseded(disabled) | 合规复核；发布即生效/失效缓存 |
| AdvisorOnboarding | draft→submitted→correcting→approved/rejected | 机构有效；承诺全签；L3 已传 |
| Authorization | unstarted→reading→pending→granted→expiring→expired；驳回→reading；granted 且规则更新→pending_reconfirm | 五步留痕；有效期≤资质/备案期；未授权锁报价/方案/佣金 |
| Assessment（登录保存） | in_progress→submitted（auto/manual 标记）→deleted | 模板/规则版本固化；仅本人可见 |
| Consultation（仅落记录） | captured（needs_manual 与未来关系请求的落地表，M1 不流转） | M2 接 A04 |

全部迁移在 `packages/core` 以纯函数实现（`canTransition`/`reduce`），后端为唯一裁决；非法迁移返回 409 并写审计。

## 6. 数据与接口契约（要点级，详细 OpenAPI 在详设）

### 6.1 核心表/对象（服务端，字段为最小集）

- `project`、`project_version`（含 JSONB 结构化内容、状态、快照指针）、`verification_record`、`fee_schedule_version`/`fee_item`（amount numeric、currency、collector、certainty、occurrence）、`assessment_template_version`、`result_template_version`、`assessment_rule_set`/`rule_item`、`word_library_version`/`word_item`、`content_slot`（首页内容位+发布态）、`data_source_authorization`。
- `organization`（境内机构最小台账）、`advisor`、`advisor_credential`（L3 文件指针，不入库二进制）、`onboarding_submission`、`required_reading`/`reading_confirmation`、`authorization_request`/`authorization`、`name_card_profile`。
- `assessment`（客户保存）、`favorite`（云收藏）、`consultation_capture`（仅落记录）。
- 事件表：`project_events`、`authorization_events`、`onboarding_events`、`content_publish_events` 等（通用 `<agg>_events` 结构，见技术方案 §3.3）。
- 审计：经统一审计服务写哈希链（M0 提供）。
- 金额约束：`numeric(14,2)` + `currency` 三字符；**无总价列**；tbc 行 amount 为空、certainty='tbc'。
- 多租户：所有表带预留 `tenant_id`（V1 固定默认值），对象级归属列（org/advisor/customer）用于 RLS 与策略。

错误规范：400（校验，回字段级错误与命中词）、401/403（认证/授权，403 写审计）、409（状态冲突/SoD 冲突/乐观锁，回当前状态）、422（业务规则拒绝，回规则码与可读说明）、429（限流）。

## 7. 服务端闸门清单（M1 必须逐条有自动化测试）

1. 项目发布：核验完整性、收费复核、词库零 block、模板/规则有效、SoD（编辑≠核验≠发布闭环同人拒绝）。
2. 事实失效：定时任务阻断关联版本对客查询。
3. 费用：服务端不产出跨币种合计；tbc 不允许数值 0 冒充；published 费表不可变。
4. 顾问：机构无效不可入驻；未通过入驻不可访问任何业务接口；未授权项目报价/方案/佣金字段**不出现在响应体**（不仅是按钮隐藏）。
5. 授权五步：无全部必读确认记录，审批接口拒绝；授权有效期 ≤ 资质/备案有效期；规则版本更新后旧授权转待重确认。
6. 词库：三个生产点写接口服务端强校验；词库发布后缓存主动失效。
7. 初评：未发布模板/规则不对外；游客 preview 不持久化个人明细；结果结构固定四类、无分数字段（接口 schema 中不存在 score/probability）。
8. 名片：响应字段白名单化（DTO 层过滤，非白名单字段不序列化）。
9. 数据源：off 时所有签证数据接口返回维护态；无假数据。
10. 所有拒绝与高敏查看（入驻材料、名片审核）写哈希链审计。

## 8. 异常与边界场景（汇总）

| 场景 | 系统行为 |
| --- | --- |
| 核验来源链接失效/官方政策变动 | 记录置失效 → 版本自动阻断展示 → 看板告警 → 编辑更新出新版 |
| 两运营并发编辑/发布期间编辑 | 乐观锁冲突提示；发布锁快照，改动进新草稿 |
| 顾问入驻材料过期/不清 | 退回补正，指明材料；不通过审核 |
| 顾问机构备案到期 | 冻结新授权/新确认；顾问端显原因；到期提醒三级 |
| 授权审批通过时资质已过期 | 服务端按有效期 min 计算，过期直接拒绝通过 |
| 项目版本发布后发现错误事实 | 暂停（停新签）→ 修新版 → 复核发布；历史版本只读留痕，不物理删除 |
| 游客初评中途断网 | 答案本机保留，可重试；不假成功、不重复提交 |
| 登录客户拒绝授权任何顾问（M1 无此动作） | 问卷默认仅本人可见，M2 授权才放开 |
| 词库误杀正常表达 | warn/block 可由合规复核调整；词条改动走版本；已拦截内容给修改指引 |
| 后台账号越权尝试（如编辑调发布） | 403 + 审计告警；M4 接合规事件 |
| 数据源合同到期未续 | 开关自动 off（定时检查合同期），模块转维护态，不缓存旧数据 |
| 示例数据误入生产 | 发布流水线检查【示例】标记；生产初始化 seed 不含任何示例内容（技术方案 §6） |

## 9. 埋点与质量基线（M1-17 口径）

- 漏斗：项目详情 UV → 开始初评 → 完成初评 → 结果页（游客/登录分别统计）；初评 needs_manual 占比（**仅用于发现规则覆盖缺口，不做顾问考核**）。
- 内容：核验覆盖率、临期/失效事实数、发布周期（草稿→发布时长）、词库命中按生产点/类别。
- 顾问：入驻通过率与补正率、必读确认时长、授权五步时长、驳回原因分布、到期/临期数。
- 全部事件不带 L3；游客事件聚合化、不可识别个人；指标口径在后台版本化。

## 10. 验收用例（Given-When-Then，AT 映射；E2E 自动化）

1. **AT01/AT02 公开可见**：Given 项目已发布且事实齐全，When 游客不登录打开列表与详情，Then 全部核心条件与费用分项可见、无留资墙。
2. **无核验不发布**：Given 版本存在 3 条无核验事实（B 地区反例），When 编辑提交发布，Then 被拒并逐条列缺失；客户端搜索不到该项目。
3. **四眼 SoD**：Given 同一员工完成编辑，When 其调用核验或发布接口，Then 409；审计可查拒绝记录。
4. **费用透明**：Given 费表含 CNY/USD 多币种与一个 tbc 项，When 任一终端渲染，Then 无总价合计、tbc 显式非 0、收取方逐项可见。
5. **AT23 词库**：在项目文本、问卷模板、顾问自述三处植入 block 词，When 提交，Then 三处分别被拒并返回命中位置；词库发布后旧草稿重交按新词库校验。
6. **初评四类**：Given 已发布规则集，When 客户完成问卷，Then 输出严格四类 + 性质提示 + 来源版本；缺必填时无确定结论；响应中不存在 score 字段。
7. **AT22 授权闭环**：Given 顾问未完成必读，When 直接调授权申请/审批接口，Then 拒绝；授权到期后该项目报价入口与字段均不可得；规则版本更新后状态转待重确认。
8. **入驻门**：Given 顾问未通过入驻，When 调用项目超市等业务接口，Then 403（不仅 UI 锁定）。
9. **AT24 名片白名单**：When 拉取名片列表，Then 响应仅含白名单字段与自述审核版；无佣金/备注/其他客户字段。
10. **Q6 数据源**：Given 开关 off，When 客户端请求签证查询，Then 返回维护态且无任何国别数据；切换 on/off 均有审计。
11. **事实失效联动**：Given 已发布项目，When 其核验记录被标记 invalid，Then 定时任务后客户端详情转复核中、列表移除。
12. **游客隐私**：When 游客完成 preview 初评，Then 服务端无其问卷明细持久化（仅聚合日志），重算幂等。

## 11. 发布与上线策略

- **dev/test**：示例数据（【示例】标识）全量功能验证；AT 用例进 CI。
- **shadow 影子环境**：内容运营/核验/合规用真实试点国别资料走完整发布流（不对外）；顾问在顾问端走入驻→授权；初评仅内部试用；校准核验节拍、提醒天数、题组与规则覆盖。
- **邀请制灰度（M1 结束态）**：客户端公开浏览/初评对受邀用户开放（依赖 D1 试点国别与 D2 主体就绪；未就绪则只放防骗教育与公开内容，初评结果页不含具体国别承诺）；后台内容必须 100% 经四眼流。
- 停止/回滚条件：发现未核验内容外泄、词库漏拦造成对客违规表述、授权绕过——立即下架相关版本/回收授权（开关级回滚），修后重走发布。
- 特性开关：项目国别、初评、顾问入驻、数据源各自独立开关，可按灰度名单放量。
