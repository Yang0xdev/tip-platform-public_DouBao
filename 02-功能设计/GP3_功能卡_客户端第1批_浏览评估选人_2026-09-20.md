# G-P3 单页功能卡 · 客户端第 1 批（浏览 → 评估 → 选人）

- 版本：v0.1（2026-09-20）
- 依据：G-P2 页面目录 V0.2 §6 模板；PLATFORM_PRODUCT_V2（下称 V2）§5、§8、§9、§16；高保真原型 prototype-v2（Pass 1–8）
- 范围：C01 账号与登录（P-00）、C02 首页（P-01a/b）、C03 项目发现（P-02）、C04 项目详情（P-03）、C05 收藏与比较（P-04）、C06 初步评估（P-05/P-06）、C07 顾问名片与选择（P-07）
- 本批之后：第 2 批 C08–C13（方案、订单、案件材料、进度消息、服务工单、我的、家庭授权）；第 3 批 C14 全球通行、顾问端 S、iPad I、后台 A
- 写法约定：**只描述功能与规则，不描述视觉**；每条规则尽量给出"触发条件 → 系统行为 → 结果/反馈"。
- 数据分级（全篇统一）：
  - **L1 公开**：已发布项目内容、费用框架、公开签证/护照数据、防骗教育——游客可见，不含个人数据。
  - **L2 客户业务数据**：问卷、方案、订单、案件、材料清单与进度、消息——登录且通过关系/归属校验后可见。
  - **L3 高敏数据**：证件原件/影印件、账户与凭证、家庭授权、跨境共享材料——逐动作授权、逐次审批、水印与审计。
- 全局红线（每张卡都继承，不再逐条重复）：不输出成功率/获批率/百分比式办理进度；费用分项并标注收取方、确定/估算、币种，异币种不相加，"待确认"≠0；公司动作≠官方受理，服务方报告≠官方状态，待核验≠到账；无僵尸动作（每个可点元素必须有真实结果或明确解释）；所有对外事实可追溯来源与时间；示例数据在上线前全部替换。

## C01 账号与登录（P-00）

### 1. 页面编号/名称/所属端
P-00 登录/验证码/账号找回 · 客户服务端（手机 App，Web 适配同规则）。

### 2. 页面目的
让用户在"需要身份"的动作前以最低摩擦完成识别；同时保证浏览、公开工具与防骗教育不需要登录。

### 3. 使用者与角色权限
- 使用者：游客（未登录）、已注册客户、需找回账号的老客户。
- 可见数据：本页不展示任何 L2/L3 业务数据。
- 排除：顾问/服务方/后台人员不走此入口（各自端独立账号体系，互不通用）。

### 4. 入口
- 触发登录的动作（门）：保存需求/问卷草稿到云端、预约或联系顾问、查看方案/订单/案件/材料/消息、收藏跨设备同步、保存护照组合、家庭授权。
- 显式入口：我的（P-17 未登录态）、全局"登录"按钮。
- 不触发登录：浏览 P-01/P-02/P-03、初评（本机临时进行，见 C06）、全球通行 P-19–P-21、防骗教育 P-16。

### 5. 出口（跳转）
- 验证成功：回到触发登录前的目标页（深链回跳），不重置用户原任务。
- 取消：回到来源页，保持游客态。
- 账号找回：进入人工核验流程（见第 6 项），不做纯线上弱验证放行。
- 检测到该手机号已有在办案件但设备陌生：登录后进入二次验证，再回目标页。

### 6. 核心功能与动作清单
1. 手机号 + 验证码登录
   - 触发：输入手机号、请求验证码 → 系统校验号段、频控（同号发送间隔、日上限）→ 发送并展示倒计时；验证通过 → 建立会话。
   - 反馈：验证码错误明确提示剩余尝试次数；超限锁定短时重发并引导人工。
2. 第三方登录（微信/Apple，后续批次）
   - 触发：选择第三方 → 授权 → 系统按绑定规则匹配账号；未匹配则引导绑定手机号，不自动创建空壳业务账号。
3. 敏感动作二次验证（step-up）
   - 触发：查看 L3 材料、家庭授权变更、合同确认、退款申请等 → 要求再次验证码/人脸（后续批次定义强度）→ 通过才放行；本页只定义"需要时能发起"。
4. 账号找回（旧手机号不可用）
   - 触发：提交新手机号 + 身份与归属证据（证件信息、历史订单/案件要素）→ 进入人工核验队列（后台 A10/A12 协同）→ 结果通知；核验期间原会话权限不放大。
5. 游客态本地数据
   - 触发：未登录做初评/收藏/护照组合 → 存本机；登录后提示合并；用户选择不合并则保留本机、不上传。

### 7. 关键字段
| 字段 | 来源 | 必填 | 可见范围 |
| --- | --- | --- | --- |
| 手机号 | 客户填 | 是 | 系统；界面脱敏显示 |
| 验证码 | 系统发 | 是 | 仅本次会话 |
| 第三方 openID | 第三方 | 条件必填 | 系统 |
| 找回证据材料 | 客户提交 | 找回时必填 | 核验岗（A10/A12），L3 |
| 游客本机数据 | 本机生成 | 否 | 仅本机，未授权不上云 |

### 8. 状态与状态变化
- 账号：未登录 → 登录中 → 已登录；已登录 → 会话过期 → 重新验证。
- 验证码：待发送 → 已发送（倒计时）→ 已验证/失效。
- 找回：未提交 → 待核验 → 通过（换绑）/驳回（说明原因与申诉路径）。
- 迁移权限：登录、step-up、找回核准由系统/核验岗执行；任何顾问无权替客户登录或索要验证码。

### 9. 业务规则与硬约束
- 最小化登录：能不登录就不拦（V2"先提供价值"原则）。
- 不做"浏览即留资"：不弹强制注册墙、不诱导填手机号才能看核心条件（P-03 核心条件公开）。
- 验证码与登录凭证绝不出现在客服/顾问对话中；顾问不得代收。
- 账号与案件的归属以实名+关系校验为准，不因知道手机号即可见案件。
- 会话、登录、step-up、找回结论全部写审计（A10）。

### 10. 异常与空状态
- 验证码未达：可重发（倒计时结束后）、可选择语音/其他通道；不假说"已发送成功"，区分"已下发/运营商未达"。
- 网络失败：表单本地保留，可重试，不重复创建账号/订单。
- 手机号命中在办案件但验证失败：只提示"需要进一步核验"，不透露案件是否存在（防枚举）。
- 无账号的新号：明确告知将创建新账号及隐私要点，不用"登录"按钮静默注册。
- 找回证据不足：说明缺什么、如何补，不把用户困在死流程，提供人工渠道。

### 11. 通知/留痕
- 登录、新设备登录、step-up、换绑：向客户发站内/短信安全提醒（T1 业务类）。
- 留痕：登录日志、设备、失败尝试、找回工单；对接 A10 审计、A08 工单。

### 12. 对应验收场景
- 游客全程浏览+使用公开工具不被要求登录（对应 AT01/AT02 的公开可见前提）。
- 敏感动作未做 step-up 被服务端拒绝（对应 AT09/AT20 的服务端校验原则）。
- 找回不弱验证、顾问无法代登录（A10 职责分离）。

### 13. 待确认项（默认处置）
- 第三方登录上线批次（默认：首期手机号验证码，微信/Apple 后置）。
- step-up 的具体强度（验证码/人脸）与合规要求（默认：先验证码，人脸待合规评估）。
- 账号是否允许注销及数据保留期限（默认：提供注销入口，法定保留数据除外，细则待法务确认，关联 D 系列决策）。

## C02 首页（P-01a 游客态 / P-01b 办理中态）

### 1. 页面编号/名称/所属端
P-01a 首页（游客）、P-01b 首页（办理中）· 客户服务端，一级 tab"首页"。

### 2. 页面目的
- 游客：不注册也能立刻看懂"这里能查什么、怎么开始、如何防骗"。
- 办理中客户：一打开就知道**当前状态、下一步动作、责任人与时限**。

### 3. 使用者与角色权限
- 游客：只见 L1（项目入口、公开工具、教育内容、了解路径）。
- 登录无案件客户：增加"我的需求/收藏/待办"，无案件不显示虚构案件数。
- 办理中客户：见本人关系内 L2 摘要；L3 不放首页，只放入口。
- 顾问/后台不可见客户首页排布的个性化全貌（内容由 A09 统一编排）。

### 4. 入口
App 启动默认页；底部 tab"首页"；深链（分享/通知回跳）。

### 5. 出口
- 游客：找项目 P-02、全球通行 P-19、初评 P-05、防骗教育 P-16、顾问名片 P-07、登录 P-00。
- 办理中：案件待办 → P-10/P-12；T0/T1 提醒 → P-13 详情；我的顾问 → P-07 关系态视图；方案待确认 → P-08。

### 6. 核心功能与动作清单
1. 游客态内容位
   - 搜索（全局最小搜索，作用于项目/公开内容，结果只含已发布项）。
   - 主 Banner / 人群分区 / 精选项目：均取自 A09 内容位与 A01 已发布项目；下架项目自动消失。
   - 高频入口：找项目、初步评估、签证查询（全球通行）、防骗教育。
   - "了解路径"科普：身份规划分几步、平台怎么收费、谁来服务（教育而非营销）。
2. 办理中态待办
   - 触发：存在进行中案件/待确认方案/未读 T0 → 首页按"时限等级 + 截止时间"排序，T0 置顶。
   - 每条待办 = 现状一句话 + 下一步动作 + 责任人 + 截止时间（对应 Wise/Monzo"一眼知道下一步"原则）。
3. 我的顾问卡
   - 有主责顾问：姓名（白名单字段）、备案/授权状态、联系入口；无顾问：显示"如何选顾问"与 P-07 入口。
4. 消息提醒摘要
   - 未读 T0/T1 计数与一句话摘要；锁屏/推送不含案号等敏感细节（详见 C11 消息卡，第 2 批）。
5. 内容位点击
   - 所有卡片可点且结果真实：项目卡进 P-03、教育卡进 P-16；无空跳、无"敬请期待"僵尸卡。

### 7. 关键字段
| 字段 | 来源 | 必填 | 可见范围 |
| --- | --- | --- | --- |
| 内容位（Banner/分区/精选） | A09 编排、A12 审核 | 是 | L1 |
| 项目卡（名称/版本/核验状态） | A01 已发布版本 | 是 | L1 |
| 我的待办（动作/责任人/时限） | 案件 Task 系统 | 办理中可见 | L2，本人关系内 |
| 顾问白名单字段 | A03 授权与备案 | 有顾问时 | L1/L2 |
| 未读计数/摘要 | A09 DeliveryRecord | 本人 | L2，摘要脱敏 |

### 8. 状态与状态变化
- 首页形态：游客态 ⇄ 登录无案件态 ⇄ 办理中态，由"是否登录 + 是否有有效关系/案件"驱动，不提供手动伪装。
- 待办：未开始 → 待客户动作（T0/T1）→ 已完成/已过期；过期只显示升级结果，不消失、不改写截止时间。
- 项目暂停/下架：卡片在首页自动移除；已在办客户走历史案件逻辑（P-10），首页给处置说明而非直接消失。

### 9. 业务规则与硬约束
- 空状态真实：没有案件就不显示案件数量、不放假待办（V2 C02"空状态真实，无虚构数量"）。
- 不做虚假倒计时、"限时涨价""今天不定就涨价"类逼单元素；红色仅用于真实 T0/风险，且同时给出动作与帮助入口。
- T0 严肃但不制造恐慌：必须同时呈现"做什么、在哪做、谁能帮我、截止时间从何而来"。
- 首页不出现成功率/获批率、不出现"内部渠道/包过"等禁表述（A12 词库在内容发布时已拦截）。
- 营销内容（T2）与业务待办（T0/T1）视觉与分区分离，营销可退订。

### 10. 异常与空状态
- 新注册无需求：显示"从找项目/做初评/问顾问开始"三个动作，不空白。
- 内容位未配置：降级为稳定的功能入口宫格，不白屏、不显示占位假文案。
- 待办加载失败：保留上次可读缓存并标注"更新时间"，提供重试；不把失败显示成"暂无待办"。
- 顾问备案到期/被暂停：顾问卡显示状态变化与平台接管说明，客户侧不出现"无人负责"（AT22），并引导新顾问安排。

### 11. 通知/留痕
- 首页本身不发通知；待办与消息由 A09 统一生成 DeliveryRecord。
- 内容位发布/下架、客户对待办的点击与完成写事件流，供 A11 建基线（不用于考核转化率造假）。

### 12. 对应验收场景
- 游客首屏无需登录即可进入项目/评估/工具/教育（AT01、AT02 公开性）。
- 办理中首屏 T0 置顶且含现状+下一步+责任人+时限（AT10、AT19 的客户端呈现）。
- 顾问资质异常时客户侧显示接管而非失联（AT22）。
- 空状态无虚构数据（V2 C02）。

### 13. 待确认项（默认处置）
- 首页内容位的初始编排与数量（默认：1 主 Banner + 3 高频入口 + 人群分区 + 1 教育位，影子期再调）。
- 是否做个性化推荐（默认：首期只按"有无案件"和人群标签静态编排，不做行为画像推荐，隐私评估后置）。

## C03 项目发现（P-02）

### 1. 页面编号/名称/所属端
P-02 项目发现列表 · 客户服务端，一级 tab"找项目"。

### 2. 页面目的
让用户按自己的人群/目的地/条件，从**已发布且有有效核验记录**的项目中做初步筛选；暂停/下架项不进入新购目录。

### 3. 使用者与角色权限
- 游客可用（L1）。
- 登录用户额外见"与我的初评/收藏相关"的标记（L2，本地/云端）。
- 未授权顾问、未发布项目、未核验事实一律不出现在列表。

### 4. 入口
首页、底部 tab、全局搜索结果、全球通行"了解长期身份路径"入口（仅当目的地有已发布项目，且明确区分旅行签证 vs 长期身份）、顾问分享链接（S-05 核准素材）。

### 5. 出口
- 项目卡 → P-03 详情。
- 筛选无结果 → 空状态（见第 10 项）与"做初评/看其他项目/找顾问"。
- 从全球通行进入 → 顶部带"短期旅行 ≠ 长期身份"提示后再看项目。

### 6. 核心功能与动作清单
1. 筛选与搜索
   - 维度：目的地（示例 A 国/B 地区/C 国）、人群（技术/雇主/家庭团聚/随行子女/投资/数字游民等）、身份性质（长期居留/续签/团聚等）、参考周期区间、费用币种区间。
   - 触发：选择条件 → 系统仅在已发布版本中过滤 → 实时返回；无匹配给明确原因。
2. 项目卡信息
   - 名称 + 当前发布版本号、身份性质、适用人群标签、参考周期（标注"参考、非承诺"）、费用起算口径（分项入口，不给打包总价）、核验时间。
   - 暂停项目（如示例"A 国雇主担保 暂停"）不出现于新购列表，仅历史案件持有人在 P-10 可见。
3. 收藏
   - 触发：点收藏 → 未登录存本机并提示登录可跨设备；登录后入云端收藏（最多与 P-04 共用，比较上限 3 项）。
4. 初评引导
   - 列表与卡片可发起 P-05；不根据筛选动作自动生成"你符合/通过率"结论。
5. 内容来源标识
   - 列表页事实（条件/费用/周期）必须来自 A01 核验台账；无核验记录的事实项不展示具体数值，显"待确认"。

### 7. 关键字段
| 字段 | 来源 | 必填 | 可见范围 |
| --- | --- | --- | --- |
| 项目 ID/名称/版本 | A01 | 是 | L1 |
| 发布状态/核验记录 | A01/A12 | 是（仅"已发布+已核验"可见） | L1 |
| 人群/身份性质标签 | A01 结构化字段 | 是 | L1 |
| 参考周期 | 官方口径汇编+核验时间 | 否（缺则"待确认"） | L1 |
| 费用框架 | FeeSchedule 已发布版 | 是（分项，不给假总价） | L1 |
| 收藏关系 | 客户/本机 | 否 | 本人 |

### 8. 状态与状态变化
- 项目版本：草稿 → 待复核 → 已发布 → 修订（旧版归档）→ 暂停/下架；列表只显示"已发布"。
- 收藏：未收藏 → 已收藏（本机/云端）→ 取消。
- 筛选：条件变更即时重算；不保留会误导的过期结果（结果带版本与更新时间）。

### 9. 业务规则与硬约束
- 编辑≠发布；无核验记录的事实不得发布、不得在列表出现（V2 A01 规则、AT01/AT02）。
- 不做"成功率/获批率"排序与标签；不按佣金高低排序项目（顾问端也不可见佣金驱动排序）。
- 异币种不折算总价、不做"最便宜"价格排序；费用以分项+收取方呈现。
- 暂停/下架项不进新购目录，但历史客户的合同与材料仍可查（P-10）。
- 从全球通行跳入时必须区分短期旅行签证与长期居留/移民，不把免签便利包装成移民卖点（V2 §7A.3/7A.5）。

### 10. 异常与空状态
- 筛选无结果：说明是"目的地暂无已发布项目"还是"条件过窄"，给出放宽条件/初评/顾问三动作；不推荐未核验项目凑数。
- 数据加载失败：可重试，不显示残缺卡片。
- 项目在用户浏览期间被下架：详情页转"该项目已暂停新签"说明页，已收藏项标注状态并保留历史说明。
- 搜索词命中教育内容：可返回防骗/科普结果，但不伪装成项目。

### 11. 通知/留痕
- 列表浏览本身不产生对外通知；收藏、分享点击写事件（A11 漏斗基线，不对外宣传数字）。
- 项目更新对收藏者可发 T2（须订阅、可退订）；项目暂停对在办客户走 T1 并由 A09 生成说明。

### 12. 对应验收场景
- 未核验/暂停项目无法在列表被游客看到（AT01、AT02）。
- 列表不存在成功率、佣金排序、打包总价（红线②与 V2 C03）。
- 从签证工具跳入有明确的旅行/身份区分（§7A.5）。

### 13. 待确认项（默认处置）
- 首批上线项目数量与人群标签集（默认：随试点 1 国 1–2 类，标签从 A01 受控词表取，不自由填）。
- 是否支持收藏上限提示数值（默认：收藏不限、比较最多 3 项，与 P-04 一致）。

7. 主动作

### 11. 通知/留痕

## C05 收藏与比较（P-04）

### 2. 页面目的
帮助用户把最多 3 个项目按同一组字段并排比较，差异与"待确认"一目了然，支持回到详情或发起评估。

### 3. 使用者与角色权限
- 游客：本机收藏与比较；登录后跨设备（L1 内容 + 本人收藏关系）。
- 只允许比较已发布项目；暂停/下架项在比较表中标状态并禁止新结论。

### 4. 入口
P-02/P-03 的收藏与比较入口、首页"我的收藏"、我的（P-17）。

### 5. 出口
- 项目详情 P-03；对选定项做初评 P-05；找顾问 P-07；返回。
- 比较项全部失效（下架）：引导回列表。

### 6. 核心功能与动作清单
1. 收藏列表
   - 查看/移除；显示每项当前版本与状态；本机项与云端项登录后提示合并。
2. 并排比较
   - 固定比较维度：身份性质、家庭随行、参考周期、费用币种与分项框架、居住要求、可自助到的阶段、第三方费用情况、主体与资质。

3. 差异提示（非推荐）
   - 系统只做事实对照与口径提示（如"异币种不可相加、不做总价排序"），**不输出"选这个更值/更容易过"的推荐或评分**。
4. 发起评估
   - 可携带比较上下文进入 P-05（问卷记录用户关注的项目，供顾问解读，不自动判定资格）。

### 7. 关键字段
同 C04 比较维度字段，另含：收藏时间、来源（本机/云端）、比较快照版本（避免项目更新后比较含义错位）。

### 8. 状态与状态变化
- 收藏项：有效 → 项目更新（提示"有新版本，比较基于 vX"）→ 暂停/下架（标灰、注明）。
- 比较表：1–3 项动态增减；超过 3 项提示先移除。

### 9. 业务规则与硬约束
- 最多 3 项并排（信息密度与可比性）。
- 不做综合打分、不做获批概率、不做价格总价排序（异币种不可比）。
- "待确认"逐格标注且在详情可查来源；不把估算当确定值比较。
- 比较与收藏不产生顾问归属、不产生佣金归因；仅当用户主动发起联系/初评才进入主线。

### 10. 异常与空状态
- 无收藏：空状态教如何收藏 + 热门/人群入口（不虚构个人偏好）。
- 仅 1 项：提示再加项目才能比较，单项时显示"查看详情/去评估"。
- 某项下架：表格中标注并说明，允许替换；不静默删除导致用户困惑。
- 合并冲突（本机与云端同名不同版本）：让用户选择保留，不自动覆盖。

### 11. 通知/留痕
- 项目更新对收藏者按订阅发 T2；比较行为写事件用于 A11 理解决策路径（不考核顾问）。

### 12. 对应验收场景
- 比较表无总价相加、无评分/成功率；缺失项显"待确认"（红线②、AT21 口径）。
- 下架项有状态说明、不产生误导（AT22 项目侧）。

### 13. 待确认项（默认处置）
- 比较维度是否允许用户自定义（默认：首期固定维度集，自定义后置）。

## C06 初步评估（P-05 问卷 / P-06 结果）

### 1. 页面编号/名称/所属端
P-05 初步评估-问卷、P-06 初步评估-结果 · 客户服务端；游客可本机完成。

### 2. 页面目的
用**经合规审核的固定问卷版本**采集需求，输出"符合 / 差距 / 待确认 / 来源时间"四类信息整理，帮助客户理解差距与下一步；**不是资格认定、不输出概率**。

### 3. 使用者与角色权限
- 游客可做（数据本机；保存/跨设备/请顾问解读需登录）。
- 问卷模板与结论模板只有 A12 审核通过版本可用；顾问个人不可改题、不可改判定逻辑。
- 超模板的个案判断必须由有权角色人工署名（见第 8/9 项）。

### 4. 入口
P-02/P-03/P-04 双 CTA、首页、iPad 面谈（I-01 同源问卷，演示模式同样受限）、顾问分享链接。

### 5. 出口
- 完成 → P-06 结果；结果 → 保存（登录）、请顾问解读（P-07）、重看项目。
- 中途退出 → 存草稿（本机/云端）；撤回 → 删除/按隐私规则处理。
- 问卷触发登录动作而用户拒绝 → 结果仅本机保留。

### 6. 核心功能与动作清单（P-05）
1. 分步问卷
   - 固定题组：目的地/项目意向、家庭构成（含成年随行成员授权提示）、基本条件（年龄/学历/语言/职业，自填，不要证件）、预算区间（可选）、时间偏好。
   - 进度指示表达"完成步数"，**绝不使用百分比暗示通过率**。
2. 草稿/退出/撤回
   - 随时存草稿、退出；提交前可改答；用户可撤回并删除本机/云端问卷（法定保留除外）。
3. 无需上传证件
   - 本阶段明确不收证件原件/影印件（L3 留到签约后材料中心 P-12）。
4. 模板版本控制
   - 顶部显示问卷模板版本（如 v3.2，已合规审核）；换版后旧草稿提示按新版补答。
5. 结果生成（P-06）
   - 触发：问卷完成到必填阈值 → 系统按已核验项目条件做规则比对 → 输出四类固定结构：
     - 已知符合项（引用项目条件版本与核验时间）；
     - 明显差距项（差距是什么、可能的补法方向，不承诺可弥补）；
     - 待确认项（需官方/持牌方核实的点）；
     - 信息来源与时间。
   - 固定性质提示：信息整理与差距提示，不是资格认定、不构成法律意见、不代表获批结果，个案以官方审核为准。
6. 人工署名
   - 任何超出模板规则的判断（边缘个案、特殊家庭结构）不自动出结论，转"顾问/合规人工解读"并署名；自动结果不含人名背书的个性化承诺。
7. 请顾问解读
   - 触发：选择顾问 → 生成解读请求；客户明确授权后顾问才可见问卷内容（分享/来源不等于授权）。

### 7. 关键字段
| 字段 | 来源 | 必填 | 可见范围 |
| --- | --- | --- | --- |
| 问卷答复 | 客户填 | 必填题完成才出结果 | 本机/本人；授权后指定顾问 |
| 问卷/结论模板版本 | A12 审核库 | 是 | L1 规则 |
| 比对用项目条件 | A01 已核验版本 | 是 | L1 |
| 四类结论 | 系统规则生成 | 是 | 本人 |
| 人工解读与署名 | 顾问/合规 | 条件 | 客户+有权角色，留痕 |

### 8. 状态与状态变化
- 问卷：未开始 → 草稿 → 已完成 → 结果已生成；可撤回（标记删除/限制处理）。
- 结论：规则自动结论（模板内）→ 人工解读（超模板）；模板升版后旧结论标注"基于 vX，仅供参考"。
- 授权：问卷默认仅本人可见 → 客户指定授权某顾问 → 可撤回（撤回后顾问端不可再访问，历史留痕保留）。

### 9. 业务规则与硬约束
- 未完成必填不给"确定结论"，可给"已完成部分的信息整理"并明确不完整（V2 C06、AT23）。
- 不输出成功率/获批率/打分/排名式结论；不使用"包过/保过/内部渠道"等词（A12 禁表述，模板与输入两端校验）。
- 问卷与结论必须用审核版本；超模板判断必须人工署名（AT23）。
- 不采集与本阶段无关的敏感信息；不要证件、不要账户信息。
- 初评不绑定顾问、不产生佣金；点击/咨询/方案确认都不产生可提现佣金（红线⑦）。
- iPad 演示模式下不得展示其他客户问卷（I-01 规则）。

### 10. 异常与空状态
- 中途退出：草稿可恢复，不清空；明确草稿保存位置（本机/云端）。
- 条件无法匹配任何已发布项目：结果页说明"当前试点无匹配路径"，给出教育内容/留联系方式由顾问人工跟进（不硬推不匹配项目）。
- 项目条件更新导致结论变化：重新生成并标注差异与时间，不篡改历史结论。
- 提交失败：答案本地保留、可重试，不假成功。
- 撤回授权：顾问端即时不可见，进行中的解读任务终止并说明。

### 11. 通知/留痕
- 结果生成、顾问解读请求、授权与撤回写事件与审计（A10）。
- 顾问解读请求对顾问发 T1 任务通知；客户侧在 P-13 可见处理状态。
- 模板版本、结论生成时间、引用条件版本随记录保存（可追溯，AT23）。

### 12. 对应验收场景
- 问卷与结论无保证性表述、模板有审核版本、超模板有人工署名（AT23）。
- 未完成问卷不出现确定结论（V2 C06）。
- 初评不产生佣金、不自动绑定顾问（红线⑦、D7）。
- 不收证件、家庭成年成员需本人授权的提示存在（隐私最小化、AT20 前置提示）。

### 13. 待确认项（默认处置）
- 问卷题目终稿与必填集（默认：以原型 v3.2 题组为基线，A12 评审后冻结）。
- 自动规则比对覆盖的项目数（默认：仅试点 1 国 1–2 类项目启用自动比对，其余转人工）。
- 问卷数据保留期限（默认：未转订单的问卷客户可删，平台默认保留期待 D 系列/法务定）。

## C07 顾问公开名片与选择（P-07）

### 1. 页面编号/名称/所属端
P-07 顾问公开名片 · 客户服务端；同一组件在"选择顾问/我的顾问/分享落地页"按关系状态呈现不同动作。

### 2. 页面目的
用**白名单内、经核验的事实字段**帮客户判断"选谁服务我"，并把"自述营销内容"与"平台核验事实"清楚分开；服务关系经双向确认才成立。

### 3. 使用者与角色权限
- 游客可见 L1 白名单字段；预约/请求服务需登录。
- 仅展示状态正常（备案有效、授权有效）的顾问可被新客选择；到期/暂停顾问的名片对新客不可发起，对在办客户显示接管安排。
- 顾问不可见谁浏览了自己名片（除非客户主动发起）；不展示客户联系方式给顾问直到关系成立。

### 4. 入口
P-03/P-06"联系/请顾问解读"、首页我的顾问卡、全部服务 P-14、顾问合规分享链接（S-05）、换顾问流程（P-17/工单，第 2 批定义）。

### 5. 出口
- 预约沟通 / 请求 TA 服务我 → 生成关系请求（待顾问接受）→ 我的顾问状态页/首页。
- 返回项目/结果页；登录门 P-00（未登录时）。

### 6. 核心功能与动作清单
1. 核验事实区（白名单字段）
   - 姓名/工号头像、所属境内备案机构、实名核验状态、人员备案状态与有效期、授权服务项目（绑定资质有效期）、从业年限（证明已核验）、平台已完成案件数、近 90 天首次响应中位数、已核实违规记录（有则如实、无则"无已核实记录"）。
2. 顾问自述区
   - 自我介绍/擅长方向，显著标注"自述内容，未经平台核验"；经 A12 敏感词与禁表述审核后才可见。
3. 服务关系动作
   - 预约沟通：生成预约请求（T1），顾问接受前显示"待接受"，不成立服务关系、不授权资料。
   - 请求 TA 服务我：客户发起 → 顾问接受 → 关系成立（D7 双向确认）；一名客户一名主责顾问。
   - 已成立关系：显示"我的顾问"、联系入口、工单/换顾问入口。
4. 异常状态呈现
   - 授权到期/备案临期：新客不可发起，显状态；暂停/调查中：名片不可新选，并对在办客户显示平台接管与交接（AT22）。
5. 分享落地
   - 从顾问分享链接进入：只记录推荐来源，不自动授权资料、不自动成立关系（红线 D7/⑨）。

### 7. 关键字段
| 字段 | 来源 | 必填 | 可见范围 |
| --- | --- | --- | --- |
| 姓名/机构/实名备案状态 | A03 备案台账 | 是 | L1 |
| 授权项目与有效期 | A03 Authorization+Credential | 是 | L1 |
| 从业年限/案件数/响应中位数 | 平台核验统计（带统计口径与时间窗） | 是 | L1 |
| 已核实违规记录 | A12/A08 结论 | 有则必填 | L1 |
| 自述内容 | 顾问提交、A12 审核 | 否 | L1，明确标识 |
| 关系状态 | 关系服务（D7） | 本人/该顾问可见 | L2 |

### 8. 状态与状态变化
- 顾问可选择性：可被选择 → 授权临期（提示）→ 暂停/到期（新客不可选，在办交接）。
- 服务关系：无关系 → 客户已发起（待接受）→ 顾问已接受（成立，一名主责）→ 换顾问中（五步交接，第 2 批卡）→ 已结束（历史可查）。
- 迁移权限：关系成立需双方动作；平台可在资质异常时强制交接但不抹去记录；顾问不能自行把客户转给他人。

### 9. 业务规则与硬约束
- 名片只出现白名单核验字段（AT24）；无获批率/成功率、无"内部渠道"、无客户隐私案例。
- 自述与核验分区、自述显式标识（AT24）。
- 双向确认才成立关系；分享来源≠归属、≠资料授权（D7、红线⑨）。
- 一名客户一名主责顾问，不做多级分佣/团队归属链对客可见。
- 资质/备案到期自动停新接旧，客户侧不失联（AT22）。
- 统计指标用客户可理解口径（如"近 90 天首次响应中位数"），不展示会诱导动作变形的单一成交额排名。

### 10. 异常与空状态
- 该项目暂无在线可接受顾问：显示"提交需求由平台分配/到岗通知"，并说明分配规则与可更换，不强塞。
- 顾问超时不接受：请求可撤回/改选/转平台分配，状态透明，不假装"已为你服务"。
- 顾问被暂停：在办客户首页与名片显示交接人与进度；新客不可见可发起按钮（而非可点后失败）。
- 分享链接过期（素材过期停分享）：落地页提示内容已更新，引导正规入口，不加载过期承诺。

### 11. 通知/留痕
- 关系请求/接受/拒绝/交接：T1 通知双方，写关系台账（来源、关系、佣金归因三分离，第 2 批/后台卡细化）。
- 顾问状态变化对在办客户发 T1 + 接管说明（A09/A03 联动）。
- 名片字段变更、自述审核留痕（A03/A12）。

### 12. 对应验收场景
- 名片仅白名单字段、无成功率、自述有标识、过期素材无法分享（AT24）。
- 关系经客户发起+顾问接受才成立，分享不自动授权（D7、红线⑨）。
- 顾问资质异常时新客不能选、在办不失联（AT22）。

### 13. 待确认项（默认处置）
- 响应中位数等统计的最小样本与展示门槛（默认：样本不足显"样本积累中"，不显示不可靠数字）。
- 平台分配规则与客户可否指定更换（默认：可分配、可无理由申请更换一次，交接规则第 2 批冻结）。

## 本批小结与跨页一致性检查

- **游客动线闭环**：P-01a → P-02 → P-03 →（P-04）→ P-05 → P-06 → P-07 全程无需登录即可获得真实价值；登录只发生在"保存/被服务"动作前。
- **事实单一来源**：项目条件/费用/主体/资质全部读 A01/A02/A03 已核验数据，客户端不自行维护事实；前台展示与后台台账版本一致。
- **不承诺原则贯穿**：初评四类结论、详情无概率、比较无评分、名片无成功率、周期均为参考。
- **钱与主体的前置铺垫**：详情页费用分项与主体展示为第 2 批 P-09 下单"主体三要素校验"建立客户认知；本批不产生任何订单与佣金。
- **给 UI/UX 阶段的输入（仅功能原则，不画视觉）**：一页一主动作；每个状态=现状+下一步+责任人/时限；说人话、术语首次出现给解释；不滥用红色、无逼单倒计时；每页都有真人/帮助出口；空状态是行动邀请。
