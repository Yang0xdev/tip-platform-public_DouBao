# G-P3 单页功能卡 · 客户端第 2 批（方案 → 订单 → 办理 → 消息 → 保障 → 我的/家庭）

- 版本：v0.1（2026-09-21）
- 依据：G-P2 §6 模板；V2 §5.3–5.10、§8、§9；原型 prototype-v2（Pass 1–8，客户端 29 屏）
- 范围：C08 我的方案（P-08）、C09 合同订单与费用（P-09/09a/09b）、C10 案件与材料（P-10/P-12/P-12a）、C11 进度与消息（P-11/P-13/P-13a）、C12 服务目录与工单（P-14/P-15/15a/15b）、C13 我的与家庭授权（P-17/P-18）
- 约定同第 1 批：只写功能与规则、不写视觉；数据分级 L1/L2/L3；继承全局红线（无成功率、费用分项收取方、四级来源、主体三要素、T0 只升级不改期、授权服务端逐项校验、佣金六态、投诉独立受理）。
- 本批是平台信任机制最密集的一段：客户在这里确认钱、合同、材料、进度并获得保障，任何"看起来完成但实际没核验"的表达都是事故。

## C08 我的方案（P-08）

### 1. 页面编号/名称/所属端
P-08 我的方案 · 客户服务端（"我的办理"域）。

### 2. 页面目的
让客户阅读、比对并**版本化确认**顾问编制的个性化方案：建议、费用分项与收取方、责任范围；确认动作只表示"了解并认可本版本方案"，不等于签署合同。

### 3. 使用者与角色权限
- 仅登录且存在方案的客户本人（L2）；经授权的成年家庭成员按授权动作可见（见 C13）。
- 顾问可编制/修订（S-07/iPad I-02），但方案须经后台报价复核（A05）客户才看得到"可确认"版本。
- 顾问不可自行改价、不可在方案中承诺结果；服务方/第三方看不到客户方案全文。

### 4. 入口
P-06 结果后顾问发送、P-07 关系成立后、首页待办"方案待确认"、消息中心 T1 通知、我的（P-17）、iPad 面谈共读（I-02 同源）。

### 5. 出口
- 确认本版本 → 生成订单草稿 → 主体校验门 → P-09。
- 请求修改 → 生成修改请求工单/任务回顾问（旧版保留，出新版）。
- 拒绝/暂不确认 → 停留，不自动下单、不失效客户数据；超时给提醒但不制造倒计时焦虑。

### 6. 核心功能与动作清单
1. 版本头
   - 方案编号、版本号（如 v3）、编制顾问、报价复核状态、有效期；明确旧版只读、不可误确认。
2. 个性化建议
   - 针对问卷/个案的路径建议、先做什么后做什么（如先补配偶语言成绩）；每条建议可追溯到项目条件版本或人工署名。
3. 费用与收取方（与 P-03 同口径，个案化）
   - 分项列平台服务费、境内服务费、境外专业服务费、官方/第三方费；逐项标收取方、确定/估算、币种、发生时点；异币种分列不合计；待确认项显式保留。
4. 责任范围
   - 顾问协助什么、平台核验什么、境外持牌方/自营交付部做什么、哪些是政府权力（平台不代判断结果）。
5. 版本化确认
   - 触发：客户点"确认本版本" → 系统校验该版本已过 A05 报价复核且在有效期 → 记录确认人、时间、版本快照 → 生成订单草稿。
   - 金额/项目/申请人/责任范围任一被修改 → 旧确认失效，必须重新确认新版本（V2 §5.3）。
6. 修改请求
   - 触发：客户填写修改点 → 生成任务给顾问（T1）→ 顾问出新版走同样复核；过程在方案内可见。
7. 共读与解释
   - iPad I-02 面谈共读内容与此页一致；客户事后可在 App 回看当时版本与确认记录。

### 7. 关键字段
| 字段 | 来源 | 必填 | 可见范围 |
| --- | --- | --- | --- |
| 方案编号/版本/有效期 | 系统 | 是 | L2 本人+授权成员+有权角色 |
| 个性化建议 | 顾问编制、规则/署名 | 是 | 同上 |
| 费用分项快照 | FeeSchedule + A05 复核 | 是 | L2 |
| 责任边界文本 | A12 审核模板 | 是 | L2 |
| 确认记录（人/时间/版本） | 系统 | 确认后 | L2 + 审计 |
| 修改请求与回复 | 客户/顾问 | 有则 | 关系内 + A08 |

### 8. 状态与状态变化
- 方案：草稿（顾问侧）→ 待复核 → 待客户确认 → 已确认（转订单草稿）→ 已修订（旧版归档）→ 失效（项目暂停/超期）。
- 确认：未确认 → 已确认某版本 → 内容变更后确认失效 → 待确认新版。
- 迁移权限：顾问编制、A05 复核、客户确认；任何一方不能代替另一方；系统不允许确认未复核版本。

### 9. 业务规则与硬约束
- "确认了解方案"不是签署、不是付款（V2 §5.4）。
- 无成功率/包过/内部渠道；建议中不得出现精确概率（AT23 同源约束）。
- 费用红线同 P-03：分项+收取方+币种+确定性，异币种不相加，待确认≠0（AT21/AT07/AT08）。
- 改价/改范围必须新版本+重新确认，旧版只读留痕，不覆盖。
- 方案引用的项目条件必须是已发布核验版本；项目暂停时方案转"失效说明"，不诱导继续付款。
- 顾问不可在方案外私聊报价或承诺（D5/红线⑩），客户侧提供"顾问私下说法与方案不一致"的投诉入口。

### 10. 异常与空状态
- 无方案：显示"完成初评并选择顾问后获取方案"，不放假方案。
- 复核未通过：客户侧只看到"方案更新中"，不展示未复核内容；顾问侧给退回原因。
- 有效期过期：显式提示需顾问刷新版本，确认按钮不可用并说明原因（不是点击后才失败）。
- 项目暂停：方案页置顶暂停说明与已发生费用/可选路径，链接 A08 工单。

### 11. 通知/留痕
- 方案发送、待确认、确认、修改请求、版本失效：T1 站内+邮件，生成 DeliveryRecord。
- 确认快照（版本、费用、责任文本、时间）随订单永久留痕，供争议时对照（A05/A10）。

### 12. 对应验收场景
- 改价后旧确认失效、必须重新确认新版本（V2 §5.3）。
- 费用分项与收取方完整、异币种不相加（AT21/AT07/AT08）。
- 未复核/已过期版本无法被确认（A05 门）。
- iPad 共读与客户 App 内容一致（I-02 规则）。

### 13. 待确认项（默认处置）
- 方案有效期具体天数（默认 14 天，FeeSchedule/合同定稿前可配）。
- 修改请求是否限次（默认：不限次，但每次留痕；反复修改可转人工沟通）。

## C09 合同订单与费用（P-09 订单 / P-09a 订单详情 / P-09b 退款调整）

### 1. 页面编号/名称/所属端
P-09 合同订单与费用、P-09a 订单详情（付款计划/收据/签署与告知登记）、P-09b 退款/订单调整 · 客户服务端（"我的办理"域）。

### 2. 页面目的
让客户在付款前后始终看清：**和谁签约、把钱付给谁、钱到没到、合同签了没、服务到哪一步、出问题怎么退**；三态（合同/到账/服务）分离，互不冒充。

### 3. 使用者与角色权限
- 签约客户本人（L2；资金凭证、合同扫描件按 L3 管理）。
- 授权成年成员仅在授权动作内可见；顾问只读订单状态、不可见账户明细、不可改金额/到账。
- 财务只见付款核验与收据字段，默认不见证件原件（职责分离）。

### 4. 入口
P-08 确认后进入；首页待办（付款/补凭证）、消息 T0/T1、我的（P-17）、工单退款流转。

### 5. 出口
- 主体校验通过 + 签署登记 + 首付款核验 → 建立案件 → P-10。
- 校验失败：订单不可生成，转说明与人工（顾问端 S-08a 同源阻断）。
- 退款/调整：P-09b 提交 → 工单（P-15b）→ A08/A07/A05。

### 6. 核心功能与动作清单
**P-09 订单总览**
1. 三态头
   - 合同状态（待签/已签署登记）、到账状态（待核验/已核验到账）、服务状态（未开始/材料准备/…），三色分区、独立时间，禁止用一个"处理中"概括。
2. 收费主体卡（下单前校验结果对客可见）
   - 签约/收费主体＝境内备案主体；境外交付方＝已关联持牌方或自营交付部；收款账户户名＝签约主体；备案/持牌状态。三要素一致才出现付款指引。
3. 付款凭证上传
   - 触发：上传转账凭证 → 状态"待核验" → 财务双人/银行核验 → "已核验到账"并开收据；重复凭证被拦截，不假成功。
4. 付款指引
   - 仅展示签约主体对公账户/合规支付通道；任何非主体账户在系统内不存在可复制入口；附"请勿向个人账户转账"防骗提示（链接 P-16）。
5. 入口聚合
   - 付款计划与收据/签署登记 → P-09a；合同全文（带水印扫描件）；退款/调整 → P-09b。

**P-09a 订单详情**
6. 付款计划
   - 分期表：期次、金额/币种、到期条件、状态；官方/第三方费按实际代收代付、未发生显"未发生"；异币种不相加。
7. 合同签署与告知登记
   - 线下/外部签署受控登记：签署时间、核验人（≠顾问本人）、合同版本；告知确认清单（费用分项已逐项确认、不承诺获批结果告知、个人信息与跨境共享授权）逐条带时间戳。
8. 收据与变更记录
   - 每期到账后开收据（编号、PDF 水印）；订单变更（分期数、金额、申请人）只生成新版本记录，旧记录留存。

**P-09b 退款 / 订单调整**
9. 申请类型
   - 退款 / 分期·方案变更 / 费用争议；关联订单；说明 + 凭证；提交即生成独立工单（P-15b），客户可查进度。
10. 规则前置告知
   - 已代收代付官方费、已发生第三方费按实际扣除；境外专业费按已完成工作量结算；具体以合同条款为准；**不出现"不成功全额退款"承诺**；顾问无权承诺退款比例/时限；金额类双人复核（A07/A05）。

### 7. 关键字段
| 字段 | 来源 | 必填 | 可见范围 |
| --- | --- | --- | --- |
| 订单号、方案版本快照 | 系统 | 是 | L2 |
| 主体三要素（签约/境外交付/收款户名） | A02/A05 | 是 | L2 |
| 付款凭证 | 客户上传（L3） | 每期必填 | 客户+财务（脱敏） |
| 到账核验结果/核验人 | 财务/银行 | 系统生成 | L2 + 审计 |
| 合同签署登记/告知确认 | 线下签署+核验岗 | 生效必填 | L2/L3 |
| 收据编号/PDF | 财务 | 到账后 | L2 |
| 退款/调整申请与结论 | 客户/A08/A07 | 有则 | 客户+独立处理人 |

### 8. 状态与状态变化
- 订单：订单草稿 → 主体校验（通过/阻断）→ 待签署 → 已签署登记 → 待首付 → 到账核验中 → 生效（建案件）→ 履约中 → 结案；支线：变更中、退款/调整（冻结相关结算）、取消。
- 到账：待付款 → 凭证待核验 → 已核验到账（开收据）/ 凭证驳回（可重传，留痕）。
- 退款：已申请 → 独立受理 → 双人复核 → 退款方案确认 → 执行（财务）→ 关闭；同步佣金调整/追回（A07，客户侧只见结果不见佣金细节）。
- 迁移权限：系统校验主体；核验岗登记签署；财务核验到账；A05/A07 双人处理金额变更；顾问在本流程无审批权。

### 9. 业务规则与硬约束
- **主体三要素不一致不能生成订单，且没有任何"强制通过"入口**（红线④、AT21）；顾问端阻断见 S-08a，客户侧同样不得付款。
- 收费主体/收款账户未配置不可下单（AT21）。
- 合同必须包含：服务范围与边界、退款规则、境外段服务方告知、平台保障范围与平台外交易边界、隐私与跨境告知（V2 §5.4）。
- "确认了解方案"≠签署；平台不做资金托管，款项不进平台账户（以最终资金路径 D 系列决策为准，文案待法务定稿）。
- 待核验≠到账；公司动作≠官方受理；重复凭证拦截重复记账。
- 官方结果≠服务失败，退款争议以合同服务范围与凭据记录为准（V2 §5.10）。
- 未登记平台订单不享受合同核验、凭据存档、材料托管、退款受理（D5，客观告知不恐吓）。

### 10. 异常与空状态
- 主体校验失败：停止付款引导，显示差异项与"转复核/联系合规"，不提供绕过路径。
- 凭证驳回：说明原因（户名不符/金额不符/图像不清），允许重传，原凭证与轨迹保留。
- 线下签署尚未登记：订单显"等待平台核验签署"，不提前开放付款承诺。
- 退款无对应订单（平台外交易）：明确不适用平台保障，引导其他合法途径，不假装受理后沉默。
- 支付通道维护/失败：保留订单与已填信息，可稍后重试，不重复扣款。

### 11. 通知/留痕
- T0：付款截止、官方截止；T1：签署待登记、到账核验结果、收据开具、退款结论；均生成 DeliveryRecord 多通道送达。
- 所有金额、主体、凭证、签署、退款动作进审计（A10）与财务台账（A07）；客户在订单详情可见同源记录。

### 12. 对应验收场景
- 主体未配置/不一致时无法生成订单、无强制通过入口（AT21、S-08a）。
- 每个费用项可见收取方，缺失项显"待确认"而非 0（AT21）。
- 凭证上传只显"待核验"，核验后才到账、开收据（V2 §5.4）。
- 退款走独立工单+双人复核，顾问无权承诺（V2 §5.10、A08 回避）。
- 合同五要素与告知确认完整可查（V2 §5.4）。

### 13. 待确认项（默认处置）
- 资金路径（对公收款/支付通道/是否托管）属 D 系列阻塞决策；原型与功能卡只表达"签约主体账户、核验后到账"，最终以法务/支付方案为准。
- 退款比例与节点表（默认：合同模板预置分阶段比例，法务定稿前不在对客页面写具体百分比）。

## C10 我的案件与材料中心（P-10 / P-12 / P-12a）

### 1. 页面编号/名称/所属端
P-10 我的案件列表、P-12 材料中心、P-12a 授权拦截态 · 客户服务端（"我的办理"tab）。

### 2. 页面目的
让客户（及获授权家庭成员）按"申请人 × 案件"组织、提交、追踪材料，清楚每件材料的状态、退回原因与下一步；并在越权时得到明确、有帮助的拒绝。

### 3. 使用者与角色权限
- 主申请人本人：本案件全部本人材料与清单（L2；证件影像 L3）。
- 配偶/成年成员：仅本人材料，且需本人授权（人员×案件×动作×有效期）。
- 监护人：可操作未成年子女材料，须登记监护证据；不得代成年成员操作。
- 顾问：协同可见清单状态，原件访问需额外批次授权；服务方门户仅见批次授权范围（A06/A10）。

### 4. 入口
首页待办、"我的办理"tab、P-09 生效后、T0 补件通知（P-13a 直达材料）、家庭授权页。

### 5. 出口
- 上传/补交 → 材料审核流 → 通过/退回（带原因）→ 案件进度 P-11。
- 缺授权 → P-12a → P-18 发授权邀请。
- 材料齐备 → 递交段由服务方/办理侧推进（客户在 P-11 看经核验节点）。

### 6. 核心功能与动作清单
**P-10 案件列表**
1. 进行中案件卡
   - 项目、家庭成员、主责顾问、阶段步骤条（合同生效/材料准备/递交受理/审理结果——阶段指引，**不是百分比**）、待办数与 T0 截止。
2. 历史/暂停案件
   - 项目暂停新签后，历史合同与材料仍可查看，附暂停说明与处置进度，不隐藏。
3. 空状态
   - 无案件时只有"了解项目/联系顾问"两个动作，不显示虚构数量。

**P-12 材料中心**
4. 申请人切换
   - 按主申/配偶/子女分栏；未授权成员的分栏不展示其材料内容，只显示授权状态与邀请入口。
5. 材料清单与状态
   - 每件材料：待提交 / 已提交待审核 / 需补充（带办理人填写的退回原因）/ 已通过；T0 项标截止时间与来源任务。
6. 上传/补交
   - 选择材料类型 → 上传（图片/PDF）→ 进度与成功/失败明确反馈；失败可重试、不留"假成功"；提交后进入审核，不可自行替换已审核文件（新版本另存，轨迹保留）。
7. 退回闭环
   - 退回必须含原因、要求、截止时间；客户补交后退回单关闭；全过程在 P-11 时间线可见。
8. 授权提示与锁定项
   - 他人材料行显示锁定状态，点击进入 P-12a。

**P-12a 授权拦截态**
9. 服务端拒绝说明
   - 明示"服务端已拒绝访问（人员×案件×动作×有效期校验未通过），不是故障或暂时隐藏"；本次拒绝已写审计。
10. 获得访问路径
   - 一键向该成员发本人授权邀请（→P-18）；说明成年成员不能代签；返回材料中心。

### 7. 关键字段
| 字段 | 来源 | 必填 | 可见范围 |
| --- | --- | --- | --- |
| 案件/申请人/家庭成员关系 | 订单+实名 | 是 | L2 关系内 |
| 材料清单项与模板 | A06 按项目版本生成 | 是 | L2 |
| 材料文件（影像） | 客户/成员上传（L3） | 按清单 | 授权范围内；原件另审批 |
| 审核状态/退回原因/审核人 | 办理员 | 系统 | L2 |
| T0 截止与任务来源 | Task 系统 | 时限项必填 | L2 |
| 授权记录 | Consent 系统 | 跨人操作必填 | L2 + A10 |

### 8. 状态与状态变化
- 材料：待提交 → 已提交待审核 → 已通过 / 需补充（→ 重新提交，版本留存）；作废材料显式标记不删除。
- 访问授权：无授权（服务端拒绝）→ 邀请已发 → 本人授权（限时）→ 可访问 → 到期/撤回（即时关闭）。
- 案件：履约阶段见 P-11；暂停/拒绝/失联/争议独立记录，不并入"处理中"（V2 §5.5）。
- 迁移权限：客户/授权成员提交；办理员审核；核验岗核验凭据；服务方按批次只读；谁都不能越权改状态。

### 9. 业务规则与硬约束
- 监护授权拦截（AT20）：无有效监护证据不能为子女提交；成年成员默认代签被拦截；全部留痕。
- 越权由服务端拒绝（不是仅隐藏入口），并写审计（AT09/AT20、红线⑫）。
- 不假成功：上传失败/处理中状态明确；客户看到的"已通过"必须有公司审核记录。
- 无凭据不展示伪精确进度（V2 §5.5）；材料进度不是官方审理进度。
- 证件原件查看/下载走 A06/A10 特殊审批、水印、限期；客户本人原件也记录访问。
- T0 补件截止时间来自官方/合同要求，**任何升级都不改写原截止时间**（红线⑤）。

### 10. 异常与空状态
- 上传失败：保留本地选择、显示原因（网络/格式/大小）、可重试，不重复提交。
- 清单未生成（合同未生效）：说明"合同与首付核验后开放材料清单"，不放空清单。
- 成员未注册/未接受邀请：显示"邀请待接受"，提供提醒与线下授权书受控登记路径（成年成员确无法本人操作时，上传原件+核验人+有效期）。
- 监护争议（离异/收养/身故）：转人工合规处理，系统不自动判定（V2 §5.9）。
- 项目暂停：材料中心只读+说明，新提交引导至工单。

### 11. 通知/留痕
- T0：补件要求、官方截止、授权到期（App+短信+邮件，同步顾问）；T1：审核结果、退回、成员授权动态。
- 所有提交、审核、退回、越权拒绝、授权变更写事件流与审计；P-11 同源展示。

### 12. 对应验收场景
- 无监护授权为子女提交被拦截、成年成员被默认代签被拦截且留痕（AT20）。
- 越权访问在服务端被拒（含直链/历史入口），有审计（AT09/AT20、P-12a）。
- 上传失败可重试且无假成功（V2 C10）。
- 退回有原因/要求/时限并可追踪（V2 §5.5）。

### 13. 待确认项（默认处置）
- 支持的文件类型/大小/留存期（默认：JPG/PDF、单文件 20MB、留存期随案件档案合规要求，待法务定）。
- 线下授权书受控登记的核验 SLA（默认：1–2 工作日，影子期校准）。

## C11 进度详情与消息中心（P-11 / P-13 / P-13a）

### 1. 页面编号/名称/所属端
P-11 进度详情、P-13 消息中心、P-13a 消息详情（送达回执）· 客户服务端。

### 2. 页面目的
让客户看到**带来源、带凭据、可核验**的真实进度，以及每条关键通知"发了没、到没到、没到平台做了什么"；彻底消灭"后台显示已通知、客户什么都没收到"。

### 3. 使用者与角色权限
- 客户本人与授权成员（L2，按授权动作）。
- 顾问/办理员可见协同视图但不可改官方进度、不可删消息；服务方报告进入前客户不可见为"进度"。
- 通知模板与通道由 A09 统一治理，任何个人不可私发 T0 类通知。

### 4. 入口

### 5. 出口
- 进度节点 → 凭据查看（水印）/ 待办动作（材料、付款）/ 工单求助。
- 消息 → P-13a 详情 → 去完成动作或联系平台。
- 通知偏好 → P-17 设置；通道失效 → 工单/人工通道说明。

### 6. 核心功能与动作清单
**P-11 进度详情**
1. 四级来源时间线
   - 每条事件标注来源：客户提交（蓝）/ 公司审核（紫）/ 服务方报告（琥珀，注明"未经官方核验"）/ 已核验官方凭据（绿，含核验人）。
2. 节点凭据
   - 官方节点（受理、补件要求、结果等）必须有经核验凭据才可发布为绿色节点；可查看水印凭据原件。
3. 补件与异常独立段
   - 缺什么、谁补、截止、逾期处理独立成段；拒绝/暂停/失联/争议各自独立记录，不合并为"处理中"。
4. 阶段提示
   - 参考周期与"非百分比、非官方承诺"常驻说明；公司动作（已递交、待受理）与官方状态（已受理）措辞严格区分。

**P-13 消息中心**
5. 分组
   - 全部 / 时限 T0 / 业务 T1 / 内容 T2；T2 可一键退订，业务消息不受营销退订影响。
6. 列表字段
   - 标题（锁屏摘要不含案号/项目细节）、通道与送达简述、状态标签（未处理/待确认/已读/T2）。

**P-13a 消息详情**

8. 通道与送达回执

9. 升级记录（T0）

10. 动作 CTA

11. 通知偏好
   - 维护手机号/邮箱/通道偏好与免打扰（T0 不允许完全关闭，仅改通道）；联系方式有效性义务以合同告知。

### 7. 关键字段
| 字段 | 来源 | 必填 | 可见范围 |
| --- | --- | --- | --- |
| 进度事件/来源级别 | 客户/公司/服务方/核验岗 | 是 | L2 |
| 官方凭据与核验人 | 官方凭据+核验岗 | 官方节点必填 | L2（原件 L3 水印） |
| 消息模板版本 | A09/A12 | 是 | L2 |
| DeliveryRecord（通道状态/时间） | 通道回执 | T0/T1 必填 | L2 本人+A09 |

| 通道偏好 | 客户 | 是 | 本人 |

### 8. 状态与状态变化
- 事件：服务方报告（线索）→ 公司核验中 → 已核验发布 / 核验不通过（不发布为官方节点，转说明）。
- 通知送达：待发送 → 已发送 → 已送达 → 已读；失败 → 换通道 → 人工 → 升级（V2 状态机）。
- T0 任务：未读 → 已读/已处理；超时 → 升级（截止时间不变）。
- 迁移权限：核验岗发布官方节点；A09 管模板；系统执行换道/升级；顾问不可改、不可删。

### 9. 业务规则与硬约束
- T0 多通道（App+短信+邮件，签约时采集并验证），同步主责顾问；未读/未达按时限升级，电话跟进记录结果（V2 §5.8、AT19）。
- 锁屏/推送摘要不显示案号等敏感详情。
- 服务方报告≠官方状态、公司动作≠官方受理、待核验≠完成（红线③）。
- 超期只升级、绝不改写原截止时间（红线⑤）。
- 业务与营销分离：T2 单独同意+可退订，绝不与 T0/T1 混发。
- 客户侧与后台看到同一份送达事实（V2 A09"客户侧可见"）。

### 10. 异常与空状态
- 全部通道未达：显示"平台将人工联系/已升级"，提供工单与备用联系方式更新入口，不静默。
- 无消息：空状态说明各分组含义，不造消息。
- 凭据图像加载失败：可重试/转人工，不把节点降级为"无凭据绿色"。
- 客户改手机号：走验证更新；旧号送达失败记录保留。
- 人工电话家属代接：如实记录"家属代接、本人未确认理解"，继续升级直到触达本人（CASE-A02 口径）。

### 11. 通知/留痕
- 本域即通知中枢；所有 DeliveryRecord、换道、电话结果、升级回写案件与 A09 看板；客户可在工单中追溯（A08）。

### 12. 对应验收场景
- T0 多通道发出并有送达回执，未读按时升级且有跟进记录，锁屏无敏感内容（AT19）。
- 官方节点必须有核验凭据；服务方报告不以官方状态出现（V2 §5.5、AT11/AT25）。
- 后台与客户送达状态一致（V2 A09）。
- 超期不改截止时间（红线⑤）。

### 13. 待确认项（默认处置）
- 各 T0 类型的未读升级时限（默认：App 2h 未读转短信、当日未达转人工、T0 剩余 ≤4h 直升级主管；A09 可配，影子期校准）。
- 消息留存期（默认：随案件档案；T2 营销消息按退订即时停止）。

## C12 全部服务与工单投诉（P-14 / P-15 / P-15a / P-15b）

### 1. 页面编号/名称/所属端
P-14 全部服务目录、P-15 服务与反馈（工单列表）、P-15a 新建工单/投诉、P-15b 工单详情/受理闭环 · 客户服务端（"服务"tab）。

把所有服务动作按业务阶段聚合到一个可找、可用的目录；让任何预约、疑问、变更、投诉都形成**有编号、有责任人、有状态、有结果**的工单，且投诉独立于被投诉顾问受理。

### 3. 使用者与角色权限
- 游客：可见公开类服务入口（找项目/评估/签证查询/防骗/找顾问），提交类动作需登录。

- 变更类 → 转 A05/A06 重新确认；投诉类 → A08 独立调查/A12；预约类 → 顾问/客服日程。

**P-14 服务目录**
1. 左分类右宫格
   - 了解评估 / 签约费用 / 办理材料 / 进度结果 / 变更投诉 / 家庭授权；逐项标注是否需登录、是否需顾问/服务方，不用灰色死按钮。
**P-15 工单列表**
2. 新建入口
   - 固定卡"预约/疑问/资料变更/投诉"→ P-15a。
3. 工单列表
   - 单号、类型、标题、处理人/部门、状态（已受理/处理中/待补充/已关闭/合规处理中）；每条可点进 P-15b。
**P-15a 新建**
4. 类型与关联
   - 类型 chips（预约咨询/疑问/资料变更/投诉）；关联订单/案件（可选）；描述；附件上传（图片/PDF）。
5. 投诉独立受理告知
   - 选择/进入投诉时显著告知：投诉进入客服/合规独立队列，被投诉顾问不可见、不能处理或关闭；私收款/误导承诺自动转合规。

   - 补充信息（通知受理人）、撤回（填原因，已受理记录保留）、关闭后评价、不认可可申请复核。

   - 调查期间被投诉顾问暂停新业务的状态、最终处置与补救向客户反馈；不以"和解"代替合规记录。
11. 变更类约束
   - 涉合同/费用/申请人变更不"提交即生效"，显示"需重新确认/登记"，流转 A05/A06 并回写。

| 字段 | 来源 | 必填 | 可见范围 |

| 工单号/类型/关联对象 | 系统/客户 | 是 | L2 |
| 描述/附件 | 客户 | 描述必填 | 客户+处理队列（投诉隔离） |
| 受理部门/处理人 | A08 分派 | 是 | L2（投诉对被投诉人隐藏） |
| 状态时间线/处理说明 | 客服/合规/办理 | 是 | L2 |
| 评价/复核请求 | 客户 | 关闭后 | A08/A11 |

### 8. 状态与状态变化
- 工单：草稿 → 已提交 → 已受理 → 处理中（可多次待补充）→ 已解决待确认 → 已关闭/已评价；支线：复核中、转合规事件、已撤回。
- 投诉：独立路径，增加"合规调查中/处置中"；被投诉人状态联动 A03（停新接旧/交接）。
- 迁移权限：系统分派（不由顾问挑单）；客服/合规处理；客户可补充/撤回/评价/申请复核；顾问仅处理协同项。

### 9. 业务规则与硬约束
- 投诉不经被投诉顾问、不被其关闭；调查人与被调查人分离（回避原则、AT26、红线⑩）。
- 涉私收款、误导承诺自动标记合规事件进入 D5 处置（V2 §5.10、AT26）。
- 私收款核实：冻结顾问新增授权，已发生合规佣金不连坐清零（红线⑦）。
- 争议分类：服务未交付 / 交付质量 / 官方结果（拒绝/补件）/ 平台外交易；官方结果≠服务失败（V2 §5.10）。
- 金额类（退款/调整）双人复核；顾问离职/被暂停不影响受理，自动改派（#TK-0917 口径）。
- 不用"处理中"吞掉异常；每个状态有责任人和下一步。

### 10. 异常与空状态
- 无工单：空状态给"常见问题/提交新工单/防骗指引"。
- 提交失败：内容暂存可重试，不生成假单号。
- 长时间无人响应：系统升级（与 T0 升级同源），客户可见升级状态。
- 平台外交易投诉：明示平台保障边界，同时提供合规举报与合法途径建议，不一推了之。

### 11. 通知/留痕
- 受理、分派、待补充、结果、复核：T1 多节点通知；投诉关键节点短信/站内双通道。
- 工单全量记录进 A08，合规联动进 A12/A03/A07；关闭后独立回访（非顾问执行）进 A11 基线。

### 12. 对应验收场景
- 私收款/平台外承诺投诉被独立受理、触发合规与授权处置，保障边界可向客户出示（AT26）。
- 顾问看不到投诉正文、不能关闭（A08 回避）。
- 变更不"提交即生效"，有重新确认留痕（V2 C12）。
- 顾问异常时工单不中断受理（AT22 服务侧）。

### 13. 待确认项（默认处置）
- 首次响应与各类型 SLA（默认：咨询 1 工作日、投诉 1 工作日受理 + 调查时限按合规制度；合同定稿前为示例值）。
- 是否开放公开 FAQ/知识库（默认：首期建最小 FAQ，与 P-16 教育内容同源审核）。

## C13 我的与家庭授权（P-17 / P-18）

### 1. 页面编号/名称/所属端
P-17 我的（个人中心）、P-18 家庭授权与安全 · 客户服务端。

### 2. 页面目的
- P-17：账号资料、我的业务入口聚合、通知偏好、资料访问记录——让用户对"我的数据谁能看"有总控。
- P-18：以"人员 × 案件 × 动作 × 有效期"管理家庭成员授权与未成年监护，可查、可撤、可追溯。

### 3. 使用者与角色权限
- 客户本人（L2/L3 总控入口）；家庭成员仅见被授权内容。
- 授权必须由成年成员本人完成；监护人代理仅限未成年子女且需监护证据。
- 顾问/服务方不参与授权授予，只在授权结果内获得访问；授权校验在服务端（A10）。

### 4. 入口
底部 tab"我的"；材料锁定 P-12a、跨成员操作拦截、订单/案件成员选择、消息偏好。

### 5. 出口
- 各业务入口（顾问/方案/订单/案件/收藏）；家庭授权管理 P-18；通知设置；访问记录；账号安全/注销（C01 体系）。

### 6. 核心功能与动作清单
**P-17 我的**
1. 身份卡
   - 实名状态、主申请人标识、账号安全入口（step-up）。
2. 业务入口
   - 我的办理、我的顾问、我的方案、合同订单与费用、收藏比较。
3. 安全与授权入口
   - 家庭授权与安全、服务记录与投诉（P-15）、通知设置、资料访问记录（谁在何时看过什么）。
4. 教育位
   - 防骗/核验收费主体入口（P-16）。
5. 通知设置
   - 通道与联系方式维护、T2 订阅退订；T0 仅可改通道不可关闭。

**P-18 家庭授权**
6. 成员与授权列表
   - 每位成员：关系、授权范围（人员×案件×动作×有效期）、状态（有效/监护代理/无授权/已撤回/已过期）。
7. 邀请成年成员授权
   - 短信/邮件邀请 → 成员本人注册/登录并逐项确认动作与有效期 → 生效；可续期、可撤回。
8. 未成年子女
   - 由法定监护人操作，登记监护关系证据（出生证明/户籍/监护文书）；监护争议转人工。
9. 成年成员例外
   - 确无法本人操作：线下授权书受控登记（上传原件、核验人、有效期），不接受默认代签。
10. 撤回与访问记录
   - 逐项撤回、即时生效（门户/顾问端访问随即关闭）；访问记录按人/案件/动作/时间可查；法定必需的已履约记录保留并说明。

### 7. 关键字段
| 字段 | 来源 | 必填 | 可见范围 |
| --- | --- | --- | --- |
| 实名/账号状态 | C01 账号体系 | 是 | 本人 |
| 成员关系/监护证据 | 客户提交+核验 | 跨人操作必填 | L2/L3 |
| 授权维度（人×案件×动作×期限） | 本人授权 | 是 | 关系内 + A10 |
| 访问记录 | A10 审计 | 系统生成 | 本人 |
| 通知偏好 | 客户 | 是 | 本人+A09 |

### 8. 状态与状态变化
- 授权：未邀请 → 待本人确认 → 有效 →（续期）/ 已撤回 / 已过期；监护：证据待登记 → 已核验（监护代理）→ 争议冻结（人工）。
- 撤回：即时关闭新访问；进行中任务按最小必要处理（如配偶材料审核中则完成当次、不扩展新范围）。
- 迁移权限：本人授权本人；监护人代理未成年人；核验岗核证据；系统服务端执行；无人可代成年成员签。

### 9. 业务规则与硬约束
- 账号≠申请人；同家庭不默认互可见（V2 §5.9）。
- 成年成员本人授权、监护人不得代成年成员确认合同；代办全程留痕（AT20、红线⑫）。
- 授权服务端逐项校验，不靠隐藏入口；撤回实时生效（AT09/AT20）。
- 撤回授权不承诺一键清除依法保留的履约记录（V2 §5.7），但停止新访问并向客户说明保留依据。
- 访问记录对客户透明（与 A10 审计同源），是信任而不是后台机密。

### 10. 异常与空状态
- 无家庭成员：空状态说明为何要授权、如何添加，不默认建成员。
- 邀请未接受：可重发、可改联系方式；不到 N 天不自动生效。
- 监护证据不足：列明缺什么、如何补；争议情形直接转人工合规，不做系统判定。
- 成员无账号/无法使用 App：走线下授权书登记路径并说明核验时长。

### 11. 通知/留痕
- 邀请、授权、续期、撤回、证据核验：T1 通知相关成员与主申；全部进 Consent 台账与 A10 审计。
- 异常访问（越权尝试）在访问记录中对客户可见摘要，并触发平台侧告警。

### 12. 对应验收场景
- 成年成员被默认代签拦截、监护无证据拦截（AT20）。
- 撤回后门户/顾问端立即不可访问（AT25 联动、V2 §5.9）。
- 客户可查看访问记录（V2 C13、A10 透明）。
- T0 通知不可被完全关闭（V2 §5.8）。

### 13. 待确认项（默认处置）
- 授权动作粒度清单（默认：查看进度/查看与提交本人材料/确认事项/接收通知四类，开发前在对象模型中冻结）。
- 监护证据的具体清单随法域/项目核验清单（A06 维护，试点国确定后补齐）。

## 本批小结：钱、案、信、权四条主线的一致性

- **钱（C08/C09）**：方案确认≠签署；主体三要素不过不下单；待核验≠到账；收据、合同告知、退款规则全程可查；顾问不碰钱与承诺。
- **案（C10/C11）**：材料按人按授权组织、退回有因、越权服务端拒绝；进度只认真凭据，四级来源措辞不混淆；T0 必达、未达必升级、截止不改写。
- **信（C11/C12）**：通知有送达回执、工单有编号有责任人；投诉独立受理、顾问被隔离；状态不允许用"处理中"吞掉。
- **权（C13）**：家庭授权四维度、本人授权本人、撤回即时生效、访问记录对客户透明。
- 所有客户端状态与后台 A05/A06/A07/A08/A09/A10/A12 一一对应，第 3 批后台功能卡将把这些控制点逐页落到岗位职责与界面动作。
