# 透明化身份规划与申请服务平台
# 第二版系统产品逻辑说明与功能设计方案（重规划版）

版本：V2.0 讨论稿｜日期：2026-09-19｜阶段：产品定义重规划，尚未进入页面定稿与开发

适用产品：客户服务端、顾问展业端；统一业务后台支撑两个终端。

本文中的"应、必须、提供"均为目标需求，不代表现有公测系统已经实现。本文不是移民资格判断、法律意见或各地监管结论。涉及主体资质、备案、持牌边界、签约收费、广告宣传与数据跨境的内容，须由执业律师及相关主管渠道逐项核验后才能开放真实业务。

## 0. 重规划说明：V2 相对 V1 改了什么

### 0.1 重规划起因

V1.0 讨论稿（2026-09-18）的机制设计（业务对象、状态机、权限模型、验收场景）经评审认为已基本成立，但存在三类缺口：

1. **商业地基空缺**：签约/收费主体、首批真实供给、平台盈利模式未定稿，订单、合同、佣金模型缺少地基；
2. **运营与合规厚度不足**：平台的核心产品其实是"核验与责任体系"，V1 只建了系统机制，没有定义核验节拍、角色编制与合规路径；
3. **双边激励未回答**：透明化削弱顾问传统的信息差租金，独立顾问为何入驻、如何防止平台外成交，没有设计。

V2 的核心调整是：**在功能规格之前插入 G-P0（商业与合规地基）决策门；把 V1 如实定位为"受控透明服务平台（准直营）"，开放双边市场后置为 V1.5/V2 的验证项；并补齐核验运营、通知触达、数据跨境、家庭授权、顾问选择信号等缺口设计。**

### 0.2 V1→V2 关键变更一览

| 决策/模块 | V1.0 | V2.0 | 理由 |
| --- | --- | --- | --- |
| 阶段顺序 | G-P1 直接确认业务规则 | 新增 **G-P0 商业与合规地基决策门**，关门后才进入功能规格 | 主体、供给、收费不定，字段设计会返工 |
| 平台定位 | 受控平台，但表述接近双边市场 | 明确 V1 为**受控透明服务平台（准直营）**；独立顾问开放市场为 V1.5/V2 假设 | 受控期先验证信任与交付，再谈网络效应 |
| 试点范围 | 未收敛 | **1 个国家/地区、1 类身份路径、邀请制客户、受控顾问池** | 把合规与核验工作面降到最小 |
| 合规输入 | 一般性提示 | 纳入 **841 号令备案制度（2026-09-15 施行）**、目的地国持牌制度示例，形成核验清单 | 监管已有新规，且直接决定主体与交付结构 |
| 盈利模式 | 未写 | 新增 D4：**明示平台服务费 + 服务方 B2B 技术/结算服务费（披露）**，不隐藏差价 | 透明定位要求收入结构可解释 |
| 顾问激励 | 仅机制 | 新增 D5：受控顾问池、价值主张、平台外成交的边界控制 | 回答"顾问为何来、为何不走私下" |
| 核验运营 | 有"复核到期提醒" | 新增**复核节拍、核验角色、资质到期自动暂停、单案件运营工时度量** | 核验是护城河也是成本中心 |
| 初评 | 输出差距/待确认 | 增补**问卷与输出模板的法务审核、禁止性表述清单、人工责任人** | 初评可能被认定为持牌移民建议 |
| 通知 | 站内消息 | 增补**三级通知、多通道触达、送达回执、未读升级** | 补件等时限错过即可能拒签 |
| 家庭授权 | 未成年人"另设计" | 增补 **V1 最小可用规则**（监护授权、成年成员本人授权） | 家庭移民是主场景，不能整体后置 |
| 顾问选择依据 | "审核事实与自述分开" | 增补**可展示的核验字段集与禁用信号（成功率等）** | 客户主动选择需要可信依据 |
| 数据跨境 | §13 列为门槛 | 增补**数据分级、单独同意、受控服务方门户（水印/不下载原件）、法定路径核验** | 证件材料出境属高敏合规项 |
| 开发切片 | A–D | 新增 **A0 供给与核验底座**（后台先行） | 没有核验底座，对客透明无数据支撑 |
| 验收场景 | AT01–AT18 | 沿用并新增 **AT19–AT26** | 覆盖新机制 |
| 客户端信息架构 | 5 个一级入口、13 张功能卡 | 维持 5 入口；C12/C13 收编入"我的"，补搜索与通知设置 | 导航收敛，功能不减少 |

### 0.3 V2 明确保留 V1 的内容（不重造）

- 三条不可妥协原则（V1 §1.3）与 15 个业务对象的基本划分；
- 推荐来源 / 服务关系 / 佣金归因三对象分离、客户选择＋顾问接受双向确认；
- 项目版本快照、订单规则快照、佣金六态、案件官方节点与内部动作分离；
- 对象级权限、服务端校验、敏感下载审批、双人复核要求；
- 三种服务方式（自助 / 顾问协助 / 专业委托）及其交付边界；
- V1 明确不做的事项（资金托管、自动递交、获批概率评分、多级分佣等），本版不改变其结论，仅调整资金托管的再评估时点（见 D8）；
- AT01–AT18 全部验收场景。

## 1. 产品定位（修正版）

### 1.1 定位

一个以**可信项目资料**为基础、以**客户知情选择**为起点、以**可追踪交付**为核心的身份规划与申请服务平台。平台不以隐藏项目条件和费用为价值，而以信息核验、需求理解、服务匹配、过程组织、交付监督和异常处理提供价值。

### 1.2 V1 的实质：受控透明服务平台（准直营）

V1 不是开放的移民服务自由市场，而是：

- **供给受控**：项目逐个审核发布；服务方由后台维护并签署协议；顾问以平台雇佣顾问和签约（挂靠）顾问为主，经备案、培训与授权后执业；
- **交付受控**：每笔订单有明确境内签约/收费主体、主责顾问、办理责任方；
- **表达受控**：对客可见的项目内容、费用、初评结论、宣传素材均经审核留版本；
- **平台对客户承担可识别的责任**：投诉有独立受理、进度有凭据、资金有核验主体。

"打破行业壁垒"在 V1 的含义是**打破客户侧的信息与信任壁垒**；"打破独立顾问的渠道壁垒"属于双边市场命题，依赖供给密度、信任品牌与监管结构，列为 V1.5/V2 的验证假设，不在 V1 承诺。

### 1.3 三阶段演进与进入条件

| 阶段 | 形态 | 进入条件（全部满足才进入下一阶段） |
| --- | --- | --- |
| **V1（本期）** | 受控透明服务平台：1 国 1 类项目、受控顾问池、邀请制客户、线下签约收款受控登记 | G-P0 决策门关闭；A0–D 切片验收通过；影子运行无阻断问题 |
| **V1.5（有限开放）** | 扩国家/项目族；有限引入经审核的独立顾问；评估第三方支付/资金托管；APP/小程序按批次发布 | V1 试点指标达基线且无重大信任/合规事故；独立顾问履约数据经过一个完整结算周期；资金与支付合规结论明确 |
| **V2（平台化假设）** | 独立顾问与服务方有序开放、平台化匹配与结算 | 供给侧留存、平台外成交率、单位核验成本三项数据证明市场模型成立；监管路径明确 |

演进阶段是规划假设，不是已批准的商业承诺；每阶段均可收缩回上一形态。

### 1.4 原则（V1 三条 + 新增一条）

1. 不把预估写成保证：初评不等于资格确认，参考周期不等于承诺获批时间；
2. 不把后台动作写成官方动作：材料已审核不等于已递交，已递交不等于官方受理；
3. 不把信息透明理解为隐私公开：费用与服务规则可解释，个人资料按目的和授权可见；
4. **（新增）每一项对客承诺必须配对一个可执行的控制动作和责任角色**——找不到责任人或核验动作的承诺，不得出现在页面对客文案中。

### 1.5 V1 试点范围

- 地域与项目：**1 个国家/地区、1 类身份路径**（由 D1 评估选定），试点期内不横向扩国；
- 客户：邀请制，从已有真实需求线索中选择；
- 顾问：覆盖试点业务量的最小团队，雇佣/签约身份明确；
- 终端：移动网页与 iPad 先行；原生 APP、小程序发布批次另行确定；
- 服务方式：自助仅覆盖"了解与材料准备"；顾问协助与专业委托仅开放经审核可交付的项目。

## 2. 商业与合规地基（G-P0 决策门）

### 2.1 为什么 P0 在功能规格之前

订单（Order）、合同（Contract）、佣金（Ledger）、服务方（ServiceProvider）四类对象的字段与状态，直接依赖"谁签约、谁收款、谁交付、谁担责、平台靠什么收费"。这些问题不关闭，C08/C09、S08/S09、A05/A07 的字段细化必然返工。P0 以决策门形式管理：**每项决策有责任人、交付物和关门标准；未关门的模块不得进入 G-P2 字段冻结。**

### 2.2 决策清单

#### D1 试点国家/地区与项目族

- **决定**：选哪一个国家/地区、哪一类身份路径作为首个试点。
- **选择标准（建议权重，评分表另附）**：
  1. 现有客户线索中需求频次高；
  2. 已有可核验、可签约、可实际交付的服务方与成功履约证据；
  3. 监管路径相对清晰：目的地国对境外客户/中国中介协作的限制可识别；
  4. 流程文件化程度高（透明工具能产生明显价值）；
  5. 费用与币种结构简单，付款路径可执行；
  6. 官方信息有稳定公开来源，可持续复核。
- **建议**：由负责人、业务、合规（外部律师）在两周内按评分表选定，得分相近时优先选供给已落实者。
- **不决定时的默认处置**：不启动 G-P2；A0 切片中不依赖国别事实的账号/权限/通用框架可先行，但项目库不得对客发布。

#### D2 主体结构与牌照/备案边界（最高优先级）

- **决定**：平台运营、对客签约、收款、境外段交付分别由什么主体承担；各主体需要什么备案、资质或持牌合作。
- **已核实的公开监管事实（2026-09-19 检索，须由执业律师核验适用性）**：
  - **中国侧**：因私出入境中介机构资格认定已于 2018-11-10 取消（国发〔2018〕35 号，公安部同步废止《因私出入境中介活动管理办法》）；但《国务院关于出境入境管理的规定》（国务院令第 841 号，2026-07-22 公布、**2026-09-15 施行**）建立了新的**中介服务机构备案管理制度**：
    - 接受委托从事出境入境政策咨询、证件代办、手续办理等中介服务的机构，应自设立之日起 **15 日内**向所在地移民管理机构备案；服务人员由所在机构办理备案；本规定施行前已从业的机构应自施行之日起 **90 日内**补办；
    - 机构应具备有相关专业知识的工作人员、相适应的场地和资金保障等条件；
    - **境外企业、机构不得在中国境内提供出境入境中介服务**；在境内依法设立的外资和港澳台资企业、机构可依法从事；
    - 禁止发布虚假信息、夸大/误导性宣传招徕客户，禁止提供或协助提供虚假材料、协助违规办理证件手续；
    - 中介机构不得泄露、出售、非法提供个人隐私和个人信息。
    - 不以营利为目的的政策咨询、查询不属于该规定所称中介服务。
  - **目的地侧（示例）**：
    - 加拿大：有偿提供移民/入籍咨询或代理者必须获授权（CICC 持牌的 RCIC/RISIA、省律师协会律师或公证人等）；IRCC 不接受无照顾问提交的申请；
    - 澳大利亚：仅 OMARA 注册移民代理（持 MARN 注册号）、法律执业者或豁免人士可合法提供移民协助；2026-04-01 起新规进一步加强注册与持续教育要求。
- **产品含义（产品判断，不是法律结论）**：
  1. 平台运营主体、对客签约主体及其顾问人员可能落入备案范围；既有业务主体存在 90 日补办窗口的合规时限；
  2. "境外服务方直接服务境内客户"的模式存在禁止性风险，V1 交付结构应设计为**境内备案主体对客签约、境外持牌主体在境外完成境外段专业工作的 B2B 协作链条**，合同如何签署需律师设计；
  3. 顾问在平台上的所有对客表达落入宣传规制，**核准素材库与话术审核（S05/A12）成为合规硬需求**；
  4. 初评、方案建议的"建议边界"需逐国确认（什么构成"移民协助/法律建议"）。
- **P0 交付物**：外部律师出具的《主体与合规适用意见》，覆盖备案义务、合同链条、持牌边界、宣传边界、人员备案；《备案责任与台账模板》。
- **不决定时的默认处置**：保持现状不签约新单；系统内不开放任何项目的"专业委托"下单。

#### D3 首批真实供给

- **决定**：试点项目的对客内容来源、境外段服务方、境内交付团队、费用证据与历史履约证据。
- **准入要件（每项留证据）**：服务方主体证明与资质/持牌状态；可交付范围与不可承诺事项；书面合作协议；标准费用与币种；官方信息来源；过往履约证明（内部核验，不直接对外宣传）；备选服务方或中断预案。
- **规则**：桌面"项目资料"文件夹只算候选来源；要件不齐的项目不得进入发布流程。
- **不决定时的默认处置**：A0 可建空框架，但试点不启动。

#### D4 盈利模式与费用结构

- **决定**：平台靠什么收费、佣金从哪里来。
- **建议方案（产品决定建议，需商业与法务确认）**：
  1. 对客费用沿用 V1 四分项（服务费、官方费用、第三方费用、可能的后续费用），其中**服务费必须拆明收取方**（平台 / 顾问所属机构 / 境外服务方）；
  2. 平台收入 = **明示的"平台服务费"分项** + 向服务方收取的 **B2B 技术/结算服务费**（在服务方协议与客户合同中披露）；不以隐藏差价、竞价排名、广告位作为 V1 收入；
  3. 顾问佣金来自平台服务费的分配，下单时锁定规则版本（沿用 V1 §5.6）；点击、咨询、方案确认不产生可提现佣金；
  4. V1 不向顾问收入驻费/订阅费（避免受控期供给阻力）。
- **理由**：收入结构可解释是"透明平台"定位的自洽要求；明示分项的转化率代价，用费用理解正确率与信任指标验证。
- **不决定时的默认处置**：费用模板保留"平台服务费"字段但不配置数值；无规则不产生任何应计佣金（沿用 V1）。

#### D5 顾问模式、激励与平台外成交边界

- **V1 顾问池**：雇佣顾问 + 签约（挂靠）顾问，完成身份审核、人员备案（如适用）、培训认证与项目授权后执业；不开放自由入驻。
- **顾问价值主张（受控期）**：经核验的项目内容与费用模板降低讲解成本与口误风险；iPad 面谈与方案工具；合规分享素材；佣金规则透明、对账有凭据；获得经审核的项目供给与客户分配。
- **平台外成交（跳单）的处理原则**：
  - 不监控私人通讯、不要求排他、不限制客户正当选择权；
  - 在入驻/服务协议中明确：禁止顾问私收客户款项、禁止以平台名义作平台外承诺、平台授权项目内的成交须登记；
  - 价值钩子在客户侧：**只有平台登记订单享受合同与主体核验、进度凭据存档、材料受控托管、投诉与退款受理**；页面与合同明示未登记订单不享受平台保障；
  - 服务方侧：境外段排期与结算只对平台登记案件开放；
  - 监测信号：登记咨询后长期无下文但服务方侧出现同客户案件、客户投诉"顾问让我转私人账户"等；处置按授权暂停规则执行，已发生佣金按原规则处理。
- **不决定时的默认处置**：顾问端仅对内部雇佣顾问开放。

#### D6 各项目可开放的自助范围

- 沿用 V1 建议：逐项目标注"可自助到哪一步、是否需要专业服务方、下一步转向平台协助还是外部官方渠道"；无已核实递交渠道的项目，界面不得出现"直接提交申请"。
- 默认处置：未标注的项目仅开放浏览与准备清单。

#### D7 客户归属与佣金归因

- 沿用 V1：推荐来源、服务关系、佣金归因分别记录；客户明确选择/同意＋顾问接受才成立服务关系；冲突后台人工复核；同一咨询/订单一名主责；V1 不做多级分佣。

#### D8 收款方式与信任补强

- V1 继续**线下转账凭证上传 + 财务核验**（不做平台资金托管、不做即时全币种支付，沿用 V1 §2.3）；
- 信任补强（新增为硬规则）：
  1. 收费主体与收款账户未配置且不一致的项目，系统不允许生成订单；
  2. 合同载明收款主体、账户、费用分项与退款规则；财务核验核对"合同主体＝收款账户名"；
  3. 到账后向客户出具可查阅的收据/凭证记录；
  4. 建议大额费用按服务节点分阶段收取（商业条款，非托管）；
  5. 退款规则、时限与争议处理写入合同与费用页。
- 第三方支付、资金托管、跨境付款通道在 V1.5 基于试点数据与支付合规结论再评估。

#### D9 数据跨境与隐私路径

- 证件、资产、无犯罪记录等属高敏个人信息；向境外服务方共享构成个人信息跨境提供。
- V1 采用"**技术控制先行 + 法定路径核验**"：
  1. 默认通过**受控服务方门户**在线查看材料：按案件授权、页面水印、禁止/审批下载、访问到期收回，尽量不下发原件，从源头最小化出境数据；
  2. 确需出境的材料：单独告知与单独同意、个人信息保护影响评估（PIPIA），并由律师确认适用法定路径（标准合同备案/保护认证/安全评估，按数据规模与主体性质判定）；
  3. 与 841 号令的中介隐私义务衔接：服务方协议纳入保密、不得转售、协助删除与 breach 通知条款；
  4. 留存与删除：按法定/合同期限留存，到期处置；客户撤回授权不删除已履约必要记录（沿用 V1）。
- 不决定时的默认处置：服务方门户只读、不开放下载，不完成同意流程不共享任何材料。

### 2.3 G-P0 关门标准（全部具备才进入 G-P2）

| 交付物 | 责任人（角色） | 关门标准 |
| --- | --- | --- |

| 主体与合规适用意见（D2） | 合规负责人/外部律师 | 备案、合同链条、持牌与宣传边界有书面结论；备案动作有时间表（注意 90 日窗口） |

## 5. 核心业务流程及异常规则

### 5.1 项目进入平台与持续核验（在 V1 §5.1 上增补节拍）

来源登记 → 内容整理 → 条件与费用复核 → **服务方主体、资质与交付范围核验（含境内签约主体）** → 合规边界确认（可承诺/不可表述清单）→ 审核通过 → 发布版本 → 顾问授权与培训 → **持续复核**。

持续复核规则（初始建议值，试点校准）：

- 官方政策/条件类：按官方来源变更监控，发现重大变更即时走新草稿；常规全量复核建议每季度一次；
- 费用类：每次对客报价前比对最新 FeeSchedule；常规复核建议每半年；
- 资质/备案类：到期前 60/30/7 天三级提醒，**到期未续系统自动暂停新签与新报价**，历史在途业务按交接/处置规则继续；
- 进度凭据：逐件核验，不抽样；
- 每条关键事实必须存在对应 VerificationRecord，无记录的事实不得出现在对客详情页。

发布后修改、在途通知、历史快照规则沿用 V1 §5.1。

### 5.2 客户选择与顾问承接

沿用 V1 §5.2（游客先浏览、分享链接只记来源、待接受关系、超时进运营队列、自助可不绑定顾问、重复咨询不重复收费）。增补：

- 顾问公开名片展示字段按 §7 的 S05 白名单输出，禁止成功率/获批率类信号；
- 平台分配顾问时，仅分配授权覆盖该项目且资质有效的顾问；
- 顾问接受关系时须确认最新版项目必读更新（S10）。

### 5.3 初评与方案（增补合规边界）

- 初评问卷按项目模板配置，模板经合规负责人审核留版本；输出固定为四类：**已知符合项、明显差距、待确认项、信息来源与时间**；
- 禁止性表述清单（系统校验＋人工复核）：不得出现"保证/包过/成功率/内部渠道/官方关系"等表述；不得输出精确获批概率；
- 每份初评结论标注性质提示（"信息整理，不构成资格认定或法律意见，个案以官方审核为准"——具体文案由律师定稿）；
- 超出模板的个案判断必须由顾问/办理人员人工出具并署名，不自动生成；
- 方案版本、改价重确认规则沿用 V1 §5.3。

### 5.4 签约与生效（增补主体校验门）

方案确认 → 生成订单草稿 → **主体校验门（收费主体、合同主体、收款账户一致且有效，费用分项收取方完整）** → 明确签约/收费/办理主体及费用 → 正式合同签署状态核验（V1 允许外部/线下签署受控登记）→ 满足生效条件 → 建立案件任务。

- "确认了解方案"不是签署（沿用 V1）；
- 合同须包含：服务范围与边界、退款规则、境外段服务方告知、平台保障范围与平台外交易边界、隐私与跨境告知；
- 付款凭证流程沿用 V1：上传显示"待核验"，财务确认才显示"已核验到账"；重复凭证拦截重复记账。

### 5.5 办理与进度（增补受控门户）

案件建立 → 模板生成材料与任务 → 客户提交 → 审核/退回 → 具备递交条件 → 服务方递交并提供凭据 → **凭据核验岗逐件核验、授权后对客发布** → 跟踪受理/补件/结果 → 后续服务与结案。

- 境外服务方通过受控门户上传凭据、查看被授权材料：按案件授权、水印、下载需审批、访问到期收回（D9）；
- 事件来源四级（客户提交/公司审核/服务方报告/已核验官方凭据）与"无凭据不展示伪精确进度"沿用 V1 §5.5；
- 补件、暂停、拒绝、失联、争议各自独立记录，不并入"处理中"。

### 5.6 佣金产生与结算

规则版本锁定、六态（预估→待触发→应计待核验→可结算→结算处理中→已结算；冻结/调整）、异议、退款调整与追回均沿用 V1 §5.6。增补：

- 仅平台登记订单可进入佣金流程；平台外成交不产生平台佣金，也不纳入平台保障（在协议与对客页面明示）；
- 顾问私收客户款项一经核实，冻结其新增授权并进入合规事件处置，已发生合规佣金按原规则结算，不连坐清零。

### 5.7 关系变更、退出与项目下架

全部沿用 V1 §5.7（换顾问五步交接、顾问离开停新接旧、项目下架可配置范围且历史不隐藏、撤回授权不承诺一键清除履约记录）。增补：顾问/服务方资质到期未续视同"暂停"触发相同处置。

### 5.8 通知触达与升级（新增）

| 级别 | 事件示例 | 通道（V1） | 升级规则 |
| --- | --- | --- | --- |
| T0 时限关键 | 补件要求、官方截止日、付款截止、授权到期 | 站内＋邮件＋短信（签约时采集并验证）；同步主责顾问 | 未读/未达在配置时限内升级顾问、运营；电话跟进须记录结果；锁屏摘要不显示敏感详情 |
| T1 业务状态 | 受理、阶段变化、方案/合同待确认、佣金状态 | 站内＋邮件（或服务通知，按通道可用性） | 超时未处理进入工作台提醒，不改写原截止时间 |
| T2 内容与营销 | 项目更新、资讯、活动 | 站内；单独订阅、可一键退订 | 不与业务必需消息混发（沿用 V1 A09） |

- 每条 T0/T1 通知生成 DeliveryRecord：发送、送达、已读均有状态；通道失败自动换通道重试；
- 客户可维护通道偏好与联系方式；合同中约定客户保持联系方式有效的义务（降低不达风险，不免除平台通知责任）。

### 5.9 家庭与未成年人授权（V1 最小规则）

- 沿用"账号≠申请人""同家庭不默认互可见"；授权维度为：人员 × 案件 × 动作 × 有效期；
- **未成年申请人**：由其法定监护人（父母/法定代理人）在平台发起并操作；须登记监护关系证据（出生证明/户籍/监护文书等，具体要求按适用法域与项目核验清单执行）；
- **成年随行成员**：原则上由本人完成授权；确无法本人操作的，允许线下授权书受控登记（上传原件、核验人、有效期），不接受默认代签；
- 监护人不得代成年成员确认合同；代办动作全程留痕；C13 提供访问记录查看与撤销。
- 复杂监护争议（离异、收养、身故）V1 转人工合规处理，不在系统内自动判定。

### 5.10 退款与服务争议（最小规则）

- 退款条件、比例与节点在合同与 FeeSchedule 中预置；退款申请走工单，金额类变更双人复核（沿用 V1）；
- 服务争议先由客服/质量独立受理（顾问不独占），区分：服务未交付、交付质量、官方结果（拒绝/补件）、平台外交易纠纷；
- 官方结果不等于服务失败（沿用"结果已出≠获批"原则），争议处理以合同服务范围与凭据记录为准；
- 涉误导宣传、私收款的工单自动标记合规事件，进入 D5 处置流程。

## 6. 客户端功能规划

### 6.1 信息架构调整

## 9. 状态设计

V1 §9 全部状态机沿用（项目版本、顾问入驻、服务关系、方案、订单、付款、材料、案件、结果、工单、佣金）。新增/修订：

| 对象 | 状态与分支 | 控制要点 |
| --- | --- | --- |
| 资质/备案 Credential | 待核验 → 有效 → 即将到期 → 已过期/已暂停；核验不通过 | 到期未续自动暂停对应顾问/服务方新业务（AT22），不影响在途案件交接 |
| 服务方 | 待准入 → 有效 → 暂停（新签/全量）→ 终止 | 境外主体须关联境内协作主体与协议 |
| 通知送达 | 待发送 → 已发送 → 已送达 → 已读；发送失败 → 换通道/升级 | T0 未达必须形成升级记录（AT19） |
| 同意与授权 Consent | 待确认 → 有效 → 已撤回 → 已到期；版本更新待重新确认 | 跨境共享单独同意，不与一般隐私授权捆绑；撤回不溯及已履约记录 |
| 材料访问（门户） | 未授权 → 可查看（水印）→ 下载审批中 → 可下载（限期）→ 已收回 | 默认不下载；越权拒绝并审计（AT25） |
| 合规事件 | 登记 → 调查中 → 处置中 → 结论（不成立/违规处置）→ 关闭 | 调查人与被调查顾问分离 |

纠错规则沿用：以更正事件替代静默改写；业务发生时间与录入时间分别记录，补录不冒充实时。

## 12. 分阶段实施与试点

### 12.1 阶段总览

```text
G-P0 商业与合规地基（决策门）
  → G-P1 确认定位/对象/V1 边界（V2 确认后更新）
  → G-P2 细化 C/S/A 功能卡：字段、异常、状态、权限、验收样例，冻结页面目录
  → G-UX 客户主流程低保真 → 顾问手机/iPad → 后台支撑 → 可点击原型 → 高保真
  → G-DEV 切片 A0 → A → B → C → D（端到端纵向切片，不做空壳页面）
  → G-TEST 账号/权限/数据测试、真机试用、风险修正
  → 受控试点：影子运行 → 邀请客户 → 复盘
  → 达关门条件后有限开放（V1.5 范围另批）
```

G0/G1 历史验收不被覆盖；本阶段不承诺未经估算的开发天数（沿用 V1 立场）。

### 12.2 切片 A0（新增）：供给与核验底座（后台先行，不对客）

交付范围：组织/账号/对象级权限基线；项目治理与 VerificationRecord；服务方与资质/备案台账；顾问入驻、培训确认与授权；FeeSchedule 与佣金规则版本配置；受控门户与水印基础能力；Consent 记录基础。

完成定义：试点项目全要件可在后台走完"登记—核验—发布"；资质到期可自动暂停；无任何对客入口依赖时底座可独立验收。

### 12.3 切片 A–D（沿用 V1，含 V2 增量）

| 切片 | 交付范围 | 完成定义（增量加粗） |
| --- | --- | --- |
| A 可信发现与咨询 | 独立账号、项目发布、分类比较与基础搜索、需求初评、顾问授权与关系 | 客户不留资浏览；服务关系真实且有权限；**初评无违规表述** |
| B 方案到订单 | 方案版本、报价复核、客户确认、合同登记、付款核验 | 费用/签约/责任/生效可解释；**主体不一致不能下单；变更重新确认** |
| C 申请与服务 | 案件、申请人与**监护授权**、材料、任务、**多通道通知**、凭据、**服务方门户**、工单 | 官方与内部状态不混淆；**T0 通知有送达与升级记录** |
| D 佣金与治理 | 规则快照、应计/结算/调整、交接、争议、**合规事件**、审计、备份恢复 | 每笔收益有证据；权限与跨境共享验证通过；历史不丢失 |

A 切片可做限定体验测试，不得宣称完整自助申请平台（沿用 V1）。

### 12.4 受控试点设计

1. **影子运行（不对外）**：选 1–2 个真实在办案件，全部流程人工实际操作、系统只记录与对照，验证：核验节拍可行性、凭据链路、通知到达率、主体/合同链条、门户可用性；
2. **邀请制客户**：从已有线索邀请少量客户使用 A–D 全流程；每单有复盘人；
3. **试点保障**：每案配备主责顾问、办理人、凭据核验人、客服受理人；合规负责人可介入；
4. **进入条件**：P0 关门＋A0–D 验收＋影子运行无阻断问题＋真机测试通过＋备案/主体动作完成；
5. **暂停与回滚**：出现误导宣传事件、资金争议、材料泄露、官方递交异常任一类，暂停新签并按预案处置；已签订单按合同继续履行，系统保留全部记录；
6. **退出试点条件**：§12.5 指标建立基线并达到内部约定门槛、无未处置重大合规事件，才评估扩项目/扩顾问。

### 12.5 指标体系（先建基线，后定目标）

- 客户侧：项目查找任务完成率、费用理解正确率、初评完成率、咨询响应时间、材料一次通过率、进度更新及时率、工单超期率、费用争议率、客户访谈反馈；
- 顾问侧：授权顾问活跃数、必读更新确认及时率、演示模式误用次数、对账异议率；
- 运营/核验侧：项目核验覆盖率、复核按期率、资质到期处置及时率、凭据核验时长、T0 通知送达率、**单项目核验工时与单案件运营工时（核验成本模型）**；
- 商业侧：登记咨询→订单转化率、平台外成交线索/投诉数、佣金对账差异率、退款率。

不把未经测试的转化率作为平台成绩（沿用 V1 §12.4）。

## 15. 正式业务开放前置条件（更新 V1 §13）

1. G-P0 全部决策关门（§2.3），备案/主体动作完成或有明确不影响开业的法律意见；
2. 关闭公测自由角色选择，建立独立账户与真实业务授权，管理人员强身份验证；
3. 试点项目内容、服务方式、服务主体与可承诺事项逐个审核，禁表述清单到位；
4. 签约方、收费方、收款账户、退款责任、佣金触发与争议规则经批准并配置进系统；
5. 私密文件与公开资料分区，对象级权限、门户水印、下载审批、留痕、备份恢复验证通过；
6. 隐私告知、跨境单独同意、家庭/监护授权、保留删除流程与服务方共享边界定稿；
7. T0/T1 通知通道实测送达率达标，送达回执与升级链可用；
8. 目标手机、iPad 真机测试通过；不宣称 APP/小程序已发布；
9. 影子运行完成且无阻断问题；无外部对接的环节明确人工责任，不以动画伪装自动办理。

本节是产品开放门槛，不是任何地区监管要求的完整清单；实施前以律师意见为准。
