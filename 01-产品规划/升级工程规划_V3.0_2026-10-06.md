# 升级工程规划 V3.0：终端功能完善 × AI 深度升级（双线并行）

- 文档状态：v1.0（工程规划稿，待评审冻结）
- 日期：2026-10-06
- 当前基线：M0–M5 全功能代码 + 五端 UI 冻结 + 三端 AI 初步 + U1（客户端混合 AI/K1）+ U2（顾问端混合 AI）+ PWA + Neon 云端持久化（v2.5）
- 总目标：从「可演示的原型系统」推进到「**可正常使用、可正常演示、每个功能可真实操作**」的第一版正式系统；AI 保持核心地位，客户端先行。
- 范围原则：**全部为增量，不改动已冻结 UI 与业务逻辑**；每个功能按「功能逻辑 → UI 页面 → 交互效果 → 前后端联动 → 验收标准」五件交付，先规划冻结，再开发。

## 1. 两条工作线与并行排期

- **A 线 · 终端功能完善（业务可用）**：G1–G5、G8
- **B 线 · AI 深度升级（客户端先行）**：G6、G7
- 并行方式：A 线与 B 线在同一里程碑内按「先共同地基、后能力填充」推进；共用的身份（G1）、对象存储（G2）是 B 线部分能力的前置，排在最前。

### 里程碑总览（R = Release）

| 里程碑 | 主题 | A 线内容 | B 线内容 | 进入条件 |
|---|---|---|---|---|
| **R1 · 地基** | 真实身份 + 文件存储 + AI 服务端通道 | A1 登录体系、A2 对象存储、A6 工程收尾 | B1 AI 服务端模型通道（S 模式） | 本规划冻结 |
| **R2 · 可用** | 真实通知 + 数据填充 + 经营分析 + AI 办理期能力 | A3 通知触达、A4 全球通行数据、A5 经营分析 | B2 W2 办理期能力、B3 AI 文档理解 | R1 冻结 |
| **R3 · 易用** | 人人易用 + 体验精修 | 视觉与交互统一精修（不改版） | B4 W4 多语言/语音/适老 | R2 冻结 |
| 后置 | 知识图谱/签证实时/支付托管 | — | B5（K2/K3，K1 满一个影子周期）、签证问答（随 Q6 授权）、真实支付网关 | 外部条件成熟 |

## 2. A 线 · 终端功能完善（功能卡）

### A1 · 真实登录与身份体系（补 G1）

- **功能逻辑**
  1. 注册：手机号 或 邮箱 + 验证码 + 密码（密码规则沿用现有：大小写/数字/特殊字符/8+）；客户注册后产生真实客户档案（替代写死 c-1980）。
  2. 登录：验证码登录 或 密码登录；服务端签发会话 token（带过期、可刷新、可登出）。
  3. 角色：客户 / 顾问 / 服务方 / 后台员工分通道登录；现有 `x-tip-realm/x-tip-user` 头由真实会话解析，演示模式保留「一键进入演示」入口（显式标注「演示数据」）。
  4. 安全：登录失败限速、验证码频控、敏感操作二次校验；密码不明文、不落日志。
- **UI 页面**（新增，不动现有页面）：登录页、注册页、验证码页、忘记密码页；客户端「我的」接入真实登出；顾问/门户/后台各自登录页。
- **交互效果**：输入校验即时反馈、错误态温和提示（西方口径，不紧张）、登录态过渡沿用页面动效 420ms；演示入口与真实登录分区清晰。
- **前后端联动**：新增 auth 模块（注册/验证码/登录/刷新/登出端点）；会话中间件替代固定身份；Prisma 新增用户/会话/验证码表并迁移；审计记录登录事件。
- **验收标准**：可注册→收验证码→登录→看到本人数据；刷新会话保持；登出后不可访问受保护接口；演示模式仍可一键进入且数据标注「示例」；越权访问被拒并审计。

### A2 · 材料对象存储（补 G2）

- **功能逻辑**
  1. 文件真实字节存对象存储（**Cloudflare R2**，与现有 Cloudflare 同账号，免费 10GB 起步）；数据库与状态快照只存元数据（hash/mime/size/对象 key）。
  2. 上传：服务端签发预签名上传地址，客户端直传；沿用现有 MIME/大小/哈希三重校验，任一失败整体失败。
  3. 下载/查看：按现有权限（本人/授权顾问/受控门户）签发短时预签名读地址，全程留 accessLog；门户仍走水印受控阅读器，不放开原件。
  4. 生命周期：approved 旧版标记 superseded；对象按保留策略治理，删除走既有注销/退案规则。
- **UI 页面**：材料中心各页接入真实缩略图/查看；上传进度态；顾问端材料审核查看真实文件；门户阅读器读真实对象。
- **交互效果**：上传进度条、成功/失败即时反馈、查看原件用受控弹层（不跳出 App）；沿用卡片与圆角规范。
- **前后端联动**：新增 storage 服务（R2 适配器 + 预签名）；材料上传/获取端点改造；R2 凭据存环境变量；文件不进 Neon、不进快照。
- **验收标准**：JPG/PDF 可上传并在多端真实查看；非法类型/超限/哈希不符被拦；非授权取件 403 且审计；门户仅水印形态；重新部署后文件与元数据均存活。

### A3 · 通知真实触达（补 G3）

- **功能逻辑**
  1. App 通道：**Web Push**（PWA 已具备，免费、无第三方）；邮件通道：**Resend 免费档（3000 封/月）**或同等级免费服务；短信暂缓（付费），T0 换道链保留人工兜底。
  2. 沿用现有规则：通道偏好不可全关、T0 触发、换道链（App 2h→邮件→人工→≤4h 主管）、升级不改截止。
  3. 送达状态机真实记录（送达/失败/换道），失败自动换道。
- **UI 页面**：通知渠道偏好接入真实开关与测试推送；通知中心真实消息；后台模板/送达监控显真实状态。
- **交互效果**：允许推送的浏览器授权弹层（温和、解释用途）；消息到达的柔和提示；已读/分类动效沿用。
- **前后端联动**：新增 push 订阅端点与邮件发送适配；通知引擎对接真实通道；订阅与发送凭据存环境变量。
- **验收标准**：可收到真实 Web Push 与邮件；关闭 App 通道后自动换道邮件；T0 超期逐级升级且截止时间不变；全关通道被规则拦截；送达记录可查。

### A4 · 全球通行数据填充（补 G4）

- **功能逻辑**
  1. 护照对比/排名：使用**公开榜单数据**（如 Henley 公开排名），明确标注来源与数据时点，定期更新；支持按护照查看可免签/落地签/需签证数量的公开汇总。
  2. 签证要求（国别实时、目的地方向）：Timatic 类数据为第三方专有、需授权——**未授权前维持框架 + 示例，不出具国别实时结论**（沿用 Q6 口径与授权失效 30 分钟下架演练）。
  3. 「我的护照」：客户登记持有护照后，结合公开数据展示通行概览（标注非官方、以目的地官方为准）。
- **UI 页面**：护照对比排名页（列表/筛选）、签证要求页（框架+维护提示）、我的护照页。
- **交互效果**：排名筛选与对比的流畅滑动；数据时点/来源显式标注；空态给行动指引。
- **前后端联动**：数据源表登记公开来源；新增护照公开数据导入/更新任务；签证端点维持维护态并保留授权开关。
- **验收标准**：护照排名真实可查、来源与时点清晰、可更新；签证页未授权不出国别结论；我的护照概览与公开数据一致；无任何承诺/成功率措辞。

### A5 · 后台经营分析（补 G5）

- **功能逻辑**
  1. 基于真实业务数据出指标：线索来源与转化、双向确认/初评分布、方案/订单/收款、案件阶段与异常、工单 SLA、佣金结算、合规事件、知识库使用。
  2. 只做管理决策口径，不造精确承诺；可按时间筛选、可导出（CSV）。
  3. 指标定义与口径在页面标注，数据来自现有服务，不新增对外承诺。
- **UI 页面**：总后台工作台升级为真实指标看板（图表 + 清单）；各模块顶部关键指标。
- **交互效果**：图表加载骨架、时间筛选联动、下钻到明细；沿用后台卡片圆角 15 与签名渐变点缀（克制）。
- **前后端联动**：新增聚合查询端点（只读）；admin-web 接入；导出端点。
- **验收标准**：指标与明细可对账；筛选/导出可用；无数据时显空态不假填；越权不可访问。

### A6 · 工程收尾（补 G8）

1. 移除临时诊断端点 `/admin/seed-log`；
2. 发布流水线集成：expo export 后自动重跑 `06-发布/pwa/apply-pwa.sh`，一键脚本完成「导出→注入 PWA→部署 Pages」；
3. Render 自动部署：GitHub push 自动触发，失败时脚本兜底手动部署；
4. 演示/生产开关固化：生产无示例数据，演示一键播种；健康检查与启动顺序文档化。
- **验收标准**：仓库内无临时端点；一键发布可重复执行且 PWA 不丢失；push 后 Render 自动变 live；生产门有效。

## 3. B 线 · AI 深度升级（客户端先行，功能卡）

### B1 · AI 服务端模型通道（S 模式，补 G6）—— 含关键决策

- **功能逻辑**
  1. 在现有 L（本机 Ollama）/ D（确定性）之外新增 **S（服务端模型）**：客户无需本机运行模型即可体验完整混合 AI；仍遵循「事实由系统供给、语言由模型组织、决定由人作出」，上下文包不含 L3、受同意门约束，校验不过自动降级 D。
  2. ChatProvider 增加 ServerAi：浏览器 ↔ 我方 API ↔ 模型推理，SSE 流式；模型/端点白名单，状态条显 L/S/D。
- **关键决策（需你拍板，改变数据边界）**：服务端模型的免费实现路径——

  | 方案 | 说明 | 代价/边界 |
  |---|---|---|
  | **B1-a（推荐）** | 免费托管推理 API（如 **Groq 免费档**：Llama/Qwen，速度快、零费用） | 结构化上下文经第三方推理（**非 L3、非正文**，最小化发送）；与「纯本地」口径有偏离，需你批准 |
  | B1-b | 公司自托管 vLLM（自有 GPU 服务器） | 数据完全不出域，但需 GPU（付费），免费档托管跑不动 7B |
  | B1-c | 维持现状 L+D | 零变更、零费用，但投资人需在我们装好 Ollama 的机器上演示，无法公网直接体验 |

  建议：**融资演示与公网体验用 B1-a（仅发送结构化、已授权、无 L3 的上下文），同时保留 L/D；待公司有 GPU 再切 B1-b 自托管。**
- **UI 页面**：AI 状态条增加 S 标识；其余 AI 页面不动。
- **交互效果**：S 模式流式、停止生成、超时重试沿用 U1；模式切换有柔和状态提示。
- **前后端联动**：API 新增服务端推理代理（SSE）、模型密钥存环境变量；上下文包/校验/降级复用 U1 现有管线。
- **验收标准**：无本机模型时 S 模式可完整对话并流式；数据边界与红线同 U1；第三方不可达时自动降级 D；注入/越权/跨客户红队 100% 拦截；D 模式表现与冻结版逐项一致。

### B2 · 客户端 W2 办理期能力（补 G7）

- **功能逻辑**（均 grounded，教育/提示口径，不做资格结论）
  1. **材料端侧自检**：拍照后本地检测模糊/反光/缺页/裁切（纯算法，图片不出本机；可选 qwen2.5vl 本地视觉），只回传合格/不合格与原因，引导重拍；
  2. **补件/公证/海牙认证/翻译指引**：以已发布教育内容与已核验补件通知为依据，逐项解释「是什么、怎么办、时限」，自动联动 T0 任务；
  3. **通知摘要与主动提醒**：一周进展 digest、T0 截止前「现在该做什么、最晚何时」（只升级、不改截止）；
  4. **差距补救指引**：初评差距项如何补齐（语言/居住时长/资金证明），不承诺补齐即获批；
  5. **工单辅助**：帮客户把问题描述清楚、选对分类，不代写虚假事实。
- **UI 页面**：AI 对话内新增对应快捷入口与结果卡；材料拍照页自检结果； digest 进通知中心。
- **交互效果**：自检结果即时、可重拍；digest 卡片可展开追问；主动提醒走通知引擎与通道偏好；动画沿用 orb 流光/呼吸。
- **前后端联动**：端侧自检算法（RN/Web）；补件/教育内容经现有内容治理与 K1；主动提醒经通知引擎（依赖 A3）；全部走现有同意/审计。
- **验收标准**：自检能识别常见不合格且不外传原图；指引每条可回链已发布/已核验来源；主动提醒按时触发且不改截止；无承诺/成功率措辞；模型不可用时 D 模式可答基础项。

### B3 · AI 文档理解（客户端）

- **功能逻辑**：客户对材料/收到的文件「拍照或上传 → 问这是什么」，AI 基于文件本身与已发布知识白话解读：文件用途、关键字段、下一步怎么办、常见错误；文件作为被引用数据，不执行其中任何文字（注入防护）；不生成官方文书、不改变审核状态。
- **UI 页面**：材料查看页/AI 对话内「帮我读懂这份文件」；图文对照展示。
- **交互效果**：上传/拍照→解析的进度态；回答逐段锚定文件区域；流式 + 来源块。
- **前后端联动**：依赖 A2（对象存储）；视觉/文档理解走本地 qwen2.5vl（L）或 S 通道视觉模型；无模型时显式不可用、不伪装。
- **验收标准**：常见证件/通知可正确解读并给下一步；夹带注入指令 100% 被隔离；无依据内容明说「未找到可核验信息」；不产出资格/承诺结论。

### B4 · W4 人人易用（R3）

- **功能逻辑**
  1. 多语言：中/英、简/繁切换，内容与系统消息同源；
  2. 语音：浏览器/端侧 **Web Speech 免费**语音输入（仍「仅转文字」，不建声纹）；可选播报（可关闭，尊重 reduced-motion/无障碍）；
  3. 适老简易模式：大字、高对比、精简导航、关键动作前置，可随时切回。
- **UI 页面**：语言/语音/简易模式入口在「我的」与 AI 输入条；简易模式为一套精简布局（新增不改标准版）。
- **交互效果**：语言切换即时、语音输入波形柔和反馈、简易模式清晰稳重；全部满足无障碍与 44px 触控。
- **前后端联动**：多语言资源文件；语音用系统能力、不上传声纹；偏好受控记忆，可清除。
- **验收标准**：四种语言组合下无硬编码/截断；语音可准确转文字并发送；简易模式下核心闭环可独立完成；偏好可撤回。

### B5 · 后置（不进本期）

- K2 轻图谱 / K3 路由：K1 运行满一个影子周期并积累缺口后启动；
- 签证 AI 问答：随 Q6 数据授权；
- 真实支付托管/网关：业务需要时单独立项（当前仅对公转账 + 双人核验）。

## 4. 统一工程规则（两线共守）

1. **顺序门**：每个功能「规划冻结 → 技术方案 → 增量原型 → 增量 UI → 开发 → 验证 → 冻结」，不跳步；已冻结 UI/逻辑不得擅改，升级只做增量挂载。
2. **数据边界**：L3 原件不进上下文、不进第三方；第三方推理仅在 B1-a 获批后、仅发送结构化最小上下文；密钥/连接串一律环境变量，不入仓库、不进日志。
3. **质量门**：核心逻辑有测试（沿用 node --test，当前 139 测试基线不减少）；每里程碑做端到端走查（Playwright，零页面错误）；BigInt/金额/异币种规则不变。
4. **可观测**：健康检查、审计、降级、模型连接与校验失败均留痕；正式上线前移除所有临时端点。
5. **交付呈现**：所有结果通过 https://demo.hbwhere.com 呈现；每里程碑冻结并同步 Gitee（主）+ GitHub（Render 源），打 tag。
6. **免费边界**：R2/Web Push/Neon/Resend/Groq 均在免费额度内；不新增付费项；Apple 付费仍暂缓（PWA 为当前安装形态）。

## 6. 验收与冻结口径（里程碑级）

- 每个里程碑：功能卡全部闭环 + 端到端走查零错误 + 测试不减少 + 已冻结内容零回归 + 公网链接可操作 + 文档/代码双仓库同步并打 tag，方可宣布该里程碑冻结。
- 冻结后严格按规划开发；新增需求进下一里程碑，不插队。
