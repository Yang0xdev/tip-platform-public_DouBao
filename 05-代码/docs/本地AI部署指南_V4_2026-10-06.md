# 本地/混合 AI 大模型部署指南（V4，教学与运维基线）

- 版本：v1.0（2026-10-06）
- 适用：本平台「本地 AI 中枢」的安装、配置、验证、升级、故障排查；未来沉淀为 skill 的母本
- 范围：macOS（首选 AI 工作站）、Linux（无 root 用户态）、混合云第三档、可选 LiteLLM
- 总原则：**本地优先（目标 85–95% 任务不出本机）；L3 原件不离机；云档默认关闭、开启需审批与脱敏**

---

## 1. 硬件与模型矩阵

### 1.1 硬件建议（Apple Silicon）

| 配置 | 可常驻模型 | 适用角色 |
|---|---|---|
| 16GB | 7B 中模型 + 嵌入（bge-m3） | 单人日常（最低可用） |
| 32GB | 7B + 14B（按需）+ VL + 嵌入 | 推荐「AI 工作站」 |
| 64GB | 14B 常驻 + VL + 32B 按需 + 多并发 | 团队共享/数据工厂 |

- Intel Mac / 普通 PC：可跑 3B/7B，速度明显慢；数据工厂建议 Apple Silicon 或带 GPU 的 Linux 工作站。
- 云 VM（如本环境 4C/8GB/无 GPU）：仅适合 0.5B–3B 冒烟与 CI，不承担生产抽取。

### 1.2 模型矩阵（Ollama 标签）

| 档位 | 标签 | 用途 |
|---|---|---|
| 快速 | `qwen2.5:3b` | 分类分诊、简单抽取、改写 |
| 日常 | `qwen2.5:7b`（或 qwen3:7b） | 结构化抽取、访谈、比较、导读、初稿（主力） |
| 复杂 | `qwen2.5:14b`（或 qwen3:14b） | 多步推理、复杂合并、疑难文书 |
| 视觉 | `qwen2.5vl:7b` | 扫描件、表格、印章、手写、材料拍照自检 |
| 嵌入 | `bge-m3` | 多语种向量化与检索 |

> 说明：0.5B 仅用于连通冒烟，其输出质量不足以对客（实测会出现明显事实偏差）——这也是「7B 为日常档 + 接地校验 + 四眼」的原因。

## 2. macOS 部署（标准路径）

### 2.1 安装

1. 官网下载 Ollama（或 `brew install ollama`）；
2. 启动菜单栏 Ollama 应用；验证：`ollama --version`、`curl http://127.0.0.1:11434/api/version`。

### 2.2 拉取模型

```bash
ollama pull qwen2.5:3b
ollama pull qwen2.5:7b
ollama pull qwen2.5:14b      # 32GB+ 再拉
ollama pull qwen2.5vl:7b
ollama pull bge-m3
ollama list
```

### 2.3 放行网页来源（关键）

浏览器中的 App 要访问本机 Ollama，必须配置环境变量后重启 Ollama：

- 临时（终端启动）：
```bash
OLLAMA_ORIGINS="https://demo.hbwhere.com,http://localhost:5100,http://localhost:8081" \
OLLAMA_HOST=127.0.0.1:11434 ollama serve
```
- 持久（GUI 版）：`launchctl setenv OLLAMA_ORIGINS "https://demo.hbwhere.com,http://localhost:5100,http://localhost:8081"`，退出并重新打开 Ollama 应用。

### 2.4 常驻与自启

- Ollama 应用默认开机启动（系统设置 → 通用 → 登录项）；
- 控制模型常驻：调用时带 `keep_alive`（如 `"30m"`/`"-1"` 永久）；内存有限只常驻 7B，其余按需加载；
- 模型默认存储 `~/.ollama/models`（大体积，可通过软链接迁到外置盘：先停服务，`mv` 后 `ln -s`）。

### 2.5 验证

```bash
curl -s http://127.0.0.1:11443 2>/dev/null # 端口核对
curl -s http://127.0.0.1:11434/api/generate -d \
'{"model":"qwen2.5:7b","prompt":"你好，用一句话自我介绍","stream":false}'
```
在 https://demo.hbwhere.com/live/client 的 AI 中提问，状态条显示「本地模型」即通。

## 3. Linux 无 root 用户态部署（本环境已验证）

适用：无 sudo、无法 `apt install zstd` 的云 VM。

```bash
# 1) 下载发行包（.tar.zst）与用户态解压能力
pip3 install --user zstandard
curl -sL -o /tmp/ollama.tar.zst \
  https://github.com/ollama/ollama/releases/download/v0.35.1/ollama-linux-amd64.tar.zst

# 2) 用 Python zstandard 解压到用户目录
python3 - <<'EOF'
import zstandard, tarfile, os
home = os.path.expanduser("~/.local/ollama"); os.makedirs(home, exist_ok=True)
with open("/tmp/ollama.tar.zst","rb") as f, zstandard.ZstdDecompressor().stream_reader(f) as r:
    with tarfile.open(fileobj=r, mode="r|") as t: t.extractall(home, filter="data")
EOF

# 3) 启动（二进制在 bin/，依赖库在 lib/）
export PATH=$HOME/.local/ollama/bin:$PATH
export LD_LIBRARY_PATH=$HOME/.local/ollama/lib:$LD_LIBRARY_PATH
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_ORIGINS="*" nohup ollama serve > /tmp/ollama.log 2>&1 &

# 4) 拉小模型冒烟
ollama pull qwen2.5:0.5b
curl -s http://127.0.0.1:11434/api/tags
```

自启（无 root）：写入用户 crontab `@reboot` 或 shell profile 守护（示例略，按环境）。

## 4. 混合模型与网关配置

### 4.1 本平台识别的环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | Ollama 地址（可指向局域网工作站） |
| `AI_CLOUD_TIER` | 未设置（关） | `=1` 才允许云第三档 |
| （云）`*_API_KEY` | 无 | 仅在云档开启时配置，存环境变量/密钥管理 |

### 4.2 路由与降级（已在代码实现）

任务 → 复杂度评分 → 档位（fast/standard/large/vision/embed）→ 候选标签；
关键抽取第二模型/确定性交叉验证；本地不可用或接地校验失败 → 确定性 D（不编造）。
敏感任务永不走云；视觉/嵌入固定本地。

### 4.3 云档脱敏（开启时强制）

1. 发送前用 GLiNER/规则剔除/替换人名、证件号、账号、地址等实体（本地保留映射）；
2. 只送任务必需的最小文本片段，不送原件、不送 L3；
3. 返回后本地再还原实体；全过程审计（任务、提供商、字数、结果，不含正文）。

### 4.4 可选：LiteLLM 统一代理（团队扩大时）

- 本地 Docker 跑 LiteLLM：统一 Ollama 多模型 + 云提供商，提供虚拟密钥、预算、日志；
- 平台把 `OLLAMA_BASE_URL` 指向 LiteLLM 即可；当前单工作站无需引入（Node 自研网关已够）。

## 5. 监控、升级、回滚

- **状态查看**：总后台 A13「本地 AI 中枢」→ 模型矩阵（安装/常驻）、路由试跑、评测门禁；
- **升级模型/Prompt**：编辑 → 沙盒试跑 → 全量评测/红队 → 红线 100% 才发布 → 版本可回滚；
- **升级 Ollama**：macOS 直接更新；Linux 重新下载解压到新目录、验证后切换 PATH；
- **回滚**：Prompt/技能保留历史版本一键回滚；模型标签不可变，切回旧标签即可。

## 6. 故障排查（高频）

| 现象 | 排查 |
|---|---|
| 浏览器连不上本机 Ollama | `OLLAMA_ORIGINS` 未含当前站点；改后未重启 Ollama；端口/地址不符 |
| 模型显示未安装 | `ollama list` 核对标签；变体标签（-instruct/-q4）注册表按前缀兼容 |
| 生成很慢/卡顿 | 内存不足降档或减少常驻；检查是否在跑 14B；`ollama ps` 看加载情况 |
| 云端容器探测全部不可用 | 正常（容器无 Ollama）；本地 Mac 上为在线；公网仅展示已发布数据 |
| 回答出现无依据内容 | 接地校验应拦截并降级 D；保留用例、补红队集后再发布 |
| CORS/403 | origins 拼写、协议（http/https）、逗号分隔无空格 |

## 7. 交付检查清单（每次部署）

- [ ] `ollama list` 模型齐全；`ollama ps` 常驻符合预期
- [ ] A13 探测成功（本地）；路由试跑结果正确
- [ ] 评测/红队：红线 100%、质量全过、门禁通过
- [ ] 未授权/跨客户提问无数据；无承诺/成功率措辞
- [ ] 云档关闭时确认零外发（审计可查）
- [ ] 文档与结果已同步 Gitee/GitHub，tag 已打
