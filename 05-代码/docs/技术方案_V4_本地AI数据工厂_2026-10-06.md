└───────────────▲──────────────────────────────────────────────────────────┘
                │

│ Postgres（Neon 云 / 本地嵌入式）：规范数据 + 元数据 + 向量(pgvector)       │

## 2. 本地 AI 基础设施（着重发力）

### 2.1 模型矩阵（Ollama）

| 档位 | 建议模型（按本机已拉 Qwen 优先，标签以实测为准） | 用途 | 资源参考 |
|---|---|---|---|
| 快速小模型 | qwen2.5:3b / qwen3:4b | 分类分诊、路由初判、简单抽取、改写 | ~3–4GB |
| 日常中模型 | qwen2.5:7b / qwen3:7b（现有） | 结构化抽取、访谈、比较、导读、初稿 | ~5–6GB |
| 复杂大模型 | qwen2.5:14b / qwen3:14b | 多步推理、复杂合并、疑难文书 | ~10–12GB |
| 视觉模型 | qwen2.5vl:7b / qwen3-vl | 扫描件、表格、印章、手写、材料自检 | ~6–7GB |
| 嵌入模型 | bge-m3 / nomic-embed-text | 本地向量化、检索 | ~0.5–1.2GB |

- **硬件建议**：Apple Silicon，**16GB 可流畅跑 7B + 嵌入**；**32GB+ 可同时常驻 7B/14B/VL**（推荐作为团队「AI 工作站」目标配置）；内存紧张时用 Ollama `keep_alive` 控制常驻模型数量，按需加载。
- Ollama 配置沿用：`OLLAMA_ORIGINS` 放行 https://demo.hbwhere.com 与本地端口；`OLLAMA_HOST=127.0.0.1`；模型目录与日志规划；设置开机自启（macOS launch agent）。

### 2.2 模型网关（自研，Node 侧）

在现有 `ollama-provider / ChatProvider / context.service / validator` 基础上扩展为统一网关：

1. **Model Registry**：登记模型（能力、上下文、视觉、状态、白名单），健康探测；
2. **Task Router**：按「任务类型 + 复杂度评分 + 密级」选模型；规则可配置、可试跑；
3. **受约束生成**：结构化 JSON Schema 输出（解码层约束 + 失败重试一次）；
4. **交叉验证**：关键字段用第二模型/确定性规则复核，不一致进人工；
5. **降级链**：本地模型不可用/接地校验失败 → 确定性 D（现有 grounded），状态透明；
6. **流式与审计**：SSE、停止生成丢弃残片；连接/路由/降级/失败均审计（不含正文）。

> 选型说明：团队规模扩大或接入多云模型时，可在本地加 **LiteLLM Proxy**（统一多模型、虚拟密钥、预算）；当前 Node 自研网关与现有代码同构、零额外服务，先自研，LiteLLM 列为可选演进。

### 2.3 混合模型策略（本地优先）

- 目标 **85–95% 任务本地完成**；云为可选第三档，**默认关闭**；
- 开启条件：仅处理本地能力不足的任务；发送前用 **GLiNER/规则脱敏**（剔除/替换人名、证件、账号等敏感实体），结果返回后本地再还原；任务范围、白名单提供商、审计单独审批；
- 任何模式下：L3 原件不离开本机、只送结构化最小上下文、数据与指令物理分隔。

## 3. AI 数据工厂 · 技术管线

### 3.1 解析栈（按难度分流）

| 场景 | 工具（本地、开源） | 输出 |
|---|---|---|
| 数字 PDF / Office | **Docling**（版面、阅读顺序、表格） | 带页码/坐标的版面块 |
| 扫描件 / 图片文字 | PaddleOCR（中/多语种） | 文本块 + 置信 |
| 复杂图文/表格/印章/手写 | **Qwen-VL** | 结构化解读 + 位置 |
| 表格 | Docling 表格还原 + VL 校验 | 行列结构 |

- 版面块统一中间格式：`{blockId, page, bbox, type, text/table, sourceTool, conf}`；
- 质量门：缺页/乱码/低清晰 → 标记重扫（与材料端侧自检共用算法）。

### 3.2 抽取与证据锚定

1. Schema 定义（字段/类型/必填/枚举/范围），存为版本化配置；
2. **两阶段**：存在性/状态判定（含否定、不确定、未知）→ 取值；
3. 受约束结构化输出；每个值写 `{value, conf, evidence:{page,bbox,snippet}}`；
4. 无证据 → 空值 + 「未找到」；跨文档对齐产出候选，不自动合并。

### 3.3 清洗、校验与置信路由

- 确定性规则引擎处理归一（日期/币种/单位/别名映射）与去重；模型只给「建议」；
- Lint：必填/类型/枚举/断链/无证据/过期/**红线措辞（接 WordEngine）**；
- 置信阈值按文档类型校准（初始阈值在 P1 用标注集回归确定，非拍脑袋）；低置信必人工；
- 四眼：复用现有审计与权限，核验人 ≠ 编制人。

### 3.4 存储分层与血缘

| 层 | 内容 | 存储 |
|---|---|---|
| L0 | 原始文件（不可变） | 本地 MinIO/文件；公网 R2 |
| L0-meta / 批次 / 抽取 / 核验 / 发布 | 全过程元数据与证据 | Postgres |
| L1 | 规范结构化记录（canonical，版本化） | Postgres |
| L2 | Wiki 知识页（K1，Markdown） | Postgres + 对象 |
| L3 | 向量 / 轻图谱（后置） | pgvector；Cognee/Graphiti |

- **数据血缘链**：AI 回答/业务记录 → L1/L2 → 抽取字段（证据 bbox）→ 批次 BR → L0 RAW（哈希）；任一环节可向前追溯、可回滚版本；
- Neon 支持 **pgvector**，后续向量层无需新增数据库。

### 3.5 新增 Prisma 模型（P1 迁移，概要）

- `raw_sources`（RAW-，来源/哈希/密级/类型/状态）
- `refine_batches`（BR-，工段状态/模型/操作人）
- `extraction_fields`（字段值/置信/证据 page·bbox·snippet/状态）
- `normalization_actions`（规则/原值/标准值/操作）
- `validation_findings`（lint/交叉验证问题、处置）
- `publish_records`（canonical 版本/生效/失效/回滚）
- `model_registry`、`ai_skills`、`prompt_versions`、`eval_reports`、`redteam_results`
- `industry_packs` 与 `pack_versions`
（具体字段在 P1/P2 详细设计时定，迁移沿用现有 prisma migrate 流程。）

## 4. 平台内核抽象与行业包

### 4.1 monorepo 演进（增量调整）

```
packages/
  core/            # 行业无关：fsm/money/banned-words/audit/assessment 等
  platform-domain/ # （新增）从 services/api 抽出的通用业务域（CRM/方案/订单/案件/工单…）
  ui-native/       # 行业无关组件/token/raised-tab-bar
services/api/      # 应用装配：platform-* + 行业包加载 + 终端 API
apps/
  client-app / advisor-app / admin-web / portal-web   # 配置驱动的终端壳
packs/             # （新增）
  immigration/     # 包1：schema/状态机/词库/模板/技能/参考数据
  # legal/ finance/ manufacturing/ 后续
```

- 抽象策略：**先在移民代码内「分包边界 + 接口」，再物理抽包**，避免一次性大重写（每步可编译、可测试）；
- 行业无关判定：模块不引用移民专有名词/字段/规则即可入 platform-*；其余进 packs/immigration。

### 4.2 配置驱动终端

- 导航、列表字段、表单、详情页、术语、状态文案由「内核 + 当前包」渲染（页面组件通用化 + schema 描述）；
- 现有定制页面（交易、材料、AI 等）保留为「内核能力页」，行业差异通过配置与插槽表达；
- 行业包加载：启动读生效包版本 → 装载 schema/规则/词库/模板/技能；切换有审计、可回滚。

### 4.3 租户模型

- 当前阶段：**一次部署一个生效行业包**（单租户/单行业），最简单可靠；
- 平台化（后置）：再引入多租户（组织 → 行业包 → 用户/数据隔离）；不在 P0–P4 提前复杂化。

## 6. 分阶段执行方案（P0–P4）

> 每阶段：开发 → 测试（不减少 139 基线）→ Playwright 端到端零错误 → 已冻结内容零回归 → 公网可操作 → 文档/双仓库同步打 tag → 宣布冻结。

### P0 · 本地 AI 基建加固（目标：1 个工作周内）

- 盘点本机硬件/已拉模型；补齐模型矩阵（缺档拉取）；Ollama 常驻与自启；
- Model Registry + 健康探测；Router v1（任务→档位，可试跑）；降级链；
- 评测/红队执行器 v1 + 首批用例；状态接入 A13；
- **冻结门**：多模型可路由、关键任务交叉验证、红队红线 100%、状态全可视。

### P1 · 数据工厂 MVP（目标：2–3 个工作周）

- L0 采集（文件夹/手工/导出）+ 不可变库；分类分诊；
- Docling/OCR/VL 解析（统一版面格式、坐标）；
- 两阶段、Schema 驱动抽取 + 证据；清洗归一；lint + 四眼；
- 发布 L1 canonical + 触发 K1；血缘可视化；选**移民一批真实高频资料**跑通；
- **冻结门**：端到端跑通；一次准确率/人工介入率有实测；字段证据与血缘可核验；发布可回滚。

### P2 · 内核抽象 + 移民包（目标：2 个工作周，可与 P3 部分并行）

- 划定并抽出 platform-domain；移民专有内容入 packs/immigration；
- 终端改配置驱动（导航/字段/术语）；行业包版本/切换/回滚；
- **冻结门**：内核与移民包清晰分离；切换包无需改业务代码；移民全功能零回归。

### P3 · 终端承接 / 真实可用（目标：2–3 个工作周）

- 真实登录/会话（V3-A1）；对象存储接材料（V3-A2）；Web Push+邮件（V3-A3）；
- 护照公开数据（V3-A4）；后台经营分析（V3-A5）；工程收尾（V3-A6）；
- AI W2（材料自检/补件指引/digest/主动提醒/工单辅助）、文档理解 B3；W4 多语言/语音/适老 B4；
- **冻结门**：四端真实可注册登录、材料真实存取、通知真实到达、AI 办理期能力可用；公网全链路零错误。

### P4 · 第二行业试点（目标：2–3 个工作周）

- 建议**律师/法律服务**：按建包清单接入真实资料 → 配 schema/流程/词库/技能 → 数据工厂炼数 → 四眼发布 → 终端试点；
- 产出《行业复制手册》与对外案例、复用率/交付周期指标；
- **冻结门**：第二行业按方法论显著快于首个行业落地、核心闭环可演示，验证「可复制到任意行业」。

> 并行策略：P0 先行；P1 为主线；P2 与 P3 在接口稳定后并行；P4 在 P2 方法定稿后启动。金融、制造作为 P5/P6 储备。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 本地 7B/14B 抽取准确率不足 | 两阶段抽取 + 受约束输出 + 交叉验证 + 置信路由四眼；阈值按标注集校准；复杂件升级大模型 |
| 表格/扫描件解析断裂 | 多工具分流（Docling/OCR/VL），质量门重扫；保留人工兜底路径 |
| 抽象过早导致大重写 | 先边界后抽包、每步可编译可测试；移民功能始终可运行 |
| 范围膨胀（一次做所有行业） | 单行业部署 + 严格阶段门；新行业排队进 P4+ |
| 提示注入/数据泄漏 | 数据/指令物理分隔、注入扫描、红队门禁、跨行业隔离测试 |
| 免费额度/服务休眠 | Render/Neon 休眠后自动恢复已验证；R2/邮件/推理监控用量；超限前告警 |
| 密钥泄漏 | 全部环境变量/本地 600 文件；轮换机制；不进仓库日志 |

## 8. 成本与免费边界

- 域名（已有，阿里云）；Cloudflare Pages/R2、Neon、Render、Web Push、Ollama、Docling、MinIO 均免费/开源；
- 邮件（Resend 免费档）；云模型第三档默认不启用；Apple 付费仍暂缓（PWA 安装）；
- 仅当 P3 需要真实邮件/或你批准云模型时，才需在你自己电脑注册对应免费服务。
