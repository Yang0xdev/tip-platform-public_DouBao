## 1. 这次升级要推动的决定

**问题**：已上线的 AI 初步功能是「确定性 grounded 问答」——答案由模板拼装，零幻觉，但只能回答预设问题，无法完成多轮需求访谈、白话导读、自由表述。
**决定**：升级为 **「Grounded + LLM 混合 AI」**：检索与事实层仍由系统确定性完成（带来源、受授权约束），**LLM 只负责把已核验的事实组织成自然语言**；模型不可用时自动回退现有确定性模式。

一句话原则（沿用并加强）：**事实由系统供给，语言由模型组织，决定由人作出。**

### 三种运行模式（用户可感知，状态透明）

| 模式 | 触发条件 | 能力 | 界面标识 |
|---|---|---|---|
| **L · 本地模型** | 本机 Ollama 在线（Qwen） | 全部 U1 能力，流式输出 | 「已连接本地模型」绿色标识 |
| **S · 服务端模型**（后续） | 公司自托管 vLLM，服务端 VPC 内调用 | 同 L，无需客户本机运行 | 「已连接」 |
| **D · 确定性模式**（现有冻结成果） | 无可用模型 | 现有进度/费用/材料/防骗问答 | 「基础模式」中性标识 |

模式切换**不改变数据边界、红线与回答契约**；L/S 模式下若生成后校验不通过，该条回答降级为 D 模式结果，不展示未通过内容。

## 3. 客户端 U1 升级能力（L/S 模式下提供）

### U1-1 · 对话式需求访谈（A5 落地，融资演示主线）

- 客户用自然语言说目标（“想让孩子有更好的教育，也希望通行方便，预算大概 100 万内”），AI **多轮追问**缺失维度：通行/教育/养老/资产配置目标、预算区间、家庭构成、时间期望、居住意愿；
- 每轮 AI 复述确认，最终生成**结构化需求画像**（客户可逐项修改）；
- 画像明确标注：「客户自述整理，不是资格认定」；
- 结束动作：**「发送给我的顾问复核」**——只产生已有类型的咨询/消息，不自动建方案、不自动匹配结论。

### U1-2 · 项目分项比较叙述

- 在**已发布项目**范围内，客户选定 2–3 个项目，AI 生成比较叙述：费用区间（分项、异币种不合计）、周期区间（非承诺）、通行范围、居住要求、申请条件；
- 表格 + 白话结论并存，每条事实行可点回来源；
- 不输出排名分、成功率、“最适合”结论；结尾给「请顾问帮我复核选择」。

### U1-3 · 合同与方案白话导读

- 客户在方案/合同页点「帮我读懂」，AI 逐条解释：费项含义、三条 Consent（费用知情/不承诺/隐私）在同意什么、哪些是责任边界；
- 导读内容**逐段锚定合同原文片段**，原文与白话左右/上下对照；
- 高敏条款（退款、争议、跨境数据）固定提示「此条建议由顾问/专业人士当面解释」；
- 不替代法律意见，不生成新承诺、不改变任何签署状态。

### U1-4 · 自由表述的 grounded 问答

- 现有 A1–A3 问题在 L/S 模式下支持自由问法与完整段落式回答（“我女儿的出生证明还需要怎么弄，来不及怎么办”）；
- 回答结构仍为：直接结论 → 分项说明 → **逐条来源块**（官方已批准/平台已核验/服务方·未经核验）→ 下一步；
- 上下文包中没有依据的部分，明说「没有找到可核验信息」，不由模型补全。

### 交互与呈现增量

1. **流式输出**：逐字出现，支持停止生成；首字超时（暂定 20s）提示并可重试；
2. **生成态标识**：回答尾部固定「由本地模型基于以下 N 条已核验记录生成」，来源块可展开；
3. **模型状态条**：AI 主页顶部细条显示 L/D 当前模式与模型标签（如 qwen3:7b），点击可查看说明；
4. **语音输入**：沿用「仅转文字」口径；
5. 动画沿用 v1.5 语言：orb 在生成时有柔和的流光状态，结束回归呼吸态，不做高频特效。

## 4. K1 · 知识编译层（LLM Wiki，运营侧）

对应「AI 项目知识与运营中心」的升级，机制详见《AI 知识工程技术路径分析》。

### 4.1 知识分层

- **L0 · raw（不可变）**：原始政策文件、项目资料、服务方文档，登记来源凭据与日期，**只读、只追加**；
- **L1 · Wiki 编译页（Markdown）**：LLM 以 L0 为唯一输入编译出主题页（如「技术居留 A · 资金证明」「无犯罪 · 公证与海牙认证」），页内交叉引用、术语互链；
- 每页 frontmatter 固定：`sources（L0 来源 id 列表）/ level / projectCode / version / authorId / reviewerId / status / compiledWith（模型标签）`；
- **没有 sources 的页面不得提交**；编译输出的每条事实必须能回链 L0。

### 4.2 编译—复核—发布循环

```
ingest（L0 登记）→ compile（LLM 生成 Wiki 草稿 + 引用清单）
→ lint（机器检查：断链/无来源段落/过期引用/红线措辞）
→ 四眼复核（编制人≠复核人，逐条核对来源）→ 发布（对客/对顾问可见）
→ 失效联动（L0 来源失效/项目暂停 → 相关 Wiki 页自动下架并登记缺口）
```

- LLM 是「编译器」，不是作者：发布责任由署名的人承担；
- lint 不通过的页面不可进入复核；复核驳回必填原因，回到编译；
- 每次重编译保留历史版本与 diff，可审计、可回滚。

### 4.3 运营工作台增量（总后台 A13 内新增，不另设模块）

| 区块 | 功能 |
|---|---|
| 编译队列 | L0 待编译主题、一键生成草稿（L/S 模式）、无模型时支持人工 Markdown 编写 |
| Wiki 条目表 | 状态（草稿/lint 待修/待复核/已发布/已下架）、版本、来源数、操作（提交/复核/发布/下架/diff） |
| Lint 报告 | 断链、无来源、过期引用、红线措辞命中，逐项定位 |
| 知识缺口 | 客户/顾问高频提问但无已发布知识的主题（只登记问题，不自动生成对外内容） |

## 5. 顾问端 AI 深度升级（预告，客户端冻结后启动）

沿用用户已明确的分工：**顾问端 AI = 销售工作 + 客户诉求 + 培训 + 资料查询 + 综合方案**。深度重设计方向（本文档仅立范围，不展开）：

1. AI 保持中央凸起主 Tab（v1.8 已冻结的 IA 不动）；
2. 以「锚定一位客户的对话式工作台」重构内部：晨间简报、会前准备、会后一屏收口、带引用的方案草稿，全部由「grounded 上下文 + LLM 组织」完成；
3. 顾问端新增能力重点：**语音/文字口述 → 自动整理为跟进记录与任务草稿**（仍需顾问确认才入库）；综合诉求方案的多项目组合叙述；
4. 所有草稿采纳走既有四眼/状态机，AI 不代提交、不代放行。

## 6. LLM 专项安全护栏（在客户端 v0.4 八项护栏上追加）

1. **数据与指令物理分隔**：上下文包以结构化数据注入，system prompt 固定版本；L0/案件片段一律标记为「被引用数据」，对数据段做注入特征扫描（“忽略以上指令/你现在是/把结论改为…”），命中即剔除该段并审计；
2. **生成后事实校验**：回答生成后，机器校验其中关键陈述是否都能在上下文包中找到依据；无依据陈述必须删除，无法删除则**整条降级为确定性结果**；校验只做一次重试；
3. **模型与标签白名单**：仅允许配置的 Ollama/自托管地址与模型标签；连接未知端点不发起请求；
4. **零业务动作**：LLM 输出不解析为指令、不调用任何写接口；所有“下一步”按钮由系统预置、走现有控制器；
5. **流式内容同样受控**：未完成生成不展示来源块以外的操作入口；停止生成即丢弃未完成内容；
6. **红队门禁升版**：诱导/注入/跨客户/红线承诺评测集随每次模型或 prompt 升版全量回归，红线拦截 100% 才允许发布该版本；
7. **数据不出域**：L 模式数据仅在浏览器与本机 Ollama 间流动；S 模式仅在公司 VPC 内；L3 原件不进上下文包；
8. **全程审计**：模型连接、模式切换、上下文包生成、校验失败、降级、停止生成均留痕，不含 L3 正文。

## 7. 波次与验收

### 波次

| 波次 | 内容 | 进入条件 |
|---|---|---|
| **U1** | 客户端四能力 + ChatProvider + 上下文包 + 模型状态条；K1 数据模型与人工/编译工作流 | 本文档与技术路线冻结 |
| **U2** | 顾问端 AI 深度重设计（第 5 节） | U1 冻结 |
| **U3** | K2 轻图谱、K3 路由（知识工程 K2/K3） | K1 运行满一个影子周期 |

### U1 产品级验收

1. L 模式：本机 Ollama 在线时四能力可用、流式正常；断词/停止/超时均有明确状态；
2. D 模式：关闭模型后，AI 表现与当前冻结版本**逐项一致**；
3. 访谈：多轮后画像字段完整、可修改；「发送顾问」只产生咨询，不产生方案/订单；
4. 比较与导读：每条事实可回链已发布来源/合同原文；无成功率、无承诺措辞；
5. 校验：构造含无依据陈述的场景，回答必须被剔除或整条降级，绝不展示；
6. 注入：数据段夹带“忽略以上指令…”等 100% 被隔离，红线诱导 100% 被拒；
7. K1：无 sources 页面不可提交；lint 不过不可复核；L0 失效联动 Wiki 下架；
8. 现有五端页面与端点零改动、零回归。
