# AI 产品设计 · 顾问端 v0.2（重设计：以客户为锚、随展业节奏）

文档状态：v0.2（重设计稿，替代 v0.1；v0.1 留档）
日期：2026-09-30
背景：v0.1 被评价“设计得不好”。复盘结论——v0.1 是功能平铺的通用 copilot：
没有跟随顾问“案头→会前→会中→会后”的真实节奏；没有“始终锚定具体客户”的概念；
把主要展业面 iPad 当附属；缺少会前准备与会后收口这两个顾问最核心的动作。
下游顺序：本文档冻结 → 技术路线 v0.2 → 原型 → UI → 开发。

## 1. 核心设计概念

### 概念一：AI 始终“锚定一位客户”
顾问同时服务约十几位客户、每位处于不同阶段。AI 面板任何时候都明确显示
**当前客户 + 其所处阶段 + 顾问对该客户的授权范围**；切换客户，全部上下文随之切换。
脱离具体客户的“通用问答”只是次要入口。

### 概念二：围绕顾问的两种工作状态
1. **案头模式（手机，会前会后/碎片时间）**：晨间简报、会前准备、会后收口、起草与自检；
2. **展业模式（iPad，客户在场）**：按核准动线讲解，AI 提示仅顾问可见、低调，不直接对客输出“答案”。

### 概念三：AI 在“风险时刻”出现，而不是随时打扰
- 客户追问结果/承诺时 → 提供合规说法；
- 即将提交无依据内容时 → 提交前自检；
- 硬截止临近、客户在等顾问、凭证待核验 → 晨间风险雷达。

### 不变的底线
AI 只检索与起草，顾问判断与署名；AI 不是四眼中任何一只“眼”；
不直接触发任何业务动作；费表只读、状态机与词库门对 AI 同样生效。

## 2. 场景地图（按顾问的一天重组）

### A 晨间案头
| 编号 | 场景 | 说明 |
|---|---|---|
| A1 | 晨间作战简报 | 按**风险排序**的行动清单：T0 硬截止优先 → 等顾问动作的客户 → 停滞案件 → 待核验凭证；每条一键直达对应页面并自动锚定客户 |
| A2 | 风险雷达 | 主动提示“今天可能出问题的 3 件事”：截止将到、授权/同意临期、sp 报告未核验、客户提出了不能承诺的问题 |

### B 会前准备
| 编号 | 场景 | 说明 |
|---|---|---|
| B1 | 客户会前简报 | 针对预约：客户画像、**自上次会面以来的时间线变化**、客户遗留问题、按其阶段预判的问题、缺失材料、可讨论范围（授权边界）、应展示的核准素材 |
| B2 | 讲解动线建议 | 基于该客户画像与阶段，生成映射到**核准素材**的讲解顺序；未授权/未发布内容不进入动线 |

### C 会中展业（iPad）
| 编号 | 场景 | 说明 |
|---|---|---|
| C1 | 讲解伴侣 | 客户提问，顾问低调查看**带来源的 grounded 答案**，再用自己的话讲解；提示层默认收起、手动唤起，客户视线不可见 |
| C2 | 现场轻记录 | 会极简记录（要点/语音转文字），AI 暂存为结构化素材，会后统一整理，不当场生成正式记录 |
| C3 | 红线即时提示 | 客户施压结果/承诺时，静默提供合规替代表达（能说什么 + “以官方审核为准”），不出现“拒绝客户”的尴尬界面 |

### D 会后收口
| 编号 | 场景 | 说明 |
|---|---|---|
| D1 | 会后一屏收口 | 从现场记录一次性产出：跟进条目（fact/internal 分离）、建议任务（遵循 T0 与来源规则）、建议对客消息、方案待更新点；顾问在一屏逐条采纳/修改/弃用 |
| D2 | 方案协作起草 | 基于费表只读快照起草；标注“哪些段落缺来源”；正式提交前先合规自检，再进入既有四眼，无捷径 |

### E 客户问答与跟进（会间）
| 编号 | 场景 | 说明 |
|---|---|---|
| E1 | 建议回复 | 锚定客户、仅基于 co/off 已核验事实与已发布内容；顾问确认后发送 |
| E2 | 官方文书白话翻译 | 补件/官方信件 → 白话解释 + 对客说明草稿（人工确认） |
| E3 | 主动关怀建议 | 仅当存在可引用的 co/off 新事实时才建议发更新；**没有新事实不生成“安抚性假更新”** |

### F 合规、学习与知识
| 编号 | 场景 | 说明 |
|---|---|---|
| F1 | 提交前合规自检 | 词库/红线/必填/费项/四眼资格一次性检查，输出问题清单；不替代复核 |
| F2 | 情景化学习 | 与本人近失误挂钩（如两次拟用非核准措辞 → 推送对应 5 分钟微课），替代泛泛排课 |
| F3 | 知识贡献 | 实践资料提交知识中心，走“导入→提取→复核来源→发布”，顾问仅贡献不发布 |

## 3. 交互与信息架构

1. **不新增 Tab**。AI 以两种形态存在：
   - 手机：工作台顶部“晨间简报/风险雷达”；客户详情与方案页内嵌入场景入口；
   - iPad：讲解模式下的顾问私有浮层（默认关）；
2. **统一“客户锚点”组件**：AI 面板顶部始终是“当前客户：#1980（阶段·授权范围）× 切换”；
3. **草稿集中收口**：所有 AI 草稿进入“待确认”区，顾问在一屏批量处理，不逐弹窗打扰；
4. AI 草稿与正式内容视觉可区分（“AI 草稿·待确认” + 来源区），“采纳并署名”后才进入既有流程；
5. 视觉与动效沿用 v1.4/v1.5 体系：温和、不紧张、不制造压迫感。

## 4. 授权与数据边界

1. 上下文只含该顾问**有权且在有效期**的客户：关系 active 主责、项目授权有效；顾问 frozenNew 时停止一切新材料/新方案生成；
2. 案件片段进入模型以**客户单独同意**为前提（同意门与客户端一致，文案含“顾问辅助”）；
3. L3 原件原文不进模型；财务到账明细、投诉正文对顾问端 AI 不可见；
4. 语音仅转文字；全部 AI 动作（检索/起草/采纳/拒绝/转人工）入哈希链。

## 5. 红线（AI 永远不做）

资格结论、获批预测、承诺措辞、成功率/时限承诺；充当复核/核验/审批人；
直接改费、改状态、建单、放行；无新事实时编造进度或安抚性更新；
使用非归属客户数据或 L3 原文；frozenNew 状态下生成新业务材料。

## 6. 验收标准（产品级）

1. A1：晨间清单按风险排序，每条可一键直达并自动锚定正确客户；
2. B1：会前简报含自上次会面的变化、授权边界与核准素材，缺一项不发布该简报；
3. D1：会后一屏可完成跟进/任务/消息/方案四类草稿处理，采纳后全部走既有规则（词库、T0、四眼）；
4. C3/E3：施压与等待场景只给合规表达或真实更新，100% 不出现承诺与假更新；
5. 安全：越权客户、frozenNew、L3、跨客户试探 100% 拒绝并审计；
6. 体验：iPad 提示层客户视角不可见、默认关。

## 7. 分期建议

- 第一波：A1/A2 晨间简报与风险雷达、D1 会后收口、E1 建议回复；
- 第二波：B1/B2 会前准备、D2 方案协作、F1 自检；
- 第三波：C1–C3 iPad 展业、E2/E3、F2/F3。
